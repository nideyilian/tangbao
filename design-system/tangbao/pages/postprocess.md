# 中控台（postprocess）

> 只记录与 `../MASTER.md` 不同的规则。没有差异的章节删除。

## 页面

- 名称：中控台（CompositeWorkspace）
- 用户主任务：配置水印归属与图层式水印预设；中控台是各配置功能的统一入口
- 主行动：左栏作用域树点选节点（切作用域）；水印分区内预设画布编辑（`PresetCanvasEditor`）；
  右区「切换中控台功能」分区导航
- 进入条件：`appMode === 'postprocess'`（Header `SegmentedControl` 显示为「中控台」）；App 对其禁用 `app-shell-with-docked-panels` 留白
- 形态口径：**完全对齐「灵境 · 策略中心」（strategy/center，2026-09-20 登录实测）——左树 + 右内容**。
  左栏「配置资产库」（`ConsoleAssetTree`）= 搜索框 + 全部/回收站 tab + 「全局默认」总览项 +
  项目树（节点带覆盖计数徽章，点节点 = 切作用域）；右区 = 作用域标题 + 新建按钮 +
  两行工具栏（`ConsoleToolbar`：配置维度/归属范围筛选 + 搜索 + 每行数量 + 网格列表，
  下行批量启用/停用/复制/删除）+ 内容（卡片网格或分区面板）。
  `src/features/composite/lib/controlConsoleSections.ts` 是唯一的分区注册表
  （顺序即下拉顺序，第一个是默认分区）。

### 业务模型（决定一切交互口径）

**方向自带一整套参数，生成图时直接调用**（杰哥 2026-09-20 明确）。
所以左树是参数的**组织骨架**，不是可选的筛选器：

| 作用域   | 右区呈现                                                                                |
| -------- | --------------------------------------------------------------------------------------- |
| 某个方向 | 该方向的参数：水印卡片上直接开停用（写 `watermarkPresetIds`），其余维度同理由面板就地改 |
| 全局默认 | 全局基线与总览；水印在此**只读**（全局清单前端没有写入点，各方向自己声明才是权威）      |

**⭐ 作用域是全局上下文指针，不是本工作区的局部状态**（2026-09-20 定）。

「现在看哪个方向」全应用只该有**一个**指针，就是 `useAssetLibraryStore.scope`
（`{ kind: 'collection', id }` ⇄ 本工作区的 `ConsoleScope`；非 collection 值 ⇒ 全局默认）。
中控台 / 素材库读同一个值，所以「在任何地方打开都默认是当前方向」自然成立，
不需要各工作区各存一份再互相同步。

写入必须用 `setCollectionContextScope`，**不能用 `setScope`** ——
后者会顺带清空素材库的选中态（那是「素材库内部切换范围」的语义），
在中控台点个方向就把用户在素材库选的一堆图清掉，属于静默丢操作
（见 `features/assetLibrary/store.ts` 里两个 action 的注释）。

**⚠️ 上下文指针 ≠ 参数**，两者分层不可混：

| 概念                                     | 基数   | 例子                                                      |
| ---------------------------------------- | ------ | --------------------------------------------------------- |
| 上下文指针（现在看哪个方向）             | 唯一   | `useAssetLibraryStore.scope`                              |
| 参数（产出覆盖哪些方向、方向用哪些水印） | 可多值 | `selectedCollectionIds`（启用范围）、`watermarkPresetIds` |

别把「当前方向」做成可多选的参数，也别让「启用范围」去覆盖上下文指针。

**其他工作区跟随同一个指针**（「在任何地方打开都默认停在当前方向」）：

| 工作区 | 跟随方式                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------- |
| 素材库 | 原生读写 `scope`（指针的 owner）                                                                                    |
| 中控台 | 读 `scope` ⇒ `ConsoleScope`；点树节点写回（`setCollectionContextScope`，不碰素材选中态）                            |
| SOP    | 打开时把 `scope` 解析成对应分组（`resolveInitialSopGroupId`，由深到浅找 `SopGroup.collectionId`）；**只定位不回写** |

SOP 侧刻意是**单向**的：在 SOP 里换分组属于它自己的浏览行为，回写会把「当前方向」带偏
（SOP 还有「全部 / 未分组 / 收藏 / 最近」这些不对应任何方向的分组）。

### 卡片网格（水印维度）

- 卡片 = 一个水印预设：**真实画布封面**（`renderCompositeV2ToCanvas`，与产出同渲染器）+
  使用状态徽章 + 编号 + 画布/图层说明 + 悬停操作条（启用停用 / 编辑 / 预览 / 复制 / 更多 / 删除）。
- **徽章随作用域切换语义**：全局 = 「N 个方向在用 / 未使用」（只数**显式声明**该预设的方向，
  不数继承值，否则全局清单会让每个预设都显示「N 个方向在用」而失去意义）；
  方向 = 「已启用 / 未启用」。
- 卡上**不做重命名**：名称的唯一编辑入口在预设库里（同参数两个入口必出「改了一处另一处不更新」）。
- 单张封面渲染失败退化为尺寸占位块，不影响整片网格。
- 「每行数量」用内联 `grid-template-columns`（Tailwind 无法为运行时变量生成类名）。

## 功能分区（4 个）

| 分区       | 组件                  | 作用域口径                                                                                        |
| ---------- | --------------------- | ------------------------------------------------------------------------------------------------- |
| 水印       | `ConsolePresetGrid`   | **默认分区**；卡片网格 + 开停用（方向作用域）；「编辑画布」切到 `PresetManagementTab`             |
| 渠道与尺寸 | `MediaSection`        | 全局共享规格；含**画面方向**（决定取用哪一组尺寸）；规格编辑折叠在下段                            |
| 输出位置   | `OutputSection`       | **消费作用域**：全局层写 `mediaOutputDirs`、节点层写 `byMedia`；**文件命名 + 产出预览**也在这一区 |
| 分发       | `DistributionSection` | 纯净版自动伴随 + 分发配置（全局唯一一套，无节点覆盖能力）                                         |

### 与「后处理」弹窗的分工（2026-09-20 定）

输入栏那个「后处理」弹窗（`src/components/PostprocessSettingsModal.tsx`）**只显示当前方向的参数**
（是否参与 / 输出位置 / 水印归属），**没有「全局默认」这个作用域** —— 下拉里只列项目树节点，
指针不在任何节点上时给「先选方向」的引导，而不是回落显示全局。它的作用域跟随同一个上下文指针
`useAssetLibraryStore.scope`，换方向用 `setCollectionContextScope` 写回（不动素材库选中态），
所以「在任何地方打开都停在当前方向」在这里也成立。

全局独有的参数一律在中控台分区里改：渠道与尺寸、**画面方向**、**命名模板**、**创作者**、
分发、**产出预览**。理由是**同一个参数给两个入口，迟早出现「在 A 改了、在 B 显示不一致」**——
`features/postprocess/paramSchema.ts` 因此只声明方向级字段，全局字段一个都不在表里
（`paramSchema.test.ts` 有断言钉住这条收窄）。

**弹窗里的跳转入口**（不能在这里改的参数必须有出口，而不是一句「请到中控台修改」）：

| 位置                          | 按钮                   | 落点分区                              |
| ----------------------------- | ---------------------- | ------------------------------------- |
| footer                        | 「去中控台改全局规格」 | `media`（渠道与尺寸，全局规格主入口） |
| 水印分组的 `Fieldset` actions | 「去中控台配水印」     | `watermark`                           |

实现：`features/composite/lib/useJumpToControlConsole.ts` —— 写 `useStore.controlConsoleSection`
再切 `appMode`。**分区是应用 store 里的唯一真相源**（不是工作区局部 state），否则跳转方无法指定落点；
中控台**离开时把它归位 `DEFAULT_CONTROL_CONSOLE_SECTION`**，所以「从顶栏点进来」看到的仍是水印。

弹窗内部布局按 MASTER §4.4 / §5.9 组织，**不用自定义卡片**：

| 层级              | 组件                                                  | 间距                                               |
| ----------------- | ----------------------------------------------------- | -------------------------------------------------- |
| 内容区            | `DialogPane`                                          | 内边距 20px（系统自带）                            |
| 作用范围 / 参数区 | `Stack gap={5}`                                       | 20px                                               |
| 分组              | **`Fieldset`**（§5.9 禁止在 `DialogPane` 里套大卡片） | 组间 `Stack gap={6}` = 24px；组内 16px（组件自带） |
| 字段行            | `Inline gap={5}` + 14rem 标签列 + 撑满的控件列        | 标签与控件 20px；控件内 8px                        |
| 状态              | 参数区末尾一行 Status（只出现一次，footer 不重复）    | 与上一组 24px                                      |

宽度取 `--ds-content-md`（48rem）：单栏参数列表不需要 80vw，窗口一大每行会被拉到一米长。

### ⚠️ 分区的准入约束（新增分区前必读）

**中控台是所有参数的统一编辑入口，节点级覆盖也在其中编辑。**

这是 2026-09-20 明确的定位：中控台的职责是「控制所有参数」，因此
节点级与全局级**都在这里改**，作用域由**左栏配置资产库树**驱动
（`GLOBAL_NODE_ID` = 全局基线，其余为 `AssetCollection.id`；点树节点 = 切作用域）。
不存在「中控台只能改全局、节点级要去别处」的断层。

但**分区只在节点层真有可覆盖字段时才消费作用域**。当前 `PostprocessNodeOverride`
（ADR-0011 收窄后）只有四个字段：

| 字段                    | 中控台对应分区 | 说明                          |
| ----------------------- | -------------- | ----------------------------- |
| `outputDir` / `byMedia` | 输出位置       | ✅ 已接作用域                 |
| `watermarkPresetIds`    | 水印           | ✅ 归属树本身就是节点级编辑面 |
| `enabled`               | —              | 整方向开关，暂未在中控台暴露  |

`distribution` / `autoCompanionClean` / `selectedMediaIds` **不在覆盖字段里** ——
它们在前端只在全局层存在（迁移时被提升到 `promotedGlobals`，属只读存档）。
所以「渠道与尺寸」「分发」两个分区**刻意不消费作用域**（界面上写明「全局一套」）：
给用户一个能选节点、选了却什么都不改变的控件，比不给更糟。

新增分区时的判断顺序：

1. 这个参数在 `PostprocessNodeOverride` 里吗？→ 在 ⇒ 消费工作区作用域；
2. 不在 ⇒ 纯全局分区，界面上写明「全局一套」。

## 页面状态

- 初始：默认落在「水印」分区（`watermark`），三栏装配（归属树 / 水印库 / 画布编辑）。
- 加载：无远端加载；LOGO 资产按需取 object URL。
- 空：水印库为空显示 `EmptyState` 引导（右上角 + 新建）；媒体表为空显示 `EmptyState` 引导。
- 成功：编辑即写对应 store（水印 → `useCompositeV2Store`；渠道/输出/分发 → `usePostprocessMediaStore`）。
- 可恢复错误：导入非预设文件时给出明确对话框说明，不猜测导入；目录选择失败走 toast。
- 不可用：非 Electron 环境下选本地文件夹受限，给出说明。

## 响应式差异

- 375px：多栏堆叠为单栏，画布优先；悬浮工具条转底栏。
- 768px：左栏（文件夹）+ 画布，右栏（图层/规则）转 Drawer。
- 1024px：左/中/右三栏接近完整，缩放控制条常驻。
- 1440px：全宽多栏完整。
- 粗指针：拖拽图层改用方向键微调或工具条按钮；缩放用控件而非滚轮手势。
