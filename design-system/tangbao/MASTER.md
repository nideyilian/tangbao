# 糖包 全局设计规范

> 状态：Active  
> 适用范围：Web、Electron、桌面端与响应式窄屏  
> 最后复核：2026-07-28  
> 维护入口：`src/design-system/`

本文件是项目界面决策的全局基线。新页面先遵循本文件；确有业务差异时，在
`design-system/tangbao/pages/` 建立页面覆盖文件，只记录差异，不复制整份规范。

## 1. 先定义真正的问题

用户真正需要的不是“一份说明文档”和“一批看起来统一的组件”，而是一套能让人和
AI 在后续修改、新建页面时都做出一致决策的约束系统。它必须同时解决四件事：

1. 设计决策有唯一入口，避免颜色、圆角、间距和动效继续散落。
2. 常见交互有可直接复用的实现，避免每个页面重新发明按钮、表单和状态。
3. 允许业务页面有差异，但差异需要显式记录，不能用任意值偷偷分叉。
4. 规范能被代码、设计工具和 AI 读取，而不只是供人浏览。

因此最终交付采用“规范 + Token + 组件 + 活预览 + 页面覆盖”的轻量设计系统，而不是
只写文档、全面换 UI 框架，或一次性重构所有历史页面。

## 2. 审查结论

### 2.1 隐藏假设

| 隐藏假设                            | 复核结论                                                              | 处理                                    |
| ----------------------------------- | --------------------------------------------------------------------- | --------------------------------------- |
| 写完规范，界面自然会一致            | 错误。没有代码约束的规范会很快失效                                    | 将语义 Token 和基础组件纳入源码         |
| 组件越多，设计系统越完整            | 错误。过早封装会冻结错误抽象                                          | 首批只覆盖高频、稳定的基础模式          |
| AI 产品应该使用紫粉渐变和强玻璃效果 | 过时的类别刻板印象                                                    | 保留现有蓝色工具型视觉语言              |
| 桌面端所有点击目标都必须 44px       | 不完整。WCAG 2.2 AA 最低目标为 24 CSS px；44px 是增强目标，也适合触屏 | 桌面默认 32–40px；粗指针自动提升到 44px |
| 引入成熟 UI 框架一定更专业          | 不成立。迁移成本和视觉冲突可能高于收益                                | 当前不引入新框架，先稳定语义层          |
| 全局统一等于所有页面完全相同        | 错误。工作台密度和设置页阅读需求不同                                  | 用页面覆盖机制表达有理由的差异          |
| 动画越丰富越显得高级                | 错误。高频生产工具更需要即时响应                                      | 动效仅用于反馈、空间关系和状态变化      |

### 2.2 信息差扫描

- 可访问性基线采用 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，而不是停留在
  WCAG 2.1。新增关注点包括焦点不可被遮挡、拖拽替代方案和目标尺寸。
- Token 的机器可读副本采用
  [Design Tokens Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/)
  的 `$type` / `$value` 结构和 `.tokens.json` 扩展名，便于未来接入 Figma、生成脚本或
  AI 工具。该版本是稳定的 Final Community Group Report；它不是 W3C 标准或 W3C
  Recommendation。
- 组件采用“语义属性 + 好默认值”策略：图标按钮在类型层强制 `aria-label`，加载按钮
  自动锁定并声明 `aria-busy`，表单错误自动关联 `aria-describedby`。
- 响应式不只看宽度，也考虑 `pointer: coarse`、`prefers-reduced-motion`、安全区和
  字体放大。
- AI 时代更高效的做法不是让模型复制视觉稿，而是先让模型读取本文件、页面覆盖和
  组件出口，再生成实现。机器可读 Token 让这一流程更稳定。

### 2.3 替代路径

| 路径                              | 成本           | 一致性 | 长期扩展 | 结论                                     |
| --------------------------------- | -------------- | ------ | -------- | ---------------------------------------- |
| 只写 Markdown 规范                | 最低           | 低     | 低       | 不采用：无法约束运行时代码               |
| 直接引入 shadcn/Radix 等整套方案  | 中到高         | 中     | 高       | 暂缓：会产生双组件体系和迁移负担         |
| Storybook + 完整设计系统平台      | 高             | 高     | 很高     | 当前过重：项目尚未需要独立发布与多人治理 |
| Token + 少量基础组件 + 开发期预览 | 低到中         | 高     | 高       | 采用：最符合当前阶段                     |
| AI 自动从截图生成任意组件         | 表面低、返工高 | 低     | 低       | 仅可用于探索，不作为生产路径             |

20% 复杂度实现 80% 效果的关键，不是一次改完所有旧页面，而是先阻止新分叉：以后
新增界面必须先复用语义 Token 和基础组件，旧页面按真实改动顺手迁移。

### 2.4 反方与失败预演

最可能的失败方式：

1. 文档、CSS Token 和 JSON Token 各自演化，产生漂移。
2. 因为基础组件暂时不够，开发者绕过系统写大量任意值。
3. 页面覆盖被滥用，最后每页都有一套“例外”。
4. 为了统一视觉而忽略业务密度，降低高频工作效率。
5. 一次性迁移旧组件，造成大范围视觉回归。

防线：

- 运行时以 `src/design-system/styles.css` 为准；`tokens.tokens.json` 是外部工具交换副本。
- 新增任意颜色、圆角、阴影、z-index 前，先证明现有语义无法表达需求。
- 页面覆盖必须写明“用户任务、为何全局规则不适用、何时删除”。
- 禁止以设计系统名义发起全仓视觉重写；按页面改动逐步迁移。
- 任何新组件必须至少被两个真实场景需要，单场景优先留在业务目录。

### 2.5 最终执行决策

原方案“创建规范文档和组件库”值得继续，但需要从两个静态产物升级为可执行系统。
最终路线：

1. 保留现有浅色主基调、蓝色主色、Zinc 中性色和 HarmonyOS Sans SC 字体。
2. 建立语义 Token，不让业务组件依赖“blue-500 代表主按钮”这类隐含约定。
3. 首批提供 Button、IconButton、TextField、TextArea、Surface、Badge、EmptyState、
   Skeleton。
4. 用开发期预览页验证浅色、深色、状态与组合。
5. 不批量替换历史组件；新建页面强制使用，旧页面按触达迁移。

## 3. 设计原则

### 3.1 产品性格

糖包 是高频、内容密集、创作生产型工具。界面应当：

- 清晰而克制：内容和生成结果是主角，装饰退后。
- 快而稳定：高频操作即时反馈，避免阻塞式或表演式动画。
- 专业但不冰冷：圆角和浅层阴影提供亲和力，色彩保持语义。
- 信息密度可控：桌面端紧凑，触屏和窄屏自动增加点击空间。

### 3.2 视觉决策优先级

1. 任务完成和信息可读性。
2. 可访问性与键盘操作。
3. 跨页面一致性。
4. 响应速度与性能。
5. 品牌表达。
6. 装饰和动效。

当低优先级目标伤害高优先级目标时，舍弃低优先级目标。

## 4. Token 体系

### 4.1 使用规则

- 业务代码使用语义名：`primary`、`surface`、`danger`、`text-muted`。
- 禁止用颜色外观命名业务意义，例如 `blueButton`、`grayText`。
- 禁止在新组件中添加未经说明的 Hex、阴影和 z-index。
- CSS 使用 `--ds-*`；Tailwind 使用 `ds.*` 命名空间；外部工具读取 `tokens.tokens.json`。
- 浅色和深色必须成对设计，不能用机械反色生成。

### 4.2 颜色

> 下表由 `src/design-system/styles.css` 的 HSL 通道值换算得出，**实现是唯一真相源**。
> 修改 Token 后必须同步本表 —— 一致性由 `src/design-system/tokensContract.test.ts` 与
> `src/design-system/docColorTable.test.ts` 双重锁定。HSL 通道写法（不带 `hsl()` 包裹）
> 是为了让 Tailwind 能追加 `/<alpha-value>`。

| 语义              | 浅色      | 深色      | 用途                               |
| ----------------- | --------- | --------- | ---------------------------------- |
| Canvas            | `#F2F4F7` | `#0B0C0F` | 页面最底层                         |
| Surface           | `#FFFFFF` | `#191B1F` | 卡片、面板、浮层                   |
| Surface subtle    | `#EDEFF3` | `#282C33` | 次级区域、禁用底色                 |
| Surface raised    | `#FFFFFF` | `#1F2228` | 真正浮起的区域（弹窗壳 / 下拉）    |
| Text              | `#1A1E28` | `#F0F2F4` | 主要文本                           |
| Text muted        | `#555D6D` | `#B6BAC3` | 说明、元数据                       |
| Text subtle       | `#676F7E` | `#959BA7` | 三级文本、占位                     |
| Border            | `#D2D7E0` | `#4A4F59` | 分隔和控件边界                     |
| Border strong     | `#A6AFBF` | `#6F7785` | 强调边界、悬停描边                 |
| Primary           | `#2C59BA` | `#89A8EC` | 当前页面唯一主要行动               |
| Primary hover     | `#214697` | `#A6BEF2` | 主行动悬停                         |
| Primary subtle    | `#EBF0FA` | `#2A3651` | 主色弱底                           |
| Success           | `#277C54` | `#82D3AE` | 成功状态                           |
| Warning           | `#9C601C` | `#E7BB79` | 可继续但需关注                     |
| Danger            | `#BE2D36` | `#EA8A90` | 错误和破坏性操作                   |
| Info              | `#216A8C` | `#89C5E1` | 非阻断信息                         |
| Selection surface | `#E6E9EF` | `#30343B` | 选中项的中性表面，不叠加品牌蓝蒙层 |
| Selection border  | `#A6AFBF` | `#6F7785` | 选中项边界、标签下划线和缩略图轮廓 |
| Focus             | `#2F5FC6` | `#89A8EC` | 键盘焦点环                         |
| Scrim             | `#14171F` | `#0F1114` | 模态遮罩底                         |

**表面层级的可辨阈值**（实测，改色时按此自查）：

- 相邻两级的对比度必须 ≥ **1.10:1**，否则肉眼无法分辨（历史事故见 `docs/RISK.md` R-38）。
- 描边对底色的对比度必须 ≥ **1.3:1**。
- 正文字号文本对比度必须 ≥ **4.5:1**（WCAG AA）。
- 浅色态 `canvas ↔ surface` = 1.10:1，深色态 `canvas ↔ surface` = 1.13:1；
  `surface-subtle` 相对 `surface-raised` 浅色 1.15:1 / 深色 1.14:1。

**四级表面层级**（弹窗与工作台必须按此选色，不得自造）：

```text
surface-raised（弹窗壳 / 下拉 / 浮层）
  └─ surface（DialogPane 内容区 / 侧栏 / 停靠栏）
       └─ surface-subtle（下沉分组卡 / 输入框 / 表头）
            └─ canvas（画布型工作台 / 内嵌预览区）
```

颜色不能成为唯一状态信号；必须同时有文本、图标、形状或位置差异。
品牌色只用于主行动、焦点和语义状态；导航、列表、缩略图的选中态使用中性
Selection Token，并通过字重、边界或位置标记表达，不使用整块蓝色背景。

### 4.3 字体

- 界面字体：`HarmonyOS Sans SC` → `Noto Sans SC` → 系统中文字体。
- 代码和参数：`Maple Mono` → `Cascadia Code` → 系统等宽字体。
- 常用字号：12 / 13 / 14 / 16 / 20 / 24px。
- 正文默认 14px，行高 1.5；帮助文档和长文本使用 16px，行高 1.65。
- 标签使用 500，标题使用 600–700；不要用低对比度代替层级。
- 数据列、计数和时长使用等宽数字，避免数值变化引发布局跳动。

### 4.4 间距与布局

- 基础单位 4px；常用间距 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px。
- 控件内部优先 8 / 12px；卡片内边距优先 16 / 20 / 24px。
- 同组小于异组：组内通常 8–12px，组间通常 20–32px。
- 桌面主内容最大宽度沿用 75rem；长文本最大 65–75 个字符。
- 375 / 768 / 1024 / 1440px 是检查点，不是为每个点写独立布局。
- 固定头部、底部输入条和侧栏必须为内容预留空间，并尊重安全区。
- 避免没有必要的嵌套滚动；列表超过 50 个复杂项目时优先虚拟化。

### 4.5 圆角、边框、阴影

- 小控件：6–8px；卡片和面板：12px；模态框：16–24px；胶囊：仅标签和筛选。
- 静态卡片优先边框，不默认加阴影。
- 只有确实高于页面的元素使用阴影：下拉 `shadow-md`，模态 `shadow-lg`。
- 同一层级不混用不同阴影；深色主题单独校准阴影和边框。
- 不使用“所有卡片都悬浮”的视觉套路。

### 4.6 应用框架、停靠侧栏与滚动条

- 应用根背景必须使用 `Canvas` Token；禁止在 `body`、应用壳或页面根节点使用
  `gray-*`、`slate-*` 等外观色替代语义 Canvas。
- 停靠侧栏是应用框架的一部分，不是浮层：背景使用 `Canvas`，左栏仅保留右侧
  1px 分隔线，右栏仅保留左侧 1px 分隔线，不使用圆角和阴影。
- 侧栏脱离边缘成为浮动面板后，才切换为 `Surface`、面板圆角和 `shadow-lg`。停靠与
  浮动必须由显式状态控制，不能依赖零散透明度类模拟。
- 中部画廊和底部输入区是主任务路径；左右侧栏作为辅助 rail 退后。侧栏的 hover、
  selected、输入控件等局部区域才使用 `Surface` / `Surface subtle`，不把整栏提亮。
- 每个侧栏最多保留一个主纵向滚动区。该区域使用 `overscroll-behavior: contain` 和
  稳定 gutter；页面根节点不强制永久滚动槽，避免页级滚动条压在右侧 rail 上。
- 桌面滚动条宽度为 6px、轨道透明；thumb 默认使用低对比 `Border strong`，只在
  hover 时增强到 `Text subtle`。根滚动区和嵌套滚动区必须共用语义 Token，深色主题
  不允许回退成亮色系统滚动条。

### 4.7 应用壳与主导航

应用是单窗口多工作区结构，层级固定为：

`Header（模式切换 + 全局状态）→ 工作区（画廊 / 策略 / 下单 / 后期处理 / Agent）→ 可停靠侧栏（工作区标签、词库）→ 底部输入条（画廊）`

- 模式切换是全局唯一顶层导航，使用 `SegmentedControl` 常驻 Header；工作区内部
  不得再出现第二套顶层导航。
- Header 是全局共享区域：只放模式切换、全局统计、主题切换和设置入口；工作区
  专属工具放入各自工作区的工具栏。
- 可停靠侧栏（WorkspaceTabBar、WordLibrarySidebar）遵循 4.6 的停靠规则；两个侧栏
  同时展开时不得把主内容压到低于 640px，空间不足时后展开者转为浮动面板。
- 切换模式必须保留各工作区的内部状态（滚动位置、选择、草稿）；销毁状态的行为
  （如清空选择）必须显式提示。
- 需求中心壳（登录、导航、目录管理）包裹 legacy 工作区时，两层不得同时出现
  各自的页面级滚动条。

### 4.8 层级

| Token    |  值 | 用途             |
| -------- | --: | ---------------- |
| base     |   0 | 普通内容         |
| sticky   |  20 | 固定导航、工具条 |
| dropdown |  40 | 下拉、弹出菜单   |
| overlay  |  80 | 遮罩             |
| modal    |  90 | 模态框           |
| toast    | 100 | 全局反馈         |
| tooltip  | 110 | 提示信息         |

禁止继续添加 `z-[9999]`。出现遮挡时先检查 stacking context，而不是提高数字。

## 5. 组件规范

完整的共享组件规范和现有 UI 模块映射见
[`COMPONENTS.md`](./COMPONENTS.md)。本章保留最核心的使用原则；组件 API、变体、禁用
场景和可访问性约束以 `COMPONENTS.md` 与 `src/design-system/catalog.ts` 为准。
具体数量以 `src/design-system/catalog.ts` 和 `catalog.test.ts` 自动覆盖结果为准。

共享组件分为七类：基础、布局、表单、导航、数据展示、反馈与浮层。业务工作台和领域
状态机不复制进组件库，而是使用共享组件组合。

### 5.1 Button

- 每个页面或模态区域最多一个视觉主按钮。
- 变体：`primary`、`secondary`、`ghost`、`danger`。
- 尺寸：`sm` 32px、`md` 36px、`lg` 40px；粗指针环境最小 44px。
- 异步动作必须使用 `loading`，防止重复提交。
- 按下反馈使用 `scale(0.97)`，不改变布局边界。
- 禁止用 `<div onClick>` 代替按钮。

### 5.2 IconButton

- 必须提供明确 `aria-label`；`title` 不能替代可访问名称。
- 图标来自 Lucide，同层级保持相同尺寸和线宽。
- 图标视觉尺寸通常 16–20px，点击区域由按钮尺寸保证。
- 工具栏图标如果发现性不足，应同时显示文本。

### 5.3 表单

- 每个字段都有可见标签，placeholder 只展示示例。
- 复杂字段提供持续可见的帮助文本。
- 校验优先在 blur 或提交后出现，不在用户每输入一个字时打断。
- 错误贴近字段，说明“原因 + 修复方式”，多错误时聚焦第一个错误。
- 只读和禁用是两种状态：只读可复制，禁用不可交互。
- 长表单自动保存草稿；关闭含未保存内容的模态框前确认。

### 5.4 Surface

- 用于视觉分组，不等于所有内容都要套卡片。
- `default`：边框面板；`subtle`：次级区域；`raised`：真正浮起的区域。
- 可点击卡片必须使用语义按钮/链接或在内部提供明确操作。

### 5.5 Badge

- 只承载短状态或分类，不承载主要操作。
- 使用 `neutral / info / success / warning / danger`。
- 状态文本必须能脱离颜色独立理解。

### 5.6 EmptyState

- 必须回答：这里是什么、为什么为空、下一步做什么。
- 有明确下一步时提供一个主行动；无行动时不要硬塞按钮。
- 插图和图标保持低强调，不超过内容本身。

### 5.7 Skeleton

- 预计等待超过约 300ms 时显示反馈；超过 1s 优先骨架。
- 骨架应接近最终布局，避免加载完成时跳动。
- 不使用大面积高亮扫光；减少动态偏好下停止脉冲。

### 5.8 其余组件

- 布局：Container、Stack、Inline、Grid、SplitPane、ScrollArea、Divider。
- 表单：Checkbox、Switch、RadioGroup、SegmentedControl、SelectField、SearchField、
  Fieldset、Stepper。
- 导航：Tabs、Toolbar、PageHeader、SectionHeader、Breadcrumbs、NavList。
- 数据展示：Card、Panel、ListRow、Stat、KeyValue、Thumbnail、AspectRatio、Disclosure、
  CodeBlock、Table。
- 反馈：Alert、ToastMessage、Spinner、Progress、StatusIndicator、ErrorState、Kbd。
- 浮层：Dialog、DialogWorkspace、DialogPane、Drawer、Tooltip、Popover、Menu。

### 5.9 复杂弹窗

复杂弹窗不是页面，也不是把页面复制进浮层。它只有一套固定层级：

`Dialog Shell → Tab Bar（可选）→ DialogWorkspace → DialogPane → Field / ListRow / Status`

- `Dialog` 只负责遮罩、焦点、标题、说明和关闭。
- `DialogWorkspace` 负责弹窗内部布局：`single / split / triple`。
- `DialogPane` 负责同一工作区内的侧栏、列表、编辑区或状态区。
- Tab 只切换同一个任务上下文下的并列内容；所有 Tab 的 pane 结构、字号、字段高度和选择状态必须一致。
- 禁止在 `DialogPane` 内再套一层页面背景、`max-width` 页面容器或大卡片；只有局部状态、提示、上传区这类真实模块才可以使用 Surface/Card。
- 列表选择使用中性 selection token、字重和 1px 边界；不叠加整块品牌蓝或彩色蒙层。

下拉选择分两类：

- `SelectField`：选择一个值，优先原生 select，闭合控件高度和 TextField 一致。
- `Menu`：执行命令，不能伪装成字段；危险命令用 danger tone 并和普通命令分组。

字段标签使用 `text` 或 `text-muted`，不可使用低对比灰色；placeholder 只作为示例，不能替代标签。

## 6. 交互与动效

### 6.1 动效

- 高频键盘操作不做进出场动画。
- Hover、颜色和按压反馈：120–180ms。
- 下拉和小浮层：150–220ms。
- 模态和抽屉：180–240ms，退出约为进入的 60–80%。
- 进入使用强 `ease-out`；屏幕内移动使用 `ease-in-out`；持续进度使用 linear。
- 只动画 `transform` 和 `opacity`；不使用 `transition: all`。
- 弹出层从触发点展开，模态框保持中心 origin。
- 动画必须可打断，且不能阻塞输入。
- `prefers-reduced-motion` 下移除位移动画，保留必要的颜色和透明度反馈。

### 6.2 快捷键

原则：

- 快捷键是加速器，不是唯一入口；每个快捷键动作必须有可见控件或菜单等价物。
- 修饰键统一按平台映射：Windows/Linux 使用 Ctrl，macOS 使用 Cmd；界面展示使用
  `Kbd` 组件并按平台显示正确符号。
- 焦点位于 `input`、`textarea`、contentEditable 时，页面级快捷键必须让位，除非该
  快捷键本身服务于当前输入（如 Enter 提交）。
- 同一手势跨页面语义必须一致：`Ctrl+S` 永远保存当前草稿；`Ctrl+C/V` 只复制粘贴
  当前选中实体；`Escape` 永远关闭最上层浮层或取消行内编辑。
- 新增快捷键前先查下方注册表，禁止在同一路径上下文中产生冲突；页面专属快捷键
  必须登记在对应的 `pages/<page>.md` 覆盖文件中。

全局注册表（跨页面保留字）：

| 快捷键                 | 作用域               | 行为                                     |
| ---------------------- | -------------------- | ---------------------------------------- |
| `Escape`               | 全局                 | 关闭最上层浮层 / 取消行内编辑 / 清空框选 |
| `Enter`                | 行内编辑、表单       | 提交当前编辑                             |
| `Tab` / `Shift+Tab`    | 全局                 | 按视觉顺序移动焦点                       |
| `Ctrl/Cmd + S`         | 有草稿概念的工作区   | 保存草稿（策略、SOP 管理）               |
| `Ctrl/Cmd + C` / `V`   | 有选中实体的工作区   | 复制 / 粘贴选中实体（策略、画布图层）    |
| `Ctrl/Cmd + 点击`      | 网格、标签栏         | 增量切换选中                             |
| `← / →`                | Lightbox、Tabs、Menu | 上一项 / 下一项                          |
| `Delete` / `Backspace` | 画布编辑器           | 删除选中对象                             |

### 6.3 选择与批量操作

- 选择模型统一为：单击选中并替换、`Ctrl/Cmd + 点击` 增量切换、拖拽框选批量圈选；
  按住 `Ctrl/Cmd` 框选为增量并集，不清空既有选择。
- 框选必须支持视口边缘自动滚动；框选矩形使用半透明 Selection surface + 1px
  Selection border，不使用品牌蓝实心色块。
- 选中态视觉遵循 4.2 的 Selection Token：中性表面 + 边界 + 图标/勾选标记，不用
  整块品牌色蒙层。
- 选中数 ≥ 1 时显示批量操作栏：包含选中计数、清除选择入口和批量命令；批量
  破坏性操作必须可撤销，不可撤销时先确认并说明影响范围。
- 虚拟化网格中选择状态必须存于数据层（id 集合），不能依赖 DOM 节点存活。
- 选择是易失状态：切换页面或筛选条件变化导致选中项不可见时，给出计数提示而
  不是静默丢弃。

### 6.4 拖拽

- 所有拖拽交互（排序、停靠、框选、画布对象移动）必须提供按钮、菜单或键盘替代
  方案（WCAG 2.2）。
- 拖拽进行中必须显示：被拖对象的预览、合法放置目标的高亮；非法目标不产生
  任何放置反馈。
- 拖拽结束立即持久化结果；持久化失败时回弹到原位置并给出 Toast 说明。
- 触屏环境长按进入拖拽，普通滑动优先滚动；拖拽把手目标至少 24×24 CSS px。
- 排序拖拽的插入位置用 2px 主色指示线表达，不整行变色。

### 6.5 右键菜单

- 右键菜单是快捷入口；其中每个命令都必须能通过可见 UI（工具栏、详情、更多
  按钮）到达。
- 使用 `Menu` 组件语义；危险命令使用 danger tone、独立分组并置于底部。
- 打开位置基于视口碰撞检测调整，永不溢出屏幕；同一时刻最多一个上下文菜单，
  打开新菜单前关闭旧菜单。
- 菜单命令的快捷键提示使用 `Kbd` 展示在行尾，只展示已实现的快捷键。
- 触屏环境用长按或显式"更多"按钮替代右键。

### 6.6 媒体查看链路

图像内容的查看深度分四级，逐级递进、职责不重叠：

| 级别 | 载体                | 职责               | 触发         |
| ---- | ------------------- | ------------------ | ------------ |
| 1    | `Thumbnail`（网格） | 识别与选择         | 常驻         |
| 2    | `HoverImagePreview` | 快速看清细节       | 指针悬停     |
| 3    | `Lightbox`          | 沉浸查看与逐张浏览 | 点击/Enter   |
| 4    | `DetailModal`       | 元数据、参数与操作 | 显式详情入口 |

- 悬停预览是增强而非入口：仅在 `pointer: fine` 环境启用，粗指针禁用；预览不
  抢占焦点、不阻挡指针路径。
- Lightbox 必须支持 `←/→` 切换、`Escape` 关闭、位置计数（如 3/42），并预加载
  相邻图像。
- 缩略图必须声明比例（`AspectRatio`），加载中显示骨架，失败显示可重试占位，
  不留浏览器破碎图标。
- 生成中的图像卡片显示进度或状态标记，位置与最终图像一致，完成时不跳动。

### 6.7 画布与遮罩编辑

画布编辑器（版式画布、遮罩编辑）是专业工具面，允许突破部分全局规则，但每项
突破必须登记在页面覆盖文件中：

- 允许全宽工作区和更深的工作面背景，用于分离画布与画布外内容。
- 必备能力：撤销/重做、清晰的选中高亮（selection token 描边 + 控制点）、键盘
  微调（方向键逐步移动）、复制/粘贴、删除。
- 工具栏使用 `Toolbar` 语义；当前激活工具用 selection token 表达，不用品牌色
  实心填充。
- 画布内滚轮和拖拽操作不得触发页面滚动；缩放提供显式控件，手势仅作增强。
- 图层列表使用 `ListRow`，层级调整同时提供拖拽和键盘/按钮两种方式。
- 编辑器专属快捷键（如 `[` `]` 调整层级）在对应页面覆盖文件登记，不占用 6.2
  的全局保留字。

### 6.8 桌面端（Electron）约定

- 目录选择、文件保存使用系统原生对话框；返回路径以可复制文本显示，不截断
  关键末段（中间省略，保留首尾）。
- 外部链接一律用系统浏览器打开，不在应用窗口内导航。
- 自定义窗口拖拽区域不得覆盖任何交互控件；可交互元素必须显式 no-drag。
- 批量导出、队列执行等长任务必须在窗口失焦或最小化后继续运行，完成后用
  Toast（应用内）汇报结果与失败数。
- 写入剪贴板、保存文件成功后必须有 Toast 反馈；失败给出原因与重试入口。
- 主题跟随系统设置为默认值；用户手动切换后记住偏好并优先于系统。

## 7. 内容与状态

### 7.1 文案

- 按钮使用动词 + 对象：`生成图片`、`保存设置`，避免模糊的 `确定`。
- 标题说明结果或任务，不重复导航名称。
- 错误消息格式：发生了什么 → 可能原因 → 用户下一步。
- 中文和英文/数字之间保持自然空格；省略号统一使用 `…`。

### 7.2 系统状态

每个异步区域至少设计：

1. 初始状态。
2. 加载状态。
3. 空状态。
4. 成功状态。
5. 可恢复错误。
6. 不可用/无权限状态。

Toast 使用 `aria-live="polite"` 且不抢焦点。删除和批量操作优先支持撤销；不可撤销时
才使用确认对话框。

### 7.3 队列与长任务

图像生成、批量执行、日程任务和批量导出共用同一套长任务状态语言：

- 状态机固定为：`排队 → 运行中 → 成功 / 失败 / 已取消`；每个状态用
  `StatusIndicator` + 文本表达，颜色遵循语义 Token。
- 可预估进度用 determinate `Progress` 并显示计数（如 12/40）；不可预估用
  indeterminate，且不伪造百分比。
- 运行中的任务必须提供取消入口；取消是安全操作，已完成部分保留并明确标记。
- 批量结果汇总必须区分成功数与失败数；失败项支持单独重试，不强迫整批重跑。
- 队列运行不阻塞界面：用户可以离开当前工作区，通过 Header 全局统计或 Toast
  获知完成情况。
- 失败信息记录到任务级详情，Toast 只报摘要（如"3 项失败"）+ 查看入口。
- 页面刷新或应用重启后，队列状态必须从持久层恢复，不出现"幽灵运行中"。

## 8. 可访问性底线

- 普通文本对比度至少 4.5:1；大文本至少 3:1。
- 非文本 UI 和焦点指示至少 3:1。
- 所有交互可用键盘完成，Tab 顺序与视觉顺序一致。
- 焦点可见且不被固定栏、弹层或滚动容器遮挡。
- WCAG 2.2 AA 指针目标至少可容纳 24×24 CSS px，或满足间距例外；触屏优先 44px。
- 拖拽必须有按钮、菜单或键盘替代方案。
- 模态打开时聚焦首个有意义元素，关闭后归还触发器。
- 图片有尺寸以避免布局跳动；有意义的图片提供替代文本，装饰图 `alt=""`。
- 不禁用页面缩放。

## 9. 响应式规则

- 先保证 375px 可操作，再增强到桌面宽度。
- 窄屏优先展示核心内容；次级设置用渐进披露。
- 小屏不允许页面级横向滚动；数据表例外时需明确滚动提示。
- 大屏使用侧栏，小屏使用顶栏或抽屉；同一层级不混用三种主导航。
- `pointer: coarse` 增加目标尺寸和间距，不依赖 hover。
- 触屏手势不是唯一入口，关键功能必须有可见控件。


运行 `npm run dev`，打开：

```text
http://localhost:5173/?design-system=1
```

预览页仅在开发环境启用，覆盖浅/深色、组件状态、表单、空状态和加载状态。

### 10.4 新页面工作流

1. 读本文件。
2. 查找 `pages/<page>.md`；存在时只覆盖明确差异。
3. 列出页面的主任务、主行动和六种系统状态。
4. 先组合 `src/design-system` 组件，再写业务组件。
5. 仅为布局使用 Tailwind；颜色、圆角、阴影使用语义 Token。
6. 检查 375 / 768 / 1024 / 1440px、浅/深色、键盘、粗指针和减少动态。
7. 构建、测试并在预览或真实页面中视觉复核。

## 11. 现状审计与迁移顺序

| Before                              | After                                        | Why                            |
| ----------------------------------- | -------------------------------------------- | ------------------------------ |
| 业务组件散落 `blue-500`、`gray-700` | 使用 `--ds-color-primary`、`--ds-color-text` | 主题和品牌调整只改语义映射     |
| 任意 `rounded-lg/rounded-3xl` 混用  | 按控件、面板、模态层级选择 Token             | 建立可预测的形状层级           |
| `transition` / `transition-all`     | 只声明实际变化的属性                         | 避免意外动画和性能问题         |
| 多处自定义按钮状态                  | 复用 `Button` / `IconButton`                 | 统一焦点、禁用、加载和按压反馈 |
| 表单错误靠颜色或顶部提示            | 字段就近错误 + 语义关联                      | 提升恢复效率和可访问性         |
| 任意 z-index 大数                   | 固定层级表                                   | 防止浮层军备竞赛               |

迁移优先级：

1. 新页面和新组件。
2. 当前正在修改的页面。
3. 设置、确认框、Toast 等跨页面高复用区域。
4. 历史稳定页面最后迁移，不为“清零技术债”制造回归。

## 13. 对抗性复核

最终方案刻意没有做三件看似“更完整”的事：没有引入新 UI 框架、没有建立 Storybook、
没有批量改造旧界面。原因不是它们没有价值，而是当前最主要风险是新增界面继续分叉，
不是缺少独立组件发布平台。轻量系统可以立即被使用，并保留升级路径。

当满足以下任一条件时，再评估更重方案：

- 三名以上开发者持续并行开发界面。
- 基础组件被多个应用或仓库共享。
- 需要视觉回归测试、版本发布和变更日志。
- 设计师需要从同一 Token 源自动同步 Figma Variables。

届时优先升级为“Token 生成流水线 + Storybook/Chromatic + 无障碍自动化”，而不是推翻
现有语义和组件 API。
