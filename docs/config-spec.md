## 零、30 秒版

配置 = **一个 ZIP 信封 + 一份 config.json 本体**。

```
tangbao-config-20260922-153000.zip
├─ config.json          ← 配置本体，人可读、可手改、可单独替换
├─ manifest.json        ← 打包元信息（谁导的、包多大、含不含图片）
└─ assets/              ← 配置引用到的图片（水印 LOGO、样例背景），按内容哈希命名
   └─ <sha256>.png
```

config.json 里只有 **三块**：全局默认（`defaults`）、项目树（`tree`）、未归属水印
（`unassignedWatermarks`）。

**三条铁律**

| 铁律                       | 一句话                                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **树是根**                 | 除了「全局默认」，所有配置都必须挂在一个树节点上。新增任何配置项，先回答「它挂在哪一层」，不许平铺进包。   |
| **没写 ≠ 空**              | 字段**没写** = 跟着上一层走；**写了个空** = 我就要空。两者的区别是整套继承的地基，逐字段的空值语义见 §四。 |
| **不放密钥、不放安全边界** | API Key、IPC 白名单、CSP 之类一律不进配置包 —— 它会被放到内网共享盘，等于谁都能拿到。详见 §九。            |

## 一、整体分层

### 1.1 信封（ZIP）

| 条目            | 必需 | 说明                                                                            |
| --------------- | ---- | ------------------------------------------------------------------------------- |
| `config.json`   | 是   | 配置本体。见 §1.2。                                                             |
| `manifest.json` | 是   | 打包元信息。谁在什么时候导的、含不含任务/图片、包内文件清单与校验和。           |
| `assets/`       | 否   | 配置引用到的图片资源（水印 LOGO、样例背景）。按内容哈希命名，重复引用天然去重。 |
| `images/`       | 否   | 素材与任务的原图。只有「完整包」才有；只发配置时不带。                          |

**为什么要信封**：水印预设里引用着 LOGO 图片，纯 JSON 装不下二进制。ZIP 只解决"装得下"，
配置本身仍然是一份可以直接打开、直接替换的 JSON。

### 1.2 本体（config.json）

```
config.json
├─ $schema                  声明；编辑器据此校验与悬浮说明
├─ format                   文件头（版本、导出信息）
├─ defaults                 全局默认层 ← 树上没表态的项都取这里
├─ tree                     项目树（第一层是产品线）
└─ unassignedWatermarks     没归属到任何产品的水印预设
```

### 1.3 七个模块

配置按**内容**分七个模块。模块用来讲解与排查，**在文件里不额外分组** ——
字段按模块顺序排列，一眼扫下来是连续的。

| #   | 模块           | 回答的问题                     | 谁能覆盖                     |
| --- | -------------- | ------------------------------ | ---------------------------- |
| ①   | **渠道与尺寸** | 投哪些渠道、每个渠道要几个尺寸 | 仅全局（字典式，节点只引用） |
| ②   | **输出位置**   | 产物写到哪                     | 全局 → 节点 → 节点内按渠道   |
| ③   | **命名**       | 文件叫什么                     | 仅全局                       |
| ④   | **水印**       | 加什么水印                     | 全局 → 节点 → 节点内按渠道   |
| ⑤   | **产出选择**   | 哪些方向允许跑、这次产出到哪些 | 仅全局                       |
| ⑥   | **画面**       | 怎么适配尺寸、横竖版           | 仅全局                       |
| ⑦   | **分发**       | 产出后怎么按天排期             | 仅全局                       |

> 为什么只有三个模块能被节点覆盖：**规格与开关收归全局，只有「这个方向交付到哪、
> 带什么水印、投哪些渠道」是方向自己的事**。给每个模块都开一层节点覆盖，会让
> 「到底哪个值生效」需要递归推理 —— 这正是 ADR-0010 / ADR-0013 收敛掉的东西。

## 二、命名规范

| 对象        | 规则                                                                            | 例子                                     |
| ----------- | ------------------------------------------------------------------------------- | ---------------------------------------- |
| 字段名      | 小驼峰（camelCase），不用下划线、不用短横线                                     | `watermarkPresetIds`、`maxSizeKb`        |
| 布尔字段    | 肯定式动词/形容词，**不用 `is`/`has` 前缀**（与现有代码一致，避免全仓改名）     | `enabled`、`pinned`、`randomize`         |
| 复数数组    | 用复数名词                                                                      | `sizes`、`channels`、`children`          |
| 目录字段    | 以 `Dir` 结尾                                                                   | `outputDir`、`targetDir`                 |
| 路径字段    | 以 `Path` 结尾（指具体文件）                                                    | `sampleBackgroundPath`                   |
| id 列表字段 | 以 `Ids` 结尾，且**名字里带上是「什么东西」的 id**                              | `watermarkPresetIds`、`selectedMediaIds` |
| 渠道 id     | 内置：`gdt`/`baidu`/`vendor`/`toutiao`；自建：`custom-<8位随机>`；保留：`clean` | `gdt`、`custom-a1b2c3d4`                 |
| 尺寸 id     | `<渠道id>-<宽>x<高>`                                                            | `gdt-1280x720`                           |
| 节点 id     | 以业务含义命名，不用序号                                                        | `dir-moon`（而不是 `n-17`）              |

### 术语对照（文件里的名字 ↔ 界面上的说法）

| 文件里                 | 界面上叫   | 说明                                                                                      |
| ---------------------- | ---------- | ----------------------------------------------------------------------------------------- |
| `media` / `Media`      | **渠道**   | 同一个东西的两个名字：代码从早期就叫 `PostprocessMedia`，一直没改。**别再加第三套叫法。** |
| `clean`（保留渠道 id） | 纯净版     | 无水印、不压缩、沿用生成尺寸                                                              |
| `collection` / node    | 项目树节点 | 产品线 → 产品 → 方向 → 扩展层                                                             |
| `preset`               | 水印预设   | 缩写只在 `compositeV2*` 模块内部用                                                        |

> ⚠️ **命名模板里的 token 是例外**：`{media}` 已经落在所有用户已配好的模板里，
> 改名等于让全部模板失效。所以 token 永久叫 `{media}`，即使界面上叫"渠道"。

## 三、字段规范

图例：**必填** = 缺了整包拒收；**选填** = 缺了走默认值。

### 3.1 `format` —— 文件头

| 字段           | 类型    | 必填 | 默认 | 取值范围 / 说明                                                              |
| -------------- | ------- | ---- | ---- | ---------------------------------------------------------------------------- |
| `kind`         | string  | ✅   | —    | 固定 `"tangbao-config"`。用来一眼认出这是配置本体。                          |
| `version`      | integer | ✅   | —    | 固定 `9`。版本不认识时整包拒收，**不做猜测性解析**。                         |
| `exportedAt`   | string  | ✅   | —    | ISO 8601 时间。排查「这份包什么时候发的」用。                                |
| `appVersion`   | string  | —    | `""` | 导出这份配置的糖包版本号，如 `"0.3.2"`。                                     |
| `skippedNodes` | integer | —    | `0`  | 导出时被跳过的回收站节点数。≥0。**必须报数**，否则"少了几十个方向"查不出来。 |

### 3.2 `defaults` —— 全局默认层

**它不对应树上的任何节点**，是「谁都没表态时用这个」。字段按模块分组如下。

#### ① 渠道与尺寸

| 字段                         | 类型        | 必填 | 默认        | 取值范围 / 说明                                                                                   |
| ---------------------------- | ----------- | ---- | ----------- | ------------------------------------------------------------------------------------------------- |
| `channels`                   | `Channel[]` | ✅   | 内置 4 渠道 | 全局唯一的字典。**允许空数组**（用户把渠道全删了）—— 空数组表示"没有渠道可用"，与"没写"是两回事。 |
| `Channel.id`                 | string      | ✅   | —           | 渠道内唯一。见 §二。                                                                              |
| `Channel.name`               | string      | ✅   | —           | 进 `{media}` 命名段。                                                                             |
| `Channel.sizes`              | `Size[]`    | ✅   | —           | 可空数组。                                                                                        |
| `Size.id`                    | string      | ✅   | —           | 约定 `<渠道id>-<宽>x<高>`。                                                                       |
| `Size.width` / `Size.height` | integer     | ✅   | —           | ≥1（像素）。                                                                                      |
| `Size.maxSizeKb`             | integer     | ✅   | `0`         | ≥0。**0 = 不压缩**。负数无意义，归一化时按 0 处理（而不是丢掉整条尺寸）。                         |
| `Size.enabled`               | boolean     | ✅   | `true`      | 这个尺寸参不参与产出。                                                                            |

> **渠道本身没有 `enabled` 字段**。ADR-0013 删掉了它 —— 它与「参与产出」对产出的影响完全等价，
> 两个开关说同一件事只会制造「勾了却不产出」的静默失效。**「这个渠道暂时不投」= 不勾参与产出。**

#### ② 输出位置

| 字段              | 类型                       | 必填 | 默认 | 取值范围 / 说明                                                                                                                                                                                                                                                    |
| ----------------- | -------------------------- | ---- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `outputDir`       | string                     | —    | `""` | 绝对路径。**空串 = 用应用默认位置**（本地保存目录下的 `postprocess`）。                                                                                                                                                                                            |
| `mediaOutputDirs` | `Record<渠道id, string[]>` | —    | `{}` | 每个渠道 1~2 个目录。**空数组或缺键 = 该渠道用 `outputDir`**（默认位置永远是兜底，不会被渠道配置弄丢）。<br>写 2 个 = **双写**（同一份产物两处各写一份，文件名相同）。<br>**上限 2 是刻意的**：导出位置是写盘放大（文件数 × 位置数），放开后一次误配就能写满磁盘。 |

#### ③ 命名

| 字段          | 类型   | 必填 | 默认                                                | 取值范围 / 说明                                                                   |
| ------------- | ------ | ---- | --------------------------------------------------- | --------------------------------------------------------------------------------- |
| `namePattern` | string | —    | `{date}-{product}-{direction}-{media}-{size}-{seq}` | 见下方 token 表。**必须含 `{seq}`**，否则同批次产物互相覆盖。空白模板回落默认值。 |
| `creator`     | string | —    | `""`                                                | 进 `{creator}` 段。空串 = 这一段被删掉。                                          |

**可用 token**：`{date}` `{line}` `{product}` `{direction}` `{creator}` `{media}` `{size}`
`{seq}` `{preset}`。

两条排版规则：① **取值为空的段整段删除**（不会出现 `A--B`）；② **未知 token 原样保留**，
便于在文件名里直接看出模板写错了（界面上另有提前提示，两者配合，不静默吞掉）。

#### ④ 水印

| 字段                 | 类型       | 必填 | 默认 | 取值范围 / 说明                                                                                                                                            |
| -------------------- | ---------- | ---- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `watermarkPresetIds` | `string[]` | —    | `[]` | 引用哪些水印预设。**`[]` = 不加水印**（显式）。数组顺序即产出顺序。<br>配 N 个预设 → 每个渠道尺寸各出 N 套，**产出量按预设数倍增**（先估磁盘再改这个值）。 |

#### ⑤ 产出选择

这三个字段最容易混，务必分清：

| 字段                       | 类型       | 必填 | 默认        | 回答的问题         | 说明                                                                                                 |
| -------------------------- | ---------- | ---- | ----------- | ------------------ | ---------------------------------------------------------------------------------------------------- |
| `selectedCollectionIds`    | `string[]` | —    | `[]`        | **哪些方向允许跑** | 启用范围。`[]` = 一个都没启用。                                                                      |
| `selectedMediaIds`         | `string[]` | —    | `["clean"]` | **默认投哪些渠道** | 这里的渠道才产出。不含 `clean` 就没有纯净版。                                                        |
| `savedTargetCollectionIds` | `string[]` | —    | `[]`        | **这次产出到哪些** | 「记住配置」存的产出目标，顺序即产出顺序。**`[]` = 没记住** → 每张图按自己的归属方向产出（原行为）。 |

> **启用范围**决定「允许」，**产出目标**决定「这次」—— 两者互相独立，判定也分开做：
> 目标要逐个过一遍启用范围，不在范围内的目标会被跳过**并说明是哪个方向**（不是照旧产出）。

#### ⑥ 画面

| 字段                 | 类型           | 必填 | 默认        | 取值范围 / 说明                                                                                                                                                                                                                                                                                               |
| -------------------- | -------------- | ---- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `direction`          | string \| null | —    | `null`      | `landscape` / `portrait` / `square` / `null`。**`null` = 按源图尺寸自动判定**。                                                                                                                                                                                                                               |
| `fitMode`            | string         | —    | `crop-fill` | `crop-fill` = 等比放大填满 + 裁边；`contain-blur` = 完整画面居中 + 四周补模糊底；`stretch` = 填满但比例被改变。<br>**全局一套，不参与节点继承**（做成方向级会让"为什么这张变形"要递归推理）。<br>未知值**必须回落默认值**，不能原样传下去 —— 渲染器遇到不认识的模式会中途抛错，整张产出作废且坏值会一直留着。 |
| `autoCompanionClean` | boolean        | —    | `true`      | 勾了任一渠道时，额外多产一份无水印原图。                                                                                                                                                                                                                                                                      |

#### ⑦ 分发

| 字段           | 类型    | 必填 | 默认    | 取值范围 / 说明                                                                |
| -------------- | ------- | ---- | ------- | ------------------------------------------------------------------------------ |
| `enabled`      | boolean | —    | `false` | 是否启用。**默认关闭**：它会在磁盘上移动文件，绝不能靠默认值把用户的产物搬走。 |
| `startDate`    | string  | —    | `""`    | `YYYYMMDD`。空串 = 未设置。                                                    |
| `days`         | integer | —    | `1`     | ≥1。小于 1 的取值一律按 1 处理。                                               |
| `mode`         | string  | —    | `copy`  | `copy` 保留原文件；`move` 搬走并清理已空的源目录。                             |
| `randomize`    | boolean | —    | `false` | 打乱后再平均分配，避免排期出现肉眼可见的规律。                                 |
| `skipWeekends` | boolean | —    | `false` | 只按工作日排期。                                                               |
| `renameMode`   | string  | —    | `date`  | `date` 替换文件名里的日期段；`sequence` 按日期文件夹名 + 序号重排。            |
| `modifyMd5`    | boolean | —    | `false` | 追加随机字节改变 md5，规避投放平台的「重复素材」判定。                         |
| `targetDir`    | string  | —    | `""`    | 分发目标根目录。空串 = 在产出目录原地按日期建子文件夹。                        |

### 3.3 `tree` —— 项目树

**同级按 `order` 升序，`order` 相同则按 `name` 排**。所以同级 `order` 不要重复。

| 字段               | 类型                | 必填 | 默认    | 取值范围 / 说明                                                                                                                                                 |
| ------------------ | ------------------- | ---- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`               | string              | ✅   | —       | 被「启用范围 / 产出目标 / 水印归属」引用。改它等于改动所有引用。                                                                                                |
| `name`             | string              | ✅   | —       | 进 `{line}` / `{product}` / `{direction}` 命名段。                                                                                                              |
| `kind`             | string              | —    | —       | `line` / `product` / `direction` / `extra`（第 4 层及以后）。**刻意不强制**：自建节点没有内置前缀，反推迟早出错；算不出就省略，恢复时按 `parentId` 挂回去即可。 |
| `order`            | integer             | ✅   | —       | 同级排序位。                                                                                                                                                    |
| `color`            | string              | —    | —       | 节点色标。                                                                                                                                                      |
| `pinned`           | boolean             | —    | `false` | 是否置顶。                                                                                                                                                      |
| `updatedAt`        | integer             | —    | —       | 参数最后改动时间（毫秒）。纯记录，不参与判定。                                                                                                                  |
| `overrides`        | `NodeOverrides`     | —    | —       | 本节点的覆盖值。**整个对象缺席 = 全部继承**。                                                                                                                   |
| `watermarkPresets` | `WatermarkPreset[]` | —    | —       | 挂在这个节点下的水印库。**判据是"有没有水印挂在它下面"，不看层级标记** —— 所以自建节点也能当库主。其余层级省略即可。                                            |
| `children`         | `Node[]`            | —    | `[]`    | 子节点。                                                                                                                                                        |

#### `overrides` —— 节点覆盖

**这一节能覆盖什么，是刻意限定的**：只有「这个方向交付到哪、带什么水印、投哪些渠道」
是方向自己的事；规格类的（尺寸、命名模板、分发）一律收归全局。

| 字段                 | 类型                    | 取值范围 / 说明                                                                                                    |
| -------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `enabled`            | boolean                 | `false` = 归属此方向的图片不产出变体。**缺省 = 参与**。                                                            |
| `outputDir`          | string                  | 空串 = 用默认输出位置（等价于没写）。                                                                              |
| `watermarkPresetIds` | `string[]`              | **`[]` = 显式「这个方向不加水印」**；字段缺席 = 继承上一层。                                                       |
| `selectedMediaIds`   | `string[]`              | **`[]` = 这个方向一个渠道都不投**；字段缺席 = 继承上一层。数组顺序即产出顺序。                                     |
| `byMedia`            | `Record<渠道id, {...}>` | 按渠道再细分，**只对本节点生效，不往父节点继续找**。只开放两项：`outputDirs`（1~2 个目录）、`watermarkPresetIds`。 |

> ⚠️ `byMedia` 里**没有** `namePattern` / `selectedMediaIds` / `distribution` / `direction`：
> 它们要么是全局规格，要么是「这个节点要不要跑」的开关。按渠道分只会让
> 「到底哪个值生效」需要递归推理。**类型上保持窄，比事后靠约定约束可靠。**

### 3.4 `unassignedWatermarks` —— 未归属的水印

| 项     | 类型                | 说明                                                                                                                                                                    |
| ------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数组项 | `WatermarkPreset[]` | `productId` 缺省（老数据）或指向一个**已被删除**的产品时，按产品分组的循环会漏掉它们。**必须单独兜住** —— 漏掉 = 静默丢配置，用户只会觉得"水印少了几套"却查不出为什么。 |

### 3.5 `WatermarkPreset` —— 水印预设

| 字段                   | 类型             | 必填 | 说明                                                                                                          |
| ---------------------- | ---------------- | ---- | ------------------------------------------------------------------------------------------------------------- |
| `id`                   | string           | ✅   | 被 `watermarkPresetIds` 引用。                                                                                |
| `name`                 | string           | ✅   | 进 `{preset}` 命名段。                                                                                        |
| `productId`            | string           | —    | 归属产品（节点 id）。**缺省或空串 = 未分配** → 不进任何产品的库，界面上单独成区，可一键指派。                 |
| `baseCanvas`           | `{width,height}` | ✅   | 画布基准，层里的比例值都以它为基准。                                                                          |
| `sampleBackgroundPath` | string           | —    | 预览用样例背景。空串 = 无。                                                                                   |
| `layers`               | `Layer[]`        | ✅   | 图层数组，自下而上渲染。**层是水印编辑器的事**，完整结构见 `src/features/composite/lib/compositeV2Types.ts`。 |
| `updatedAt`            | integer          | ✅   | 最后修改时间（毫秒）。                                                                                        |

层的三种类型：`text`（文字）、`image`（图片）、`logo`（品牌标识）。每层必带
`id` / `name` / `type` / `visible` / `opacity` / `position`。
两个**正向判定**字段（反向字段会让老数据整批出问题）：

- `orientation`：`"vertical"` 才竖排；缺省或任何其它值都按横排。
- `withIdentifier`：**缺省 = 带**署名；只有显式 `false` 才是不带。

## 四、继承与覆盖

### 4.1 继承链

```
defaults（全局默认）
  └ 产品线        overrides 覆盖上一层
      └ 产品      overrides 覆盖上一层
          └ 方向  overrides 覆盖上一层  ← 产出时实际取用的值
```

**逐级向上找，谁先表态就听谁的。** 只有 §3.3 表里列出的四项参与继承，
其余字段只存在于 `defaults`。

### 4.2 「没写」与「空」—— 逐字段对照（**最容易出错的一节**）

| 字段                       | 字段缺席（没写）       | 写了空值（`[]` / `""` / `null`）           |
| -------------------------- | ---------------------- | ------------------------------------------ |
| `watermarkPresetIds`       | 继承上一层             | `[]` = **这个方向不加水印**（显式覆盖）    |
| `selectedMediaIds`         | 继承上一层             | `[]` = **一个渠道都不投**                  |
| `outputDir`                | 继承上一层             | `""` = 用默认输出位置（≈ 没写）            |
| `mediaOutputDirs[渠道]`    | 继承（用 `outputDir`） | `[]` = 该渠道用 `outputDir`                |
| `savedTargetCollectionIds` | 用默认值 `[]`          | `[]` = 没记住 → 按图片归属方向产出         |
| `channels`                 | 用内置渠道表           | `[]` = **真的没有渠道**（不复活内置表）    |
| `namePattern`              | 用默认模板             | `""` / 空白 = 回落默认模板（不是空文件名） |
| `fitMode`                  | 默认 `crop-fill`       | 未知值 = 回落默认值（**不原样传下去**）    |

**判断"有没有配"时不能用 `length`** —— 空数组是有效值。这与 `undefined`（没表态）是两件事。

### 4.3 恢复顺序（不可交换）

```
① 立树  →  ② 灌每个节点的参数  →  ③ 放水印库  →  ④ 挂渠道与输出位置
```

顺序反了会出现「引用了不存在的水印 / 渠道」。**而引用关系是字符串，写的时候不校验，
出问题要到产出那一刻才炸** —— 这类错误极难自查。

「同 id 节点覆盖 + 本地独有的保留」也是刻意的：彻底替换会把使用者自建的方向、
连同挂在上面的素材一起变成孤儿，而换来的只是"树长得更一致"。

## 七、版本与兼容

- `format.version` 是**整数**，当前 `9`。结构变化才 +1；**纯新增可选字段不 bump**
  （缺字段 → 回落旧行为，没有需要折算的旧语义）。
- 版本不认识 → **整包拒收并说明原因**，不做猜测性解析。
- 拉取 = **单向覆盖**（发布方那份是权威）：同 id 节点一律以包为准，本地独有的方向保留。
  **拉取前先备份本机配置，备份失败就中止** —— 不做没有退路的覆盖。
- 包内**默认不含 API Key**。

## 九、不该放进配置的东西

配置包会被放到**内网共享盘**，能看到那个盘的人都能打开它。所以：

| 类别                       | 例子                                              | 为什么                                                                                          |
| -------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **密钥与凭据**             | API Key、代理口令、OAuth token                    | 放共享盘 = 谁都能拿到。API 配置住在设置里，**不进配置包**。                                     |
| **安全边界**               | IPC 路径白名单根、CSP、可信渲染进程校验           | 做成"用户可配置"等于把边界交给用户 = 没有边界。正确做法是从**用户已配置的输出目录反推**受信根。 |
| **本机绝对路径之外的环境** | 机器名、盘符映射、用户目录                        | 换台机器就没意义，只会让导入方多出一堆指不到的条目。                                            |
| **素材索引**               | `generatedAssets`                                 | 树属于配置，**素材索引不属于** —— 发过去只会让别人的素材库里多出指不到的条目。                  |
| **内部实现细节**           | UI 时序（防抖 400ms、hover 延迟 150ms）、动画时长 | 纯粹是噪声，用户不会改，改坏只会制造新的静默点。                                                |

## 十、跨机器一致性（「A 机发布 → 全新 B 机拉取」能还原到什么程度）

> 结论先行：**不能保证完全一致。** 但「中控台里改得动的那套配置」能一致。
> 本节的作用是把「哪些地方一定不一样、为什么」写死，免得每次都要重新推一遍。

### 10.1 能一致的部分

项目树（层级 / 名称 / 顺序 / 颜色 / 置顶）、每个方向的参数（参与渠道 / 显式空水印 / 输出位置 /
按渠道覆盖）、水印库（预设、归属 `productId`、LOGO、图层）、渠道与尺寸字典、命名模板与创作者、
画面方向与适配、分发配置、启用范围与产出目标 —— 这些都在 `config.json` 里，**逐字段一致**。

**如果你「水印只用水印库里的」**（即从不碰水印编辑器里的「替换图片素材」从本机磁盘选图）：
预设本体、`productId` 归属、每个图层的几何（`position` / `fontSize` / `lineHeight` /
`letterSpacing` / `padding` / `rotation` / `opacity` / `orientation` / `align`）、`baseCanvas`、
标识符配置、`globalFitMode` 全部逐字段一致 ⇒ **B 机上水印布局不会乱**。
唯一会变的是**字体观感**（见 10.4 后半），以及样例背景图（`sampleBackgroundPath` 是本机路径，
只影响编辑器预览，不影响产出）。

### 10.2 一定不一致的（设计如此，不是 bug）

| #   | 差异                      | 为什么                                                                                                                                                                                                                            |
| --- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | **API 密钥为空**          | 配置同步**不传** `includeSecrets`（`configSync.ts` 的 `publishConfigToSyncDir`），而 `sanitizeSettingsForBackup` 会把 `apiKey` / `profiles[].apiKey` / `agentProfiles[].apiKey` 全清空。放共享盘 = 谁都能拿到。**B 机需手工填。** |
| A2  | **回收站里的节点**        | 不导出，只在 `format.skippedNodes` 里报个数。回收站里的东西在别人机器上没有意义。                                                                                                                                                 |
| A3  | **工作区标签 / 会话草稿** | 在包里（`workspaceState`），但导入侧**不恢复** —— `replaceWorkspace` 要求 `importTasks === true` 且包里确实有任务，而配置包是 `importTasks: false`。                                                                              |
| A4  | **纯 UI 偏好**            | 上次停在中控台哪个 tab（`controlConsoleSection`）、树的折叠状态（localStorage）**都不进包** —— 它们是「我这台机器上想怎么看」。                                                                                                   |

### 10.3 值一致、但目标机器上「用不了」的（本机绝对路径）

`outputDir` / `mediaOutputDirs` / 节点 `overrides.outputDir` / `byMedia.outputDirs` /
`distribution.targetDir` / 设置里的 `customBackupPath` / 水印库的 `logoLibraryPath` 与
`backgroundFolders` —— 都是**绝对路径**。

包搬过去后，配置里照旧写着 `D:\交付\…`，但 B 机没这个盘就是没这个盘：产出会失败或写到别处。
**只有 UNC 共享路径（`\\server\share\…`）才真正跨机器可用。**

### 10.4 会真丢的 / 会变的：水印素材与字体 ⚠️

#### A. 本机选图型的水印素材（会真丢）

水印图层里引用的图片有 5 种形态（`CompositeV2ImageAssetRef`）：`stored` / `dataUrl` /
`project` / `path` / `internal`。

- 导出前的 `migrateLegacyCompositeAssets` 只迁 `dataUrl` 与 `project` 两种 → `stored`；
- `collectCompositeAssetIds` **只收集 `stored`**（`compositeAssets.ts:76-87`）；
- 而 `{ kind: 'path', path }` 由「**从本机磁盘选图**」直接写入（`PresetCanvasEditor.tsx:376`、
  `PresetLayerPanel.tsx:121`），既不迁移也不收集。

⇒ **这类图片不进包，B 机上断图。** 这是当前实现的一个真实缺口，已列入 §八 第 11 项。

**怎么自查**：判断标准不是「用不用库」，而是**那张图是怎么进到图层里的** ——

| 图片的来源                                       | 落成什么形态                  | 跨机器    |
| ------------------------------------------------ | ----------------------------- | --------- |
| LOGO 库选 LOGO（`PresetManagementTab.tsx:1001`） | `stored`                      | ✅ 不丢   |
| 素材库送入 / 预设导入                            | `dataUrl` → 导出前迁 `stored` | ✅ 不丢   |
| **编辑器里的「替换图片素材」→ 从本机磁盘选**     | `path`                        | ❌ **丢** |

（LOGO 库本身不受影响：`projectLogos` 走 `assetId` → 打包在 `composite-assets/` 里。）

#### B. 字体（不会乱位置，但会变字形）⚠️

- `fontFamily` 在水印编辑器里是一个**自由文本输入框**，不是可选列表 —— 它只是个**字体名**，
  **字体文件不随包走**：`public/` 下没有任何字体文件，全仓也没有 `@font-face`。
- 渲染时把它直接拼给 canvas：`ctx.font = \`${layer.fontWeight} ${layer.fontSize}px ${layer.fontFamily}\``
（`compositeRendererV2.ts:307`、`compositeTextLayout.ts:89`）。
- ⇒ B 机没装同名字体时，canvas 回退到系统默认字体：**字形、字重合成、单字宽度都会变**。
- **但布局位置不会乱**：文字是按 `position` 给出的**框**对齐的（`ctx.textAlign = layer.align`，
  贴框的左 / 右 / 中边），框的几何全在包里 ⇒ 居中还是居中、贴右边还是贴右边；字号是像素值、
  行距与字距也是数值 ⇒ 行 / 列位置不变。变的是**文字自己长什么样、有多宽**。
- 真正的风险是**溢出**：某行文字在 A 机上正好排满框、B 机字体更宽时，可能压出框外。

⇒ 要完全一致，B 机必须装有与 A 机**同名同版本**的字体（建议在发布说明里附上所用字体清单）。

### 10.5 时间戳与合并语义

- 节点 `createdAt` / `updatedAt` 在包里没存，恢复时用 `now` 补齐（`toAssetCollections`）→ 数值不同，用户看不见。
- 设置走 `mergeImportedSettings`：**干净的 B 机**（只有默认 profile）→ `hasOnlyDefaultProfiles` 为真 →
  **整份采用**；**已经加过 API profile 的机器** → 走合并分支，只追加 `profiles` / `customProviders`，
  其余字段保持本机值（`...current`）→ **不一致，且这是刻意的**。

### 10.6 时机与来源

- 发布是**手动**点「发布配置」→ 拿到的是**那一刻**的快照；发布之后改的配置不在包里。
- 拉取取的是配置目录里**字典序最大的那份**（`listSyncDirConfigs` 排序后取第一个），
  **不区分是谁发布的** —— 目录里有别人发过，你拉到的可能不是自己那份。

### 10.7 要「完全一致」必须满足的前提

1. B 机装**同一个大版本**的糖包（`format.version` 不认识就整包拒收）。
2. 发布前确认配置目录里**只有你一份**（或确认最新那份就是你发的）。
3. 发布完成后**不再改**配置。
4. 所有路径类配置改用 **UNC 共享路径**，或每台机器建同样的目录；且配置目录要在主进程白名单里
   持久化放行（R-31 / R-62，`local-settings.json` 的 `configSyncPath`）。
5. 水印素材不要用「从本机磁盘选图」—— 或等 §八 第 11 项落地。
