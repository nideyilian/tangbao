# 自包含素材库（库根收敛）手工冒烟清单

> 对应设计：`docs/superpowers/specs/2026-08-20-self-contained-library-design.md`
> 自动化冒烟（文件级 E2E）：`npx vitest run electron/library-smoke.test.ts`
> 本清单用于 Electron GUI 手工验证。每步给出操作与预期结果；任一步不符合预期即记录并回退该步。

前置：准备一台装有旧版本（库根收敛前）且已生成素材的机器，或手动构造旧布局（`userData/asset-kernel.sqlite` + `userData/local-saves/cache-images/`）。

---

## 1. 升级迁移（旧数据自动迁入库根）

| 项   | 内容                                                                                                                                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 用新版本覆盖安装，直接启动，进入素材库，浏览全部素材                                                                                                                                                                                                     |
| 预期 | ① 启动无报错、无需手工操作；② 素材/项目/标签/评分/备注与升级前完全一致；③ 打开 `userData/local-saves/`，可见 `db/`、`thumbs/`、`backups/` 与 `library.json`；④ `userData/asset-kernel.sqlite` 已不在原位；⑤ `library.json` 含 `catalogMigratedAt` 时间戳 |

## 2. 库根展示与说明

| 项   | 内容                                                                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 设置 → 数据管理 → 本地保存 卡片                                                                                                                                      |
| 预期 | ① 文案为「素材库位置」；② 说明含"复制此文件夹即备份整个素材库（退出应用后复制）"；③ 目录提示展示 `cache-images/ db/ thumbs/ backups/` 与任务输出目录；④ 可打开该目录 |

## 3. 修改库根（整库搬家）

| 项       | 内容                                                                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作     | 在设置中选择一个新的库根目录（如 `D:\我的素材库`）→ 确认                                                                                                                                                                   |
| 预期     | ① 完成后素材库内容不变；② 新库根下出现 `db/`（含 `asset-kernel.sqlite`）、`thumbs/`、`backups/`；③ 旧库根的 `db/`、`thumbs/`、`backups/` 已搬走（`cache-images` 由原复制逻辑处理，可留在旧处）；④ 素材详情/搜索/收藏均正常 |
| 回退验证 | ① 再次把库根改到一个**已含另一个素材库数据库**的目录 → 应报错且原库根与数据不变；② 改回原库根 → 数据仍在                                                                                                                   |

## 4. 复制库根 = 完整备份

| 项   | 内容                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------- |
| 操作 | 退出应用 → 复制整个库根文件夹到另一位置（或另一台机器）→ 在设置里把「素材库位置」指向复制出的目录 → 启动        |
| 预期 | ① 素材、项目、收藏、评分、标签、备注全部原样可用；② 生成记录/来源快照可追溯；③ 缩略图无需重新生成（随库根搬走） |

## 5. 缩略图磁盘缓存

| 项   | 内容                                                                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | ① 正常浏览素材库网格；② 删除库根 `thumbs/` 目录后重新浏览                                                                                                                    |
| 预期 | ① 首次浏览后 `thumbs/` 出现 `*.v3.webp` 文件；② 删除后网格短暂灰底即自动重建（浏览即回填），素材数据不受影响；③ 设置 → 数据管理 → 存储概览的「缩略图缓存」显示磁盘字节与数量 |

## 6. 导出元数据清单（JSONL）

| 项   | 内容                                                                                                                                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 设置 → 数据管理 → 素材库维护 → 「导出元数据清单（JSONL）」→ 默认保存到库根 `backups/` 或自定义位置                                                                                                                      |
| 预期 | ① 保存成功提示条数与素材数一致；② 用文本编辑器打开：每行一个素材，含 id/imageId/评分/收藏/标签/项目/备注/生成来源等字段；③ 库里全部素材都在清单中（含旧版本被软删的：2026-09-24 起的迁移会把它们恢复正常，见 ADR-0021） |

## 7. 运行库完整性校验

| 项         | 内容                                                                                                                                                                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作       | 设置 → 数据管理 → 素材库维护 → 「运行库完整性校验」                                                                                                                                                                                                                                    |
| 预期       | ① 正常库：提示"校验通过"，内联报告 SQLite 目录=正常、原图抽查 N 个、各项异常为 0；② 人为制造异常（向 `cache-images/` 放入一个未被引用的 png、或改坏一个文件内容、或删除一个被引用文件）后再次校验 → 对应孤儿/哈希不符/缺失项出现且不误报正常文件；③ 校验过程中不产生任何写入（仅读取） |
| 浏览器/PWA | 提示"浏览器环境仅支持 IndexedDB 记录校验，磁盘完整性检查需使用桌面版"                                                                                                                                                                                                                  |

## 8. ZIP 备份默认位置与打开备份目录

| 项   | 内容                                                                                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | ① 数据管理 → 导出数据 → 「导出所选数据」；② 点「打开备份目录」                                                                                                                                             |
| 预期 | ① 保存对话框默认打开库根 `backups/`；② 导出成功后在 `backups/` 可见该 ZIP；③ 「打开备份目录」在资源管理器中打开同一目录；④ 旧版在 `userData/backups` 留下的 ZIP 仍可导入（导入是文件级操作，不受位置影响） |

## 9. 回归与既有功能

| 项   | 内容                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | ① ZIP 导入轻量备份或勾选原图的完整备份（v6/v7）；② `tangbao://` 深链接打开素材；③ 本地 REST API / MCP 检索素材；④ 素材下载、复制图片、打开文件位置 |
| 预期 | 全部行为与升级前一致；REST/MCP 的素材路径解析仍正常（token 仍在 `userData/asset-api.json`，未随库移动）                                            |
