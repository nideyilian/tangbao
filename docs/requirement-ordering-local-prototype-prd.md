# 需求下单、策略中心与跑量知识库：本地原型 PRD

> 文档状态：待评审  
> 目标版本：第一阶段 Windows 本地可运行原型  
> 项目：糖包 V2 / GPT Image Playground  
> 更新日期：2026-07-20

## 1. 文档目的

本文档将已经确认的业务需求整理为可实施、可测试、可迁移的产品方案。

第一阶段不部署中心服务器，也不实现真正的多电脑共享；但本地原型必须完整验证以下两条业务闭环：

```text
优化师：
登录 → 鼠标选择产品/渠道/规格/类型/数量 → 自动拆单与规则路由
→ 立即进入生成队列 → 查看进度与预计完成时间 → 查看结果与本地归档

策略师：
导入历史素材与投放数据 → 视觉分析与 OCR → 相似素材聚类
→ 跑量知识提炼 → 人工审核 → 草稿测试 → 管理员审批 → 发布
```

本文档同时定义未来迁移到中心服务、PostgreSQL、Redis、向量库和 NAS 时必须保留的接口边界，但这些基础设施不属于第一阶段交付。

## 2. 产品背景

### 2.1 目标用户

核心下单用户是信息流优化师，主要生产广告投放图。优化师不应填写复杂提示词，而应通过选择已配置的业务选项完成下单。

策略师负责维护业务规则、生图策略、素材知识和固定生成模块。

管理员负责账号、权限、系统模型、运行参数、发布审批和全局运行管理。

### 2.2 现有痛点

- 下单依赖手工描述，操作成本高，容易漏填或表达不一致。
- 产品、渠道和素材方向的规则分散，无法自动组合和校验。
- 固定方向需要严格执行规范，通用生成又需要主动差异化，两者缺少统一路由。
- 大批量生成缺少组合级进度、预计完成时间、失败补跑和结构化归档。
- 历史素材与投放数据没有形成可检索、可审核、可版本化的跑量知识。
- 普通用户可接触过多模型和提示词配置，不利于策略保护和统一治理。

### 2.3 产品目标

1. 优化师仅使用鼠标即可快速完成正式下单。
2. 系统自动拆分“产品 × 渠道 × 规格 × 类型 × 数量”组合。
3. 固化类型自动命中固定模块，智能类型自动使用已发布知识。
4. 生成过程持续反馈排队、分析、生成、保存和失败状态。
5. 结果按稳定目录规则保存，并生成机器可读和人类可读清单。
6. 策略师可通过历史素材和投放数据沉淀跑量知识。
7. 所有正式生成均引用不可变的规则版本快照。
8. 第一阶段数据模型和服务调用均可迁移到未来中心化架构。

### 2.4 成功指标

第一阶段以功能验证为主，不以真实生产吞吐量为验收指标：

- 一次下单的主要业务输入不超过四个区域：产品、渠道、类型、数量。
- 用户不输入提示词也能完成生成。
- 有效组合、排除组合和总图片数计算准确率为 100%。
- 正式需求均能追溯到产品、渠道、类型、知识和固定规则版本。
- 单张失败不会阻塞同一需求中的其他图片。
- 应用重启后可恢复需求、规则、导入批次和可恢复的任务状态。
- 历史素材导入后可形成可审核的结构化分析结果与知识条目。

## 3. 第一阶段范围

### 3.1 必须实现

- Windows 桌面端本地登录。
- 三种模拟角色及权限隔离。
- 产品、渠道、素材类型、兼容关系和保存路径配置。
- 固定规则和智能策略的草稿、测试、审批、发布、版本与回滚。
- 极简需求下单页。
- 产品、渠道、类型多选；渠道内可多选 16:9 与 9:16。
- 自动拆单、兼容性判断、固定模块完整性判断和排除说明。
- 本地队列、进度、预计完成时间、取消、重试和失败补跑。
- 加急申请及管理员审批模拟。
- 每单上限和个人每日额度。
- 复用当前项目的真实生图能力。
- 保存到本机测试目录，并生成图片清单、需求概览和 manifest。
- 我的需求、需求详情、缩略图分页、组合筛选和打开本地目录。
- 历史素材文件夹导入和递归扫描。
- CSV / Excel 投放数据导入及字段映射。
- OpenAI Responses 兼容视觉分析、OCR 和知识提炼。
- 相似素材簇、单图分析详情和待审核知识。
- 批量审核、知识发布、稳定/潜力知识分层。
- 本地通知、桌面通知、审计日志。
- 服务接口层与本地适配器。

### 3.2 第一阶段明确不实现

- 中心服务器部署。
- 多电脑实时同步。
- PostgreSQL、Redis、Qdrant 或其他生产数据库部署。
- NAS 实际写入；仅使用本地目录模拟同样的路径规则。
- 应用退出后继续生成。
- 真正的组织级用户目录和在线账号服务。
- 飞书通知。
- 广告平台 API 直连。
- 金额成本核算。
- 手机端或浏览器移动端完整适配。
- GIF、PSD、视频和压缩包视觉分析。
- 生产级十万张/日吞吐验证。

### 3.3 未来阶段目标

- 中心 API、任务调度服务和多生成执行器。
- PostgreSQL 业务数据、Redis 队列、向量数据库和 NAS。
- 50 人协作、峰值 100,000 张/日容量。
- 飞书通知和广告平台数据回流。
- 生产级紧急队列、配额、限流、监控和高可用。

## 6. 原型演示数据

### 6.1 产品 SKU

1. 小红书 APP
2. 百万医疗险
3. 短剧图片

每个 SKU 作为独立产品选项。后台可保留产品系列字段，但下单页不增加系列与 SKU 两层选择。

产品隐藏配置至少包括：

- 名称、短名称、分类和代表图。
- 核心卖点。
- 目标人群。
- 使用场景。
- 品牌表达。
- 产品素材和参考图。
- 禁用内容。
- 默认保存目录。
- 启用状态、草稿版本和已发布版本。

### 6.2 渠道

1. 广点通
2. 头条
3. 百度

每个渠道支持 16:9 和 9:16，优化师可同时选择多个规格。后台保留渠道组与广告位规格结构，为未来拆成多个广告位选项做准备。

渠道隐藏配置至少包括：

- 渠道名称和代表图标。
- 支持规格。
- 画面偏好。
- 文案安全区。
- 合规约束。
- 默认保存目录。
- 启用状态和版本。

### 6.3 素材类型

1. 痛点型：智能策略。
2. 场景型：智能策略。
3. 卖点型：智能策略。
4. 诱导点击型：固定规则。
5. 促销型：固定规则。

每个类型卡片显示名称、代表图和一句话说明。代表图支持：

- 策略师上传。
- 从草稿测试结果中选取。

### 6.4 固定规则合规要求

“诱导点击型”仅表示合规的兴趣引导，不允许：

- 仿系统通知、聊天、未读消息或下载弹窗。
- 伪造关闭、播放、领取或操作按钮。
- 中奖、红包、订单、支付和虚假收益提示。
- 虚构权威、销量、效果数据或绝对化承诺。
- 未经授权的品牌界面、标志或版权素材。

“促销型”必须使用真实可用的活动信息；没有价格或活动数据时，禁止生成虚构折扣、倒计时或限量承诺。

## 7. 需求下单

### 7.1 页面目标

优化师尽可能只用鼠标完成下单，不接触提示词、模型或 API 配置。

页面主流程只有四个区域：

1. 产品
2. 渠道
3. 类型
4. 数量

规格是渠道卡片内的二级选项，不单独形成第五个表单区域。

### 7.2 产品选择

- 支持多选。
- 卡片显示产品图和 SKU 名称。
- 默认排序结合当前用户的使用频率、最近使用时间和常用组合。
- 新用户使用管理员配置的默认排序。
- 提供“常用、最近使用、分类、全部”鼠标筛选。
- 不依赖输入搜索即可完成选择；仍保留搜索作为辅助能力。

### 7.3 渠道和规格选择

- 渠道支持多选。
- 选中渠道后，在卡片中显示 16:9 和 9:16 规格按钮。
- 同一渠道可以同时选择两个规格。
- 没有选择任何规格的渠道不计入有效组合。

### 7.4 类型选择

- 支持多选。
- 卡片显示代表图、名称、说明和“固定规则/智能策略”标记。
- 固定规则标记不向优化师泄露具体提示词。

### 7.5 数量

- 表示每个“产品 × 渠道 × 规格 × 类型”组合生成的图片数量。
- 快捷值：50、100、150、200、250。
- 默认值：50。
- 加减步长：10。
- 快捷值、默认值和步长可由管理员配置。

### 7.6 总量公式

```text
总图片数 =
Σ（每个产品 × 每个渠道下实际选择的规格数 × 每个有效类型 × 每组合数量）
```

示例：

```text
1 个产品 × 1 个渠道 × 2 个规格 × 1 个类型 × 50 张 = 100 张
```

### 7.7 下单摘要

页面底部固定展示：

- 已选产品数。
- 已选渠道数。
- 已选规格数。
- 已选类型数。
- 原始组合数。
- 有效组合数。
- 排除组合数。
- 总图片数。
- 当前个人剩余额度。
- 动态预计完成时间。
- 排除原因入口。
- 申请加急入口。
- “立即下单”主按钮。

不再增加生成前确认弹窗；用户点击“立即下单”后直接创建需求并进入队列。

### 7.8 兼容性和自动排除

- 产品、渠道、规格和类型均可配置兼容关系。
- 固定规则缺少某个渠道或规格适配时，该组合无效。
- 多选导致部分组合无效时，系统自动排除无效组合，其余组合继续。
- 摘要必须列出被排除的组合和具体原因。
- 没有任何有效组合时禁止提交。
- 演示数据默认全部兼容。

### 7.9 单张需求上限

- 默认上限：500 张。
- 管理员可以修改。
- 超过上限时立即显示字段级错误并禁止提交。
- 错误必须说明当前总数、上限和建议减少的选择或数量。

### 7.10 个人每日额度

- 默认每位优化师每天 2,000 张。
- 按北京时间 00:00 重置。
- 管理员可调整个人额度或临时追加额度。
- 占用额度 = 已成功 + 生成中 + 已排队的计划图片。
- 取消后，未开始的图片释放额度。
- 失败和自动重试不重复扣额度。
- 达到上限后禁止普通下单；紧急单也需管理员追加额度。

### 7.11 加急申请

- “申请加急”是提交按钮旁的次要选项。
- 勾选后才展开加急原因。
- 优化师提交后等待管理员审批。
- 管理员可通过、驳回、取消加急，也可直接将需求设为紧急。
- 默认不预留紧急并发。
- 管理员可配置紧急并发预留比例；无紧急任务时预留能力回归普通队列。

### 7.12 复制历史需求

- 优化师可以复制自己的历史需求。
- 复制产品、渠道、规格、类型和数量。
- 新需求必须重新使用当前已发布规则，不沿用旧需求的规则快照。
- 若选项已归档或规则不完整，复制页显示失效项并要求重新选择。

## 8. 自动分析、规则路由与提示词组装

### 8.1 路由输入

每个组合的路由输入包括：

- 产品已发布版本。
- 渠道已发布版本。
- 规格。
- 素材类型已发布版本。
- 固定规则或智能策略版本。
- 已发布知识版本。
- 管理员系统默认生图参数。
- 差异化序号。

### 8.2 规则模式

#### 固化类型

用于诱导点击型和促销型：

- 必须命中已发布固定规则。
- 固定规则必须包含所选渠道和规格适配。
- 缺少适配时排除该组合，不回退到通用智能策略。
- 仅在固定规则声明的可变范围内做差异化。

#### 智能类型

用于痛点型、场景型和卖点型：

- 组合产品、渠道、类型和已发布跑量知识。
- 自动规划多个差异化方向。
- 不允许只通过随机 seed 形成表面差异。

### 8.3 冲突处理

业务组装优先级：

```text
固定生成模块 > 渠道规则 > 产品规则 > 类型通用规则 > 已发布知识 > 系统默认
```

任何层级的硬性合规禁用项均拥有否决权。固定模块不能覆盖更严格的渠道或系统合规禁令；发生冲突时，该组合被排除或任务失败前置，不得静默忽略。

### 8.4 主动差异化

同一组合中的多张图片需要主动变化：

- 构图与视觉焦点。
- 场景和空间关系。
- 产品占比与主体位置。
- 色彩和光影。
- 文案表达和信息层级。
- 视觉动线。

必须保持不变：

- 产品事实。
- 渠道规范。
- 规格安全区。
- 固定规则中不可变要求。
- 合规禁令。

### 8.5 尺寸自动适配

#### 16:9

- 优先水平视觉动线。
- 预留左右安全区。
- 避免将核心主体和关键信息压缩在中心窄区。
- 文案可采用左文右图、右文左图或横向层级。

#### 9:16

- 优先上下视觉动线。
- 预留顶部和底部渠道安全区。
- 主体与核心利益点需在首屏视觉中心。
- 控制纵向文案层级，避免底部重要信息被遮挡。

尺寸适配内容进入最终提示词快照。

### 8.6 跑量知识配比

智能类型默认使用：

- 80% 稳定跑量方向。
- 20% 潜力探索方向。

比例可由策略师按渠道修改，必须随策略版本发布，并写入需求快照。

## 9. 需求、组合与图片任务

### 9.1 拆单层级

```text
需求单
└─ 产品
   └─ 渠道
      └─ 规格
         └─ 素材类型
            └─ 图片任务
```

### 9.2 状态

需求状态：

```text
已创建
→ 等待加急审批（可选）
→ 排队中
→ 分析中
→ 生成中
→ 保存中
→ 已完成 | 部分失败 | 失败 | 已取消
```

图片任务状态：

```text
待处理 → 分析中 → 等待生成 → 生成中 → 保存中 → 成功
                                           └→ 重试中 → 失败
```

### 9.3 进度反馈

需求详情持续显示：

- 计划图片数。
- 已排队。
- 分析中。
- 生成中。
- 保存中。
- 成功。
- 失败。
- 已排除。
- 已取消。
- 总进度百分比。
- 当前阶段说明。
- 预计完成时间。
- 最近一次状态更新时间。

### 9.4 生成结构视图

详情页使用可展开层级：

```text
产品 → 渠道 → 规格 → 类型 → 图片
```

每层显示计划数、成功数、失败数和进度。默认只展开正在运行或异常节点，避免数百张图片造成信息过载。

### 9.5 预计完成时间

本地原型按以下信息滚动估算：

- 当前待处理图片数。
- 当前并发。
- 近期成功图片平均耗时。
- 当前需求剩余数量。
- 重试中的任务。

没有足够历史数据时显示区间估计，并标注“基于默认速度”。不得展示没有依据的精确时间点。

未来生产目标：

- 紧急单不超过 50 张：目标 30 分钟。
- 紧急单 51–200 张：目标 1 小时。
- 紧急单 201–500 张：目标 2 小时。
- 普通单：数小时或当日完成，峰值可延续到次日。

第一阶段仅展示估算逻辑，不以这些生产时效作为本地原型性能承诺。

### 9.6 重试

- 单张图片自动重试最多 2 次。
- 自动重试不重复占用额度。
- 仍失败则标记失败，不阻塞其他图片。
- 优化师可对自己的失败项执行“一键补单”。
- 管理员可重跑任意失败项。
- 补单创建新的图片任务，并保留来源任务 ID。

### 9.7 取消

- 排队中：优化师可整单取消。
- 生成中：停止尚未开始的任务；正在调用 API 的任务尽力取消。
- 已生成和已保存结果继续保留。
- 需求最终状态标记为“用户终止”或“管理员终止”。
- 取消动作写入审计日志。

### 9.8 本地原型关闭语义

- 应用完全退出后不继续执行。
- 重启后恢复需求和队列记录。
- 对中断的生成任务显示“待恢复”，由用户或管理员明确选择继续或取消。
- 不得把本地原型描述为后台服务。

## 11. 策略中心

### 11.1 配置对象

- 产品 SKU。
- 渠道。
- 规格。
- 素材类型。
- 产品与渠道/类型兼容关系。
- 固定规则。
- 智能策略。
- 跑量知识引用。
- 保存目录。

### 11.2 生命周期

```text
草稿 → 测试中 → 待审批 → 已发布 → 已归档
                           └→ 已驳回 → 草稿
```

- 策略师编辑草稿。
- 草稿测试通过后提交发布。
- 管理员审批后上线。
- 只有已发布版本可用于正式需求。
- 已发布版本不可直接修改；编辑时创建新草稿版本。
- 管理员可查看版本差异和回滚。

### 11.3 规则快照

下单时冻结：

- 产品版本。
- 渠道版本。
- 类型版本。
- 固定规则或智能策略版本。
- 知识版本和稳定/探索比例。
- 合规规则版本。
- 最终组装提示词。
- 生图参数。

排队或生成中的需求不受后续发布影响。

### 11.4 停用与归档

被历史需求使用的产品、渠道、类型、规则和知识不得物理删除：

- “停用”后不再出现在新下单页。
- “归档”后进入历史管理视图。
- 历史需求继续显示原名称、版本和快照。
- 管理员可恢复。

### 11.5 草稿测试

- 保存到独立的 `strategy-tests` 目录。
- 每次默认最多 20 张，管理员可调整。
- 文件标记草稿版本和测试人员。
- 不进入正式需求统计。
- 不自动进入跑量知识库。
- 策略师可以从测试结果中选择类型代表图。

### 11.6 固定规则编辑器

固定规则至少包含：

- 适用类型。
- 适用产品范围。
- 渠道与规格适配。
- 不可变画面要求。
- 可变维度。
- 构图规范。
- 文案规范。
- 元素规范。
- 禁用项。
- 尺寸适配规则。
- 测试用例和测试结果。

编辑器需要提供结构化字段和完整规则预览，不以单个超长文本框承载全部内容。

## 12. 历史素材与跑量知识库

### 12.1 输入类型

支持：

- JPG / JPEG
- PNG
- WebP
- CSV
- Excel

图片递归扫描子文件夹。

暂不支持：

- GIF
- PSD
- 视频
- 压缩包

不支持文件进入导入报告，不导致整个批次失败。

### 12.2 导入批次

默认限制：

- 单批最多 500 张。
- 分析并发 2。
- 管理员可调整。

支持：

- 暂停。
- 继续。
- 取消。
- 失败重试。
- 文件哈希去重。
- 增量扫描。
- 已分析文件默认跳过。

### 12.3 无数据表导入

策略师必须为整个文件夹选择：

- 产品：必填。
- 渠道：必填。
- 素材类型：可选，可由系统自动判断。
- 时间范围：建议填写。

### 12.4 有数据表导入

统一要求数据中包含：

- 图片相对路径、文件名或唯一素材 ID。
- 曝光。
- 点击。
- 转化。

导入映射页允许策略师用鼠标指定：

- 哪一列对应图片。
- 哪一列对应曝光。
- 哪一列对应点击。
- 哪一列对应转化。
- 可选产品、渠道、类型和日期列。

数据表的单图标签优先于文件夹默认标签。

导入预检显示：

- 成功关联。
- 未匹配图片。
- 重复数据。
- 缺失指标。
- 格式错误。
- 将被跳过的记录。

### 12.5 素材唯一性

每张图片计算内容哈希并创建稳定素材 ID。图片重命名后仍可识别为同一文件。

同一图片在不同批次出现时：

- 素材实体不重复创建。
- 可以新增不同日期或渠道的效果记录。
- 分析结果按模型版本保留。

### 12.6 视觉分析

第一阶段使用管理员配置的 OpenAI Responses 兼容视觉模型。

每张素材输出：

- OCR 原文。
- 标题、利益点、数字、行动引导和免责声明。
- 主体和产品占比。
- 构图版式。
- 视觉焦点。
- 场景。
- 人群。
- 色彩。
- 光影。
- 文案位置与表达方式。
- 渠道适配。
- 合规风险。
- 自动判断的素材类型。
- 模型版本。
- 原始模型响应引用。

策略师可以修正 OCR 和结构化字段，修正内容写入独立人工覆盖层，不覆盖原始模型结果。

### 12.7 衍生指标

系统根据原始数据计算：

```text
点击率 = 点击 / 曝光
转化率 = 转化 / 点击
曝光转化率 = 转化 / 曝光
```

分母为零时显示“无有效样本”，不得计算为 0% 后参与排名。

### 12.8 跑量判定

按产品、渠道和时间范围形成比较组。

#### 稳定跑量知识

- 达到管理员配置的最低曝光门槛。
- 点击率、转化率或组合评分进入配置的前百分位。
- 证据权重高。

#### 潜力探索知识

- 样本量不足。
- 点击率或转化率异常突出。
- 保留为探索信号，不直接等同于稳定结论。

随着新数据导入：

- 潜力知识可升级为稳定知识。
- 后续表现下降时自动降权。
- 已发布知识不被静默改写，需要形成新候选版本。

### 12.9 聚类与知识提炼

页面层级：

```text
导入批次 → 相似素材簇 → 待审核知识条目
```

相似素材簇显示：

- 代表图。
- 素材数量。
- 共同视觉特征。
- 产品、渠道、类型分布。
- 曝光、点击、转化分布。
- 稳定或潜力标记。
- 证据素材。

知识条目必须记录：

- 结论。
- 适用范围。
- 不适用范围。
- 证据素材 ID。
- 指标时间范围。
- 置信度。
- 稳定/潜力类型。
- 分析模型版本。
- 创建人、审核人和发布时间。

### 12.10 知识审核

自动提炼的内容先进入“待审核”：

- 修改。
- 发布。
- 驳回。
- 归档。
- 合并。
- 查看逐张分析详情。

支持多选后的批量发布、批量归档、批量驳回和批量加标签。

以下操作仍需逐项确认：

- 合并知识结论。
- 发布固定规则。

未经审核的知识只能用于草稿测试，不能进入正式生成。

### 12.11 自动扫描

第一阶段使用本地目录模拟 NAS 数据目录：

- 默认每 30 分钟扫描。
- 管理员可配置为 10 分钟、30 分钟、1 小时或每天固定时间。
- 支持“立即扫描”。
- 应用未运行时不扫描。

## 15. UI/UX 规范

### 15.1 目标平台

- Windows 桌面端。
- 设计基准：1440 × 900。
- 最低可用：1280 × 720。
- 暂不要求手机端完成策略配置和知识审核。

### 15.2 设计原则

- 延续当前项目 React + Tailwind 的视觉语言。
- 使用专业、数据密集但层级清楚的桌面工作台风格。
- 主色沿用蓝色语义；成功使用绿色，警告使用琥珀色，错误使用红色。
- 不使用 AI 紫粉渐变作为主要视觉。
- 不使用 Emoji 作为结构性图标，统一使用现有 SVG/Lucide 图标。
- 每个页面只有一个主操作。
- 所有长流程提供持久状态，不以 Toast 替代任务记录。

### 15.3 下单页布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 需求下单                                      今日剩余 1,850 │
├──────────────────────────────────────────────────────────────┤
│ 1. 产品       [常用] [最近] [分类] [全部]                    │
│ [产品卡] [产品卡] [产品卡] ...                               │
├──────────────────────────────────────────────────────────────┤
│ 2. 渠道                                                     │
│ [广点通  ✓  16:9 ✓  9:16 ○] [头条 ...] [百度 ...]           │
├──────────────────────────────────────────────────────────────┤
│ 3. 类型                                                     │
│ [示例图 痛点型] [示例图 场景型] [示例图 卖点型] ...          │
├──────────────────────────────────────────────────────────────┤
│ 4. 每组合数量  [50] [100] [150] [200] [250]  [-] 50 [+]     │
├──────────────────────────────────────────────────────────────┤
│ 固定摘要：有效 8 组 · 排除 1 组 · 共 400 张 · 预计 3–5 小时 │
│ [申请加急]                                      [立即下单]   │
└──────────────────────────────────────────────────────────────┘
```

### 15.4 交互反馈

- 卡片点击后 100ms 内出现选中反馈。
- 异步操作超过 300ms 显示加载状态。
- 提交按钮在创建需求期间禁用，防止重复下单。
- 错误显示在相关区域旁，并提供修复方式。
- 排除组合不能只用颜色区分，必须显示图标、文字和原因。
- 鼠标悬停可以补充说明，但关键能力不能仅依赖悬停。
- 进度变化采用 150–300ms 过渡。
- 尊重 `prefers-reduced-motion`。

### 15.5 可访问性

- 可点击区域建议不小于 44 × 44px。
- 所有字段有可见标签。
- 图标按钮提供 `aria-label`。
- 代表图提供有意义的替代文本。
- 键盘焦点顺序与视觉顺序一致。
- 可用空格或 Enter 切换多选卡片。
- 正文和背景对比度至少 4.5:1。
- 状态不能仅通过红/绿色表达。
- Toast 使用非抢焦点的 `aria-live="polite"`。

### 15.6 大列表性能

- 图片和任务列表超过 100 项时使用虚拟化或分页。
- 缩略图懒加载并预留固定比例空间。
- 不在列表中读取原图。
- 筛选和聚合避免在每次渲染中重复全量计算。

## 16. 本地原型技术方案

### 16.1 总体原则

第一阶段继续使用当前 Electron + React + TypeScript + Zustand + IndexedDB 技术栈。新增能力必须通过领域服务接口调用，UI 不直接依赖本地存储或 Electron IPC，从而允许未来替换为中心 API。

### 16.2 服务接口

```ts
interface AuthService {
  login(input: LoginInput): Promise<Session>
  logout(): Promise<void>
  getSession(): Promise<Session | null>
}

interface ConfigurationRepository {
  listPublishedCatalog(): Promise<PublishedCatalog>
  saveDraft(draft: StrategyDraft): Promise<void>
  submitForApproval(versionId: string): Promise<void>
  publish(versionId: string): Promise<void>
  rollback(entityId: string, versionId: string): Promise<void>
}

interface OrderRepository {
```

## 18. 实施计划

实施遵循“先建立可迁移的领域边界，再连接真实生成和视觉分析”的顺序。

实现：

- 新增需求、配置、知识、权限和审计类型。
- 定义服务接口和本地适配器工厂。
- IndexedDB schema 升级与迁移。
- 演示数据 seed。

验收：

- 旧数据可正常启动。
- 新领域数据可创建、保存、重启恢复。
- UI 不直接读取 Electron 文件 API。

### 阶段 1：本地登录与角色化导航

实现：

- 登录页和三组模拟账号。
- 会话持久化。
- 角色路由守卫。
- 角色默认首页。

验收：

- 退出后清除会话，不删除业务数据。

### 阶段 2：配置目录与版本工作流

实现：

- 示例图上传与测试图选取。
- 草稿、测试、提交审批、审批、发布、归档和回滚。

- 本地路径规则、唯一素材 ID 和防覆盖。

验收：

- API 配置正确时可真实生成。
- 单张失败不阻塞其他任务。

- 输出目录、文件名和清单字段一致。

- 关键操作均有审计记录。

## 21. 风险与控制

| 风险                     | 影响                         | 控制措施                                         |
| ------------------------ | ---------------------------- | ------------------------------------------------ |
| 第一阶段范围较大         | 实施周期和回归面增加         | 严格按阶段交付，每阶段独立验收                   |
| 真实生成默认数量 50      | 测试可能产生大量 API 调用    | 开发/测试使用 Mock API；真实调用前显示总量和额度 |
| 当前任务模型与需求域耦合 | 容易复制第二套生成逻辑       | 通过执行适配器复用现有生成能力                   |
| 视觉模型输出不稳定       | 结构化分析可能缺字段         | JSON schema 校验、修复重试、保留原始结果         |
| 本地 IndexedDB 数据增长  | 大量缩略图和分析结果影响性能 | 图片留在文件系统，DB 只存元数据；列表虚拟化      |
| 应用退出中断队列         | 用户误以为后台继续           | 明确本地语义，重启后提供待恢复入口               |
| 固定规则和渠道合规冲突   | 可能产生不合规素材           | 硬性禁令拥有否决权，生成前校验                   |
| 小样本偶然高指标         | 错误沉淀为稳定规律           | 稳定/潜力双层知识和最低样本门槛                  |
| 原型接口不利于未来迁移   | 中心化时需要重写             | 从第一天使用服务接口和本地适配器                 |
| 敏感 API 密钥泄露        | 安全风险                     | 仅管理员可见，不写入快照、日志和导出             |

## 22. 未来中心化架构约束
