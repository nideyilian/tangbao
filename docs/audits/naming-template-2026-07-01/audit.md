# 命名模板与编辑器交互审计

## 审计范围

- 产品区域：后期处理 → 预设管理 → 命名模板
- 用户目标：用内置变量和自定义变量组织模板，并可靠预判最终目录名和文件名
- 审计方式：在本地运行中的实际界面完成交互取证，再核对编辑器、状态管理和导出路径代码
- 约束：同一个模板同时参与目录和文件名生成是已确认的产品需求，不作为逻辑缺陷

## 流程证据

1. `01-default-state.png` — 默认模板（健康度：一般）
   - 变量会以解析后的示例值显示，动态内容和普通分隔符可以视觉区分。
   - 只展示一串词条，不展示“最终目录 / 最终文件名”，用户看不到同一模板在两个位置的实际结果。
   - 编辑框占据较大高度，但真正关键的输出预览缺席。

2. `02-variable-inserted.png` — 点击“序号”插入变量（健康度：较差）
   - 新变量被直接追加到末尾。
   - 系统不会自动补分隔符，也没有插入前预览或撤销提示，结果立即变成 `…渠道1`。

3. `03-built-in-name-collision.png` — 创建名为 `date` 的自定义变量（健康度：危险）
   - 界面允许自定义变量和内置变量重名。
   - `{date}` 词条立即显示自定义值“自定义日期”，看起来像是覆盖成功。
   - 实际导出替换顺序先处理内置 `{date}`，随后自定义变量已经无 token 可替换，因此最终仍会使用真实日期。可见预览与导出结果不一致。

4. `04-caret-insert-appends.png` — 把光标移到开头后点击“渠道”（健康度：较差）
   - 虽然用户先把光标放在模板开头，按钮仍把变量追加到末尾。
   - “插入变量”实际是“追加变量”；它忽略光标和选区，并允许重复变量无提示。

5. `05-clear-silently-resets.png` — 全选并删除模板（健康度：较差）
   - 清空后编辑器立即恢复默认模板。
   - 没有必填说明、错误状态或“已恢复默认值”反馈，用户容易认为删除操作没有生效或编辑器失灵。

6. `06-draft-leaks-between-presets.png` — 输入自定义变量名后切换预设（健康度：危险）
   - 在默认预设中尚未提交的 `draftA` 被带入新预设。
   - 若用户随后点击“添加自定义值”，草稿会加到错误的预设中。
   - 原因是自定义变量输入框的本地状态没有随 `preset.id` 切换而重置。

## 主要问题

### P1 — 预览与真实导出可能不一致

自定义变量值在编辑器预览中覆盖内置变量值，但导出逻辑优先替换内置变量。`date`、`channel`、`size`、`preset` 和 `index` 都可触发这一问题。此问题会产生“看见的是 A，导出的是 B”的结果，应优先修复。

### P1 — 插入操作不遵循光标

变量按钮始终执行字符串末尾追加，完全不读取编辑器选区。按钮文案、用户动作和结果不一致；追加时又不处理分隔符，容易生成粘连名称。

### P1 — 编辑草稿跨预设泄漏

自定义变量名和值使用组件本地状态，但组件在切换预设时被复用。未提交草稿会进入另一个预设上下文，存在误配置风险。

### P2 — 缺少最终路径预览

同一模板同时生成目录名和文件名是预期功能，但界面没有明确说明，也没有分别展示：

- 最终目录：`输出根目录 / 解析后的模板 / …`
- 最终文件：`解析后的模板.jpg`
- 非法字符清理、斜杠分层、空段过滤和重名后缀后的结果

当前蓝色词条只是变量示例，并不是最终输出预览，因此无法承担校验作用。

### P2 — 自定义变量缺少约束和错误反馈

- 允许与内置变量重名。
- 名称只移除空白和花括号，仍允许斜杠、冒号等容易造成歧义的字符。
- 同名自定义变量会被静默更新，没有“已存在”反馈。
- 值可以为空；空值会形成几乎不可见的变量词条。
- 删除自定义变量不会处理模板中已有的 token；导出时可能留下字面量 `{变量名}`。
- 手动输入未知 token 也不会报错，最终可能将 `{unknown}` 原样用于目录和文件名。

### P2 — 拖拽排序只移动变量，不移动分隔符

编辑器拖动的是单个变量词条，`-`、`_` 等普通文本留在原位。因此“调整变量顺序”可能产生双分隔符、尾部分隔符或词条粘连。界面文案把它描述成可靠排序，但实现更接近自由排版。

### P2 — 修改立即持久化，缺少编辑边界

每次输入都会直接更新全局持久化状态，没有保存、取消、重置、撤销入口。对 contenteditable 这种易误触的编辑器来说，试验性输入也会立即成为正式配置。

## 可访问性风险

- 编辑区域声明为 `role="textbox"`，但没有 `aria-multiline`，说明文字也没有通过 `aria-describedby` 关联。
- 可拖动变量是不可聚焦的 `span`，键盘用户没有等价的排序操作。
- 内置变量词条没有独立删除按钮；只能依赖光标位置与 Backspace/Delete，操作方式不可发现。
- 按钮和说明文字较小，变量按钮的点击区域偏紧。
- 组件没有输入法组合事件处理；每次输入都会写入状态并重建 HTML。中文输入法下的候选、光标稳定性需要专项实机验证。

## 测试覆盖缺口

现有测试覆盖了 token 渲染、DOM 转模板和基础自定义变量添加，但没有覆盖：

- 按光标位置插入；
- 自定义变量与内置变量重名；
- 预览值与导出替换结果一致；
- 切换预设时清理草稿；
- 清空、未知 token、空值和删除变量；
- 拖动变量后分隔符的结果；
- 键盘操作和中文输入法组合输入。

## 建议顺序

1. 禁止自定义变量使用内置名称，并让预览与导出共用同一个解析函数。
2. 让变量按钮真正插入到当前光标/选区；如果没有有效光标，再明确追加并智能处理分隔符。
3. 以 `preset.id` 隔离或重置自定义变量草稿。
4. 增加“最终目录 + 最终文件名”双预览，并展示清理后的真实结果。
5. 为模板增加明确的校验状态、恢复默认按钮和未知 token 提示。
6. 再决定保留自由拖拽，还是改成更稳定的结构化 token 排序器。

## 证据限制

- 截图可以证明可见状态和主要交互结果，但不能证明完整 WCAG 合规。
- 拖拽排序、屏幕阅读器朗读和中文输入法组合输入尚未完成专项设备测试。
- 本次没有执行真实文件导出；预览/导出不一致结论来自已复现界面状态与导出替换代码的直接对照。
