# 后期处理模块审计

## 审计范围

- 表面：后期处理 V2 的“批量导出”和“预设管理”。
- 用户目标：完成背景、预设、输出目录和尺寸规则配置后启动批量导出。
- 证据：
  - `01-batch-export-empty-state.png`：当前批量导出完整界面。
  - `02-configured-but-disabled.png`：用户提供的已配置但按钮禁用状态。
  - `03-preset-management.png`：预设管理与输出根目录所在位置。
- 边界：浏览器无法访问 Electron 的真实本地文件选择器，因此没有实际写入用户目录或执行完整导出。

## 流程步骤

1. **进入批量导出 — 健康度：一般**
   - 页面同时展示背景、预览、规则、预设和结果，信息完整。
   - 1280px 宽度下内容非常密集，关键状态被压缩到小字和弱对比区域。

2. **配置预设及输出目录 — 健康度：一般**
   - 输出根目录、命名模板、图层和预览集中在同一预设详情中。
   - 输出根目录位于另一个标签页；批量导出页只给出笼统错误，无法指出哪个预设缺少目录。

3. **启用尺寸规则 — 健康度：较差**
   - 默认规则全部为 `enabled: false`。
   - 尺寸和 KB 输入框即使规则未启用也可以编辑，容易让用户误以为“填完参数就是启用”。
   - 单条规则的启用入口是覆盖整行的透明按钮，没有显式复选框或“已启用”文本。
   - 分类复选框仅表示“全部启用”，部分启用时没有 indeterminate 状态。

4. **启动导出 — 健康度：较差**
   - 按钮由背景、预设组、勾选预设、输出目录和计划数量五项共同决定。
   - 所有失败原因被压成同一句，用户无法定位缺失项。
   - 初始 `runStatusText` 永远显示“请完成背景、预设和尺寸规则配置”，配置变化后不会刷新。
   - 计划构造会直接丢弃背景方向与尺寸方向不同的组合；这与“裁切填满 / 完整留边 / 拉伸变形”适配选项冲突。

## 根因

`BatchExportTab.tsx` 中 `canStartExport` 要求：

1. 已加载背景；
2. 预设组存在；
3. 至少一个预设被勾选；
4. 每个已勾选预设都有 `outputRootPath`；
5. `plannedExportCount > 0`。

第 5 项由 `expandCompositeExportItems()` 计算。该函数只保留背景与输出规则方向完全相同的组合。因此即便背景、输出目录、预设和规则都已填写，只要启用规则与背景方向不一致，计划数仍为 0，按钮继续禁用。

从截图可见的另一高概率原因是尺寸卡片只有数值、没有清晰的单条启用状态。默认规则全部关闭，编辑尺寸数值不会自动启用规则。

## 做得好的点

- 使用 `structuredClone` 固化导出快照，运行中修改配置不会污染当前批次。
- 预设组、预设、全局规则、预设覆盖规则之间的职责划分清楚。
- 命名模板支持日期、渠道、尺寸、预设、序号和自定义变量，扩展性较好。
- 文件重名时自动追加后缀，避免覆盖已有文件。
- 导出结果按成功、警告、失败和历史拆分，具备可恢复的批处理心智模型。
- 暂停、继续、取消只在图片之间生效，虽然粒度有限，但状态机简单且安全。
- 最大 KB 使用质量二分搜索；无法满足时保留结果并给出警告，而不是静默失败。
- 合成 overlay 按预设版本和目标尺寸缓存，可减少重复绘制。

## 主要问题

1. **P0：方向过滤与适配模式冲突**
   - 非等比适配已经能够处理跨方向图片，导出计划却提前过滤掉这些组合。

2. **P0：验证不可诊断**
   - 一个布尔值和一句通用文案承载五种失败原因。

3. **P1：状态文案陈旧**
   - `runStatusText` 初始错误提示不会随配置状态更新。

4. **P1：规则启用交互隐晦**
   - “设置数值”和“启用规则”视觉上没有明确区分。

5. **P1：批量临时状态不持久化**
   - 背景文件夹、已勾选预设、自定义参数等不在 persisted state 中；重启或热更新后需要重新操作。

6. **P1：模块当前不处于可发布测试状态**
   - Composite 测试为 118/120，通过率高，但 `BatchExportTab` 有 2 个失败。
   - TypeScript 检查还有 7 个 Composite 类型错误，包括 asset 联合类型未收窄、测试 fixture 缺少宽高和缺失类型导入。

7. **P2：取消粒度较粗**
   - 单张大图正在解码或渲染时无法立即暂停/取消。

8. **P2：overlay 缓存无上限**
   - 多预设、多尺寸和频繁修改可能持续扩大 `Map`。

## 可访问性风险

- 多个图标按钮在 DOM 中没有可访问名称。
- 单条尺寸规则使用透明覆盖按钮，焦点和启用状态不直观。
- 关键说明大量使用 11–12px 小字和浅灰色，低视力及高缩放场景风险较高。
- 禁用按钮只通过透明度表达状态，且错误说明未与按钮建立 `aria-describedby` 关系。
- 当前证据不足以确认完整键盘顺序、焦点环、屏幕阅读器播报和 200% 缩放表现。

## 建议顺序

1. 删除方向一致性过滤，或将它改成显式、可关闭的“仅匹配同方向”选项。
2. 建立 `getExportReadiness()`，返回每个具体缺失项及受影响预设，而不是单个布尔值。
3. 直接从 readiness 派生文案，移除陈旧的初始 `runStatusText`。
4. 给每条尺寸规则增加明确复选框和启用样式；分类复选框支持部分选中。
5. 在批量页提供“去设置”链接，直接定位缺少输出目录的预设。
6. 修复现有 2 个测试失败和 7 个类型错误后再继续扩展功能。
