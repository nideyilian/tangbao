# 糖包 生成素材库设计方案

> 日期：2026-08-14  
> 状态：待确认后实施  
> 目标版本：素材库 V1  
> 适用端：Electron、浏览器/PWA  
> 产品模式：Operate（高频生产工具）

## 1. 方案结论

将现有顶级入口“画廊”升级为“素材库”，不新增一个与画廊并列、内容重复的页面。素材库保留两个工作视角：

1. **图片**：以每张生成结果为管理对象，承担查找、整理、收藏、评分、复用、导出和回收站能力。
2. **生成批次**：保留现有任务卡、SOP 批次、失败状态、重试和任务导航，承担生成过程追溯。

原图由 糖包 托管且只保存一份：

```text
StoredImage（内容哈希 ID，对应一份原图）
  ├─ GeneratedAsset（素材管理记录）
  ├─ TaskRecord.outputImages（生成来源）
  ├─ 其他任务的 inputImageIds（衍生依赖）
  ├─ SOP / 策略 / Agent 引用
  └─ 导出时复制到用户目标目录
```

素材记录与任务记录生命周期分离：删除任务不会删除有效素材；素材进入回收站不会立即删除原图；清空回收站时，只有不存在阻断性引用的原图才会被永久删除。

V1 首版只管理 糖包 生成图片，不管理上传图片、视频、音频或任意本地目录。

## 2. 当前架构基线与复用结论

### 2.1 已有能力

| 能力              | 当前实现                                         | V1 处理                                |
| ----------------- | ------------------------------------------------ | -------------------------------------- |
| 图片内容去重      | `src/lib/db.ts` 使用 SHA-256 内容哈希作为图片 ID | 直接复用，素材 ID 与图片 ID 一致       |
| Electron 原图托管 | `<localSavePath>/cache-images`                   | 保留物理目录，V1 不搬迁、不改名        |
| 浏览器图片存储    | IndexedDB `images` store                         | 继续使用                               |
| 缩略图            | IndexedDB `thumbnails`，带版本和回填             | 直接复用                               |
| 图片瀑布流        | `TaskGrid`、`GalleryImageTile`、虚拟化 masonry   | 抽取到素材网格复用                     |
| 任务详情          | `DetailModal`                                    | 保留给生成批次；素材改为非阻断详情面板 |
| 图片查看          | `Lightbox`                                       | 复用并适配素材列表导航                 |
| 搜索筛选          | `SearchBar`、`galleryTaskFilter`                 | 拆成素材查询与批次查询                 |
| 收藏夹            | 基于任务复制的 `FavoriteCollection`              | 迁移为图片级收藏和项目归属             |
| 批量操作          | `selectedTaskIds` + 底部批量栏                   | 图片视角新增独立 `selectedAssetIds`    |
| 本地文件安全      | Electron IPC 路径白名单与真实路径校验            | 继续作为唯一文件操作入口               |
| 备份              | Electron 流式 ZIP、浏览器 ZIP                    | 扩展 manifest 和引用收集               |
| 数据迁移          | IndexedDB schema upgrade + migration journal     | 增加可恢复的素材回填迁移               |

### 2.2 当前必须修正的边界

现有图片回收逻辑将任务、草稿、Agent、SOP 等引用汇总后删除孤立图片。生成结果目前主要依赖任务引用存活，因此：

- 直接删除任务可能删除其最后一份原图。
- 收藏逻辑会复制任务卡，不复制图片文件，但素材归属仍然是任务级。
- 图片视角的选择也是任务级；选择一张图片实际上会选中整张任务卡。
- 备份只收集任务、会话和工作区引用，无法备份“任务已删但素材仍在”的图片。

V1 必须先建立 `GeneratedAsset` 作为新的独立引用源，再修改删除和备份逻辑。不能先改 UI、后补生命周期，否则会出现可见素材被后台清理的问题。

## 3. 范围

### 3.1 V1 必须交付

- 成功生成的图片自动进入素材库。
- “画廊”入口改名为“素材库”。
- “图片 / 生成批次”双视角。
- 全部、最近、收藏、未整理、项目、标签、回收站。
- 图片级搜索、筛选、排序、评分、收藏和多选。
- 项目归类；一张图片可以属于多个项目。
- 手动标签；一张图片可以有多个标签。
- 右侧素材详情面板，展示生成快照和来源关系。
- 一键加入参考图、复用到生成器、进入后期处理、下载、定位文件。
- 图片级回收站、恢复、永久删除和引用冲突提示。
- 任务删除后素材保留。
- 旧任务、旧收藏夹和旧收藏卡迁移。
- 完整备份、导入和旧备份兼容。
- Electron 与浏览器/PWA 的功能降级规则。
- 大量素材下的虚拟化、缩略图加载和查询性能。

### 3.2 明确不进入 V1

- 导入外部图片成为素材。
- 视频、音频、PSD、SVG 等非生成位图。
- AI 自动打标、OCR、视觉语义搜索。
- 向量相似搜索和“找相似图片”。
- 云同步、团队共享、跨设备冲突合并。
- 用户自定义规则构建器式智能集合。
- 重复图片自动删除或自动合并用户元数据。
- 自动清空回收站。
- 监视任意本地目录。
- 对现有 `cache-images` 做物理目录重命名或大规模搬迁。

这些能力可在 V2/V3 建立在稳定素材索引之上，不应阻塞首版。

## 4. 核心术语

| 术语     | 定义                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 原图     | `StoredImage` 管理的图片字节。Electron 为本地文件，浏览器为 IndexedDB 内容 |
| 素材     | `GeneratedAsset`，一张生成图片对应的可管理记录                             |
| 来源     | 某次任务的某个输出位置及其生成快照                                         |
| 生成批次 | 现有 `TaskRecord` 或 SOP 批次，是过程记录，不是素材分类                    |
| 项目     | 用户创建的虚拟集合；不对应物理目录；支持一张素材属于多个项目               |
| 标签     | 用户手动添加的关键词                                                       |
| 未整理   | 没有项目归属且没有用户标签的有效素材                                       |
| 回收站   | 已从普通素材视图移除、但仍保留原图和元数据的素材                           |
| 永久删除 | 删除素材记录并尝试释放原图；存在阻断性引用时拒绝并说明来源                 |
| 衍生关系 | 生成任务使用其他生成素材作为输入时形成的父子关系                           |

## 5. 产品信息架构

```text
素材库
├─ 图片
│  ├─ 全部素材
│  ├─ 最近生成
│  ├─ 收藏
│  ├─ 未整理
│  ├─ 项目
│  │  └─ 用户项目（支持层级）
│  ├─ 标签
│  └─ 回收站
└─ 生成批次
   ├─ 当前工作区标签页
   ├─ 任务卡
   ├─ SOP 批次
   ├─ 运行中 / 完成 / 失败
   └─ 当前任务导航
```

### 5.1 顶级导航

- `Header.tsx` 中“画廊”展示文案改为“素材库”。
- 内部 `AppMode` 暂时继续使用 `'gallery'`，避免无业务价值的大规模重命名。
- 内部 `GalleryViewMode` 暂时继续使用 `'images' | 'tasks'`；显示文案改为“图片 / 生成批次”。
- 新安装默认进入“图片”；已有用户保留本地保存的视图偏好。

### 5.2 桌面布局

图片视角采用三栏工作布局：

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 素材导航      │ 搜索 / 筛选 / 排序 / 视图     │ 素材详情 / 词条   │
│              ├──────────────────────────────┤                  │
│ 全部、最近    │                              │ 大图预览          │
│ 收藏、未整理  │      虚拟化图片瀑布流         │ 项目、标签、评分   │
│ 项目、标签    │                              │ 提示词与参数       │
│ 回收站        │                              │ 来源与操作         │
└──────────────┴──────────────────────────────┴──────────────────┘
                      底部：生成输入 / 素材批量操作
```

生成批次视角继续使用现有结构：

- 左侧为 `WorkspaceTabBar`。
- 中间为任务卡或批次卡。
- 右侧为任务导航 / 词条库。
- 底部为现有生成输入和任务批量操作。

图片视角下：

- 左侧用 `AssetLibrarySidebar` 替代 `WorkspaceTabBar`。
- 右侧边栏优先显示素材详情，并保留“词条”页签。
- 当前生成目标标签页通过输入栏中的“生成到：标签页名称”控件明确展示和切换，避免左侧切换为素材导航后丢失生成上下文。

### 5.3 响应式规则

| 宽度/输入方式 | 布局                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| ≥ 1280px      | 三栏常驻；左右栏均可停靠和调整宽度                                                 |
| 1024–1279px   | 左栏可收起，右侧详情为可停靠窄栏                                                   |
| 768–1023px    | 主区域单栏；素材导航和详情使用左右 Drawer                                          |
| < 768px       | 工具栏分两行；素材导航为全高 Drawer；详情为全屏或底部 Drawer；批量栏替代生成输入栏 |
| 粗指针        | 点击目标至少 44px；不依赖悬停                                                      |

不得让主页面、左栏和右栏同时出现三个互相竞争的滚动容器。桌面端主网格使用页面主滚动；停靠侧栏内部独立滚动。移动端 Drawer 独立滚动并锁定背景。

## 6. 核心用户流程

### 6.1 生成即归档

1. 用户从画廊生成器、Agent、SOP 批量、日程或恢复任务获得成功输出。
2. 图片先按现有逻辑写入 `StoredImage`，得到内容哈希 `imageId`。
3. 任务写入或更新 `outputImages`。
4. 素材同步器按 `imageId` 幂等 upsert `GeneratedAsset`。
5. 素材立即出现在“全部素材”和“未整理”。
6. 若相同内容已存在，不复制原图和素材记录；向现有素材追加新的来源快照。
7. 若该图片曾被永久删除，但本次来源的 `taskFinishedAt ?? taskCreatedAt` 晚于删除墓碑，则视为用户重新生成，恢复为新素材。

生成主流程不能等待缩略图或完整搜索索引生成。素材记录写入后即可完成任务；缩略图和派生元数据后台补齐。

### 6.2 浏览与查找

- 默认按素材首次生成时间倒序。
- 单击选择素材并在右侧打开详情。
- 双击或按 Enter 打开大图预览。
- 空格切换选择；Shift 连选；Ctrl/Cmd 追加选择。
- 框选沿用现有桌面拖拽选择，但选择单位改为 `assetId`。
- 搜索匹配：原始提示词、修订提示词、模型、API 配置名称、项目名称和标签名称。
- 筛选支持：日期、模型/服务商、横竖方向、尺寸区间、评分、收藏、项目、标签、来源模式。
- 排序支持：生成时间、最近整理、评分、宽度、面积。

V1 不对图片像素进行视觉内容分析，搜索结果不得暗示支持语义理解。

### 6.3 整理

- 点击星标切换收藏。
- 评分为 0–5；0 表示未评分。
- “添加到项目”允许多选项目；不会移动或复制物理文件。
- “添加标签”支持搜索已有标签和快速创建。
- 一张素材可属于多个项目和多个标签。
- 从某项目视图执行“从项目移除”只修改归属，不进入回收站。
- “未整理”的严格定义：`collectionIds.length === 0 && tagIds.length === 0`，收藏和评分不改变该状态。

项目支持两级以上层级，但 V1 UI 最多展开到三级，避免侧栏失控。数据模型不限制层级；创建或移动时必须阻止父子循环。

### 6.4 再创作

右侧详情和右键菜单提供：

- **加入参考图**：把当前素材加入当前生成标签页的输入图片。
- **复用到生成器**：恢复来源快照中的提示词和请求参数，并尽可能恢复参考图片；不自动提交任务。
- **查看来源任务**：来源任务存在时切换到“生成批次”、定位任务并打开详情。
- **再次生成**：V1 通过“复用到生成器”完成，避免绕过用户对当前 API 配置和参数的确认。
- **进入后期处理**：将原图送入现有后期处理工作区。
- **下载**：使用来源快照中的稳定文件命名信息；来源任务被删除后仍能得到一致名称。
- **在文件夹中显示**：仅 Electron；定位托管原图文件。

若来源参考图已缺失，“复用到生成器”仍恢复提示词和参数，并明确提示缺失的参考图数量，不静默伪装为完整恢复。

### 6.5 删除生成任务

删除任务时：

- 删除 `TaskRecord` 和任务级状态。
- 不删除其有效或回收站中的 `GeneratedAsset`。
- 素材详情继续展示已保存的来源快照。
- 来源任务入口显示“来源任务已删除”。
- 只有不被素材、其他任务输入、草稿、SOP、策略或 Agent 引用的非素材依赖图片，才可以由 GC 删除。

用户不需要在删除任务时回答“是否保留素材”，因为首版规则固定为保留，降低高频操作风险。

### 6.6 回收站

普通删除执行软删除：

1. `status` 变为 `trashed`。
2. 写入 `trashedAt`。
3. 保留原图、缩略图、项目、标签、评分和来源快照。
4. 普通视图立即移除，回收站可见。
5. Toast 提供短时“撤销”。

恢复时回到删除前项目和标签状态。

清空回收站或永久删除前执行引用分析：

- 来源任务的 `outputImages` 不作为阻断性引用；永久删除成功时同步从所有来源任务输出中移除该 ID，并清理按图片索引的参数映射。
- 其他任务的输入图、遮罩、当前草稿、Agent 输入、SOP 参考图、策略封面/参考图等属于阻断性引用。
- 存在阻断性引用时拒绝永久删除，显示引用类型、名称和数量，并提供跳转入口。
- V1 不提供“强制级联删除所有引用”，避免跨工作区误删。

永久删除成功后，任务需要保留 `purgedOutputSlots?: number[]`，以原始输出槽位表达“这里曾有结果，但已永久删除”；同时清理 `outputImages` 中的活跃图片 ID，避免 UI 破图或引用图继续把它当作现存文件。

执行顺序：

1. 写入 `AssetTombstone`，防止启动回填从旧任务重新创建素材。
2. 从来源任务输出数组和对应映射中移除图片 ID。
3. 删除素材记录。
4. 删除缩略图。
5. 删除 `StoredImage` 元数据。
6. Electron 通过受限 IPC 删除托管原图文件；浏览器删除 IndexedDB 内容。
7. 文件删除失败时记录可重试清理，不回滚已完成的数据库删除，也不把素材重新显示出来。

回收站默认不自动过期。自动清理以后作为显式设置加入，不能在 V1 默默启用。

## 7. 数据模型

### 7.1 GeneratedAsset

```ts
export type AssetStatus = 'active' | 'trashed'
export type AssetRating = 0 | 1 | 2 | 3 | 4 | 5

export interface GeneratedAsset {
  /** 与 StoredImage.id 相同；一份图片内容只有一条素材记录 */
  id: string
  imageId: string
  status: AssetStatus
  createdAt: number
  updatedAt: number
  trashedAt: number | null
  favorite: boolean
  rating: AssetRating
  collectionIds: string[]
  tagIds: string[]
  /** 所有生成来源；相同内容由多个任务产生时不会覆盖 */
  origins: GeneratedAssetOrigin[]
  primaryOriginKey: string | null
  /** 输入中已经是生成素材的图片，用于衍生链 */
  parentAssetIds: string[]
  /** 查询和布局使用的派生媒体信息；原始文件路径仍只存在 StoredImage */
  width?: number
  height?: number
  mimeType?: string
  byteSize?: number
  metadataVersion: number
}
```

约束：

- `id === imageId`。
- `origins` 以 `origin.key` 去重。
- `collectionIds`、`tagIds`、`parentAssetIds` 必须去重且排序稳定。
- `trashedAt` 仅在 `status === 'trashed'` 时非空。
- 更新来源不得覆盖用户收藏、评分、项目、标签和回收站状态。
- 新增来源时 `createdAt` 保留最早来源时间，`updatedAt` 更新。

### 7.2 GeneratedAssetOrigin

```ts
export interface GeneratedAssetOrigin {
  /** `${taskId}:${outputSlot}`；旧任务没有槽位时使用迁移时记录的原始下标 */
  key: string
  taskId: string
  outputSlot: number
  taskCreatedAt: number
  taskFinishedAt: number | null
  sourceMode: 'gallery' | 'agent' | 'schedule' | 'sop' | 'unknown'
  workspaceTabId?: string
  workspaceTabName?: string
  prompt: string
  revisedPrompt?: string
  requestedParams: TaskParams
  actualParams?: Partial<TaskParams>
  apiProvider?: ApiProvider
  apiProfileId?: string
  apiProfileName?: string
  apiMode?: ApiMode
  apiModel?: string
  inputImageIds: string[]
  maskTargetImageId?: string | null
  maskImageId?: string | null
  filenameBatch?: number
  filenameLabel?: string
  generatedFileNameBase?: string
}
```

来源快照不保存 API Key、代理凭据、完整原始响应和其他秘密。`requestedParams` 在写入前经过与任务备份相同的安全清理。

输入图片 ID 的处理：

- 如果输入图片本身是生成素材，写入 `parentAssetIds`。
- 如果输入图片是上传图，它不会出现在素材库，但作为“隐藏依赖”被来源快照引用。
- 隐藏依赖可以保证来源任务被删除后仍可复用；只有最后一个引用释放后才允许 GC。

### 7.3 AssetCollection

```ts
export interface AssetCollection {
  id: string
  name: string
  normalizedName: string
  parentId: string | null
  order: number
  createdAt: number
  updatedAt: number
}
```

- UI 名称为“项目”。
- 仅是虚拟归属，不对应本地目录。
- 同一父级下名称大小写和空白归一化后必须唯一。
- 删除项目默认只移除归属，不删除素材。

### 7.4 AssetTag

```ts
export interface AssetTag {
  id: string
  name: string
  normalizedName: string
  color?: string
  createdAt: number
  updatedAt: number
}
```

标签名称归一化后全局唯一。颜色只能使用设计系统允许的语义色板，不接受任意 CSS 字符串。

### 7.5 AssetTombstone

```ts
export interface AssetTombstone {
  id: string
  imageId: string
  purgedAt: number
  /** 永久删除前已知的最新来源完成时间；任务未完成时回退创建时间 */
  lastOriginOccurredAt: number
}
```

墓碑用途：

- 启动迁移或任务回填遇到旧来源时不重新创建已永久删除素材。
- 同一内容之后被用户重新生成，若新来源的 `taskFinishedAt ?? taskCreatedAt` 晚于 `purgedAt`，允许删除墓碑并重新创建。这样已经在运行、但在清空回收站之后才真正完成的任务也不会被误判为旧来源。
- 墓碑体积极小，备份必须包含。

### 7.6 StoredImage 扩展

可选新增：

```ts
mimeType?: string
byteSize?: number
```

新图在保存时填写；旧图在首次查看详情或后台空闲时惰性回填。不能为了补齐文件大小在启动时同步遍历全部原图。

## 8. IndexedDB 与仓储层

数据库版本从 9 升至 10，新增：

```text
generatedAssets    keyPath: id
assetCollections   keyPath: id
assetTags          keyPath: id
assetTombstones    keyPath: id
```

`generatedAssets` 建议索引：

- `createdAt`
- `updatedAt`
- `status`
- `trashedAt`
- `favorite`
- `rating`
- `collectionIds`，`multiEntry: true`
- `tagIds`，`multiEntry: true`

V1 渲染层不得直接调用 IndexedDB。新增仓储接口：

```ts
getAsset(id)
getAssetsByIds(ids)
listAssets()
putAsset(asset)
upsertAssetFromTask(task, context)
patchAssets(ids, patch)
moveAssetsToTrash(ids, now)
restoreAssets(ids, now)
purgeAssets(ids, referenceGraph)
listCollections()
putCollection(collection)
deleteCollection(id)
listTags()
putTag(tag)
deleteTag(id)
getTombstone(imageId)
putTombstone(tombstone)
```

批量写必须使用单个 IndexedDB transaction，不能对每张图单独打开数据库事务。文件删除必须在数据库提交后执行，沿用现有“数据库为事实、文件清理可重试”规则。

## 9. 素材写入与一致性

### 9.1 同步触发点

所有任务写入继续经过 `src/store.ts` 的 `putTask()` 包装器。任务写成功后，将最新任务投递到一个串行、可合并的素材同步队列：

```text
putTask(task)
  ├─ sanitize + dbPutTask
  └─ enqueueAssetSync(task.id)
       └─ 读取最新 TaskRecord
          └─ 对 outputImages 幂等 upsert
```

同一任务在流式、多图并发和最终参数回填期间会多次更新。队列按 `taskId` 合并，只处理最新快照，避免重复写。

### 9.2 崩溃恢复

任务和素材不强求跨 store 的大事务，因为现有任务完成链路较多。采用双保险：

1. 正常运行时由同步队列实时 upsert。
2. 每次启动在任务恢复完成后执行轻量 reconcile：只检查 `outputImages` 是否存在对应素材或来源 key，不重新读取图片字节。

因此即使应用在“任务写入成功、素材写入前”崩溃，下次启动也会补齐。该过程必须幂等。

### 9.3 相同内容的处理

`imageId` 是内容哈希，因此相同图片只存在一个 `GeneratedAsset`。新的任务输出相同内容时：

- 不新增素材卡片。
- 不复制文件。
- 追加一个来源快照。
- 将最新来源设为可选主来源，但默认仍保留用户已选择的 `primaryOriginKey`。
- 详情面板显示“2 个生成来源”。

## 10. 旧数据迁移

迁移 ID：`generated-asset-library-v1`。

### 10.1 原则

- 加法迁移，不搬动图片文件。
- 不清空旧收藏字段。
- 不在同一版本删除旧收藏影子任务。
- 每批最多处理固定数量任务，记录游标，允许中断恢复。
- 单条失败不删除任务或图片；迁移整体标记失败并给出可重试入口。
- 素材库不可用时仍能进入“生成批次”查看原历史。

### 10.2 回填顺序

1. 等待现有图片文件迁移完成，确保 Electron 原图已经有 `localPath`。
2. 读取并恢复工作区任务归属。
3. 按 `createdAt ASC, id ASC` 分批扫描历史任务。
4. 对每个 `outputImages` 创建或更新素材来源。
5. 根据任务输入关系建立 `parentAssetIds`。
6. 回填宽高；缺失时依赖已有缩略图元数据，不能启动时解码所有原图。
7. 迁移旧收藏。
8. 完成后运行一次引用一致性检查，不执行自动删除。

### 10.3 旧收藏迁移规则

现有收藏可能是任务本身，也可能是“不在任何工作区标签页中的收藏影子任务”。迁移规则：

- 所有旧收藏任务的输出素材设置 `favorite = true`。
- 默认收藏夹只映射为收藏状态，不创建同名项目。
- 非默认收藏夹创建同名项目，并把对应素材加入项目。
- 同名项目冲突时按归一化名称复用，不重复创建。
- 判断为收藏影子任务的记录不追加为新的素材来源，避免详情中出现伪重复来源。
- V1 保留影子任务和旧字段，但新 UI 不再读取它们。
- 后续版本只有在备份、迁移统计和用户数据验证完成后，才可单独提供兼容数据清理。

### 10.4 迁移进度

- 小数据量静默完成。
- 超过 1000 个历史任务时，在设置 → 数据中显示进度。
- 迁移不阻塞生成批次视图。
- 图片视角在迁移中显示“正在建立素材索引”，并逐步展示已完成数据。
- 失败时显示最后成功数量、错误摘要和“重试”，不能只写控制台。

## 11. 查询模型与性能

### 11.1 数据规模目标

| 规模          | 期望                                       |
| ------------- | ------------------------------------------ |
| 0–100         | 即时加载，无明显骨架屏                     |
| 100–5,000     | 常规用户范围；筛选和滚动保持流畅           |
| 5,000–10,000  | 完整支持；只加载可见缩略图                 |
| 10,000–30,000 | 可用；允许短暂查询延迟，不允许加载全部原图 |

### 11.2 内存规则

- 素材 store 只保存元数据，不保存原图 data URL。
- 网格只订阅缩略图；不再像当前 `GalleryImageTile` 一样同时预加载完整原图。
- 完整原图只在大图、详情大预览、复制、下载或拖出时读取。
- 保留现有原图 LRU 缓存和缩略图缓存。
- DOM 仅渲染视口和有限 overscan 项。
- 切换筛选时复用已知宽高，避免瀑布流整体跳动。

### 11.3 V1 搜索策略

V1 不引入全文搜索依赖。加载轻量素材记录后，以 `useDeferredValue` 和纯函数查询：

```ts
queryAssets({
  assets,
  collections,
  tags,
  query,
  scope,
  filters,
  sort,
})
```

搜索字符串执行 Unicode 小写、首尾空白和连续空白归一化。中文按子串匹配。提示词不做分词，不保存不可解释的自动关键词。

若 30,000 条基准显示主线程延迟超过目标，再将同一纯查询函数移动到 Web Worker；V1 不预先建立复杂倒排索引。

## 12. 图片视角详细交互

### 12.1 左侧导航

固定系统入口：

- 全部素材：有效素材总数。
- 最近生成：最近 7 天；日期范围固定，不等于排序。
- 收藏：`favorite === true`。
- 未整理：无项目且无标签。
- 回收站：`status === 'trashed'`。

项目区：

- 新建、重命名、移动、删除。
- 显示包含的素材数量。
- 支持把当前选择添加到项目。
- 删除项目只移除归属，确认文案必须写明“不删除图片”。

标签区：

- 常用标签和全部标签。
- 点击标签筛选。
- 管理入口支持重命名、颜色和删除。
- 删除标签只移除素材关联。

### 12.2 顶部工具栏

左到右：

1. 当前范围名称和数量。
2. 搜索框。
3. 筛选 Popover；有条件时显示数量徽标。
4. 排序菜单。
5. 网格列数 3–6，沿用当前偏好。
6. “图片 / 生成批次”切换。

工具栏在窄屏分两行，搜索占满第一行。筛选条件使用可清除 chips，但最多直接显示 3 个，其余合并为“另有 N 项”，避免工具栏无限增高。

### 12.3 素材卡片

卡片只展示必要信息：

- 图片缩略图。
- 选择状态。
- 收藏状态。
- 评分（仅评分后显示）。
- 多来源标记（来源数 > 1）。
- 回收站状态或引用冲突状态。

默认不在图片上覆盖长提示词、模型名或一排操作按钮。详细信息进入右侧面板；常用操作通过右键菜单和键盘完成。

图片应使用有意义但简洁的 alt：优先用户可读的提示词截断，纯装饰网格重复时可使用空 alt，并由卡片的 `aria-label` 提供完整名称、时间和状态。

### 12.4 选择与批量栏

图片视角使用 `selectedAssetIds`，与现有 `selectedTaskIds` 完全分离。

选择大于 0 时，底部批量操作栏替代生成输入卡，包含：

- 取消选择。
- 全选当前结果。
- 收藏/取消收藏。
- 评分。
- 添加到项目。
- 添加标签。
- 下载。
- 移到回收站；回收站中改为恢复和永久删除。

操作完成后：

- 组织类操作保留选择，便于连续整理。
- 下载保留选择。
- 移到回收站或恢复后清除不可见项的选择。
- Escape 清除选择并恢复生成输入卡。

### 12.5 右侧详情

单选：

- 预览图。
- 收藏和评分。
- 项目和标签。
- 生成时间、尺寸、格式、文件大小。
- 原始提示词和修订提示词。
- 请求参数与实际参数差异。
- 服务商、模型、配置名称。
- 输入参考图缩略图；缺失时显示占位和说明。
- 来源任务、工作区、Agent/SOP 信息。
- 衍生自和衍生结果。
- 加入参考图、复用到生成器、后期处理、下载、文件定位、回收站。

多选：

- 显示选中数量和可合并操作。
- 项目/标签显示三态：全部具有、部分具有、全部没有。
- 不展示某一张素材的提示词和来源。

无选择：

- 显示当前范围统计和快捷整理提示，不留空白面板。

详情面板不是 Modal。浏览下一张素材时保持面板打开，避免反复开关阻断瀑布流筛选。

## 13. 生成批次视角改造

- 保留现有任务卡、SOP 批次卡、状态筛选、失败清理、重试和任务详情。
- 显示文案从“任务”明确为“生成批次”时，不修改底层 Task 类型。
- 当前 `GalleryImageTile` 分支移出 `TaskGrid`，图片视角改由素材仓储驱动。
- 生成批次删除提示改为：“删除生成记录不会删除素材库中的图片”。
- 若永久删除素材导致某任务输出被移除，任务卡显示剩余输出；没有输出时显示“结果已从素材库永久删除”，而不是破图。
- 来源任务定位通过 `galleryNavigateTaskId` 复用现有导航能力。

## 14. 引用图与垃圾回收

新增统一引用图构建器，替代散落在 `store.ts` 中的多份近似逻辑：

```ts
interface ImageReferenceGraph {
  ownersByImageId: Map<string, ImageReference[]>
  outputOriginsByImageId: Map<string, TaskOutputReference[]>
}
```

拥有型引用包括：

- 有效和回收站素材自身的 `imageId`。
- 素材来源快照中的输入图、遮罩图和遮罩目标图。
- 其他任务输入、遮罩和流式诊断图。
- 当前画廊/Agent/工作区草稿。
- Agent 对话输入。
- SOP 批次参考图和 SOP 封面。
- 策略参考图和封面。
- 已知的后期处理、合成和订单工作区持久引用。

非阻断来源引用：

- 任务 `outputImages` 中作为生成结果的那一条关系。

永久删除流程先阻断检查，再在一个业务事务中清理所有非阻断输出映射，最后调用底层图片删除。所有现有 `deleteImageIfUnreferenced`、`deleteUnreferencedImageIds` 和 `getAllOrphanedImageIds` 必须改为使用同一引用图，避免规则漂移。

## 15. 备份与恢复

### 15.1 Manifest

备份版本从 5 升至 6，`ExportData` 增加：

```ts
generatedAssets?: GeneratedAsset[]
assetCollections?: AssetCollection[]
assetTags?: AssetTag[]
assetTombstones?: AssetTombstone[]
```

### 15.2 图片引用收集

备份图片集合必须包括：

- 任务、会话、工作区现有引用。
- 有效和回收站素材原图。
- 素材来源快照的隐藏输入依赖。
- SOP、策略等统一引用图中的拥有型引用。

因此，即使来源任务已被删除，只要素材仍存在，原图仍会进入备份。

### 15.3 导入选择

备份 UI 增加“素材库”选择项：

- 选择素材库自动依赖图片文件。
- 只选任务、不选素材库时，旧行为保持；任务输出可在导入后由回填建立素材。
- 选择素材库、不选任务时，来源快照和原图仍可独立恢复。

### 15.4 合并规则

- 项目按 ID 优先；ID 冲突但名称不同则为导入项目生成新 ID并重映射。
- 标签按归一化名称合并。
- 相同 `assetId`：来源数组取并集；项目和标签取并集；收藏、评分、状态取 `updatedAt` 更新的一方。
- 墓碑仅阻止 `taskCreatedAt <= purgedAt` 的旧来源；新来源可以恢复素材。
- 导入事务失败时不得留下只有元数据没有图片的半成品素材。

旧版本备份没有素材字段时正常导入任务和图片，然后运行素材回填。

## 16. Electron 与浏览器差异

| 功能               | Electron                       | 浏览器/PWA             |
| ------------------ | ------------------------------ | ---------------------- |
| 素材元数据         | IndexedDB                      | IndexedDB              |
| 原图               | `<localSavePath>/cache-images` | IndexedDB `images`     |
| 在文件夹中显示     | 支持                           | 隐藏                   |
| 修改素材存储根目录 | 复用现有本地保存目录迁移       | 不支持                 |
| 大备份             | 主进程流式 ZIP                 | 浏览器 ZIP，受内存限制 |
| 永久删除           | DB 提交后受限 IPC 删除文件     | IndexedDB 删除         |

设置页面将 `cache-images` 对用户展示为“素材原图存储”，但 V1 保持真实目录名，避免一次无价值且高风险的磁盘迁移。

## 17. 异常与边界状态

必须实现：

- 首次空素材库：说明生成成功的图片会自动出现，主操作指向生成输入。
- 搜索无结果：保留当前筛选摘要并提供清除筛选。
- 迁移中：展示进度，不阻塞批次视图。
- 迁移失败：展示可重试错误，不删除旧数据。
- 原图缺失：卡片显示缺失占位；详情给出来源、预期路径和修复建议。
- 缩略图缺失：显示骨架并后台重建，不立即解码全部原图。
- 文件删除失败：素材从 UI 移除，设置页提供“重试清理残留文件”。
- 项目/标签重名：就地提示，不静默合并用户输入。
- 永久删除有引用：列出阻断项，不提供模糊的“操作失败”。
- 来源任务被删除：快照仍可读，定位按钮变为不可用说明。
- 来源 API 配置被删除：显示历史配置名称；复用时使用当前配置并明确提示。
- 多来源：用户可切换查看来源，默认主来源可手动设置。
- 相同图片重新生成：墓碑规则允许新来源恢复。
- 存储空间不足：任务结果写入失败时不得创建指向不存在原图的素材。

## 18. 可访问性与键盘

- 左侧导航使用 `nav`/`NavList`，当前范围有 `aria-current`。
- 网格使用可聚焦卡片，选择状态通过 `aria-selected` 或 `aria-pressed` 暴露。
- 右侧详情标题与当前素材关联。
- 项目和标签三态批量编辑使用原生 checkbox `indeterminate`。
- 所有图标按钮有完整中文名称和 Tooltip。
- 焦点不会因虚拟化滚动突然丢失；移除当前项后移动到相邻项或工具栏。
- Drawer 和 Dialog 锁焦点、Escape 关闭并归还焦点。
- 颜色不是收藏、评分、回收站、选择和错误的唯一表达。
- 尊重 `prefers-reduced-motion`；只保留 120–240ms 状态过渡。
- 快捷键：
  - `Space`：切换当前素材选择。
  - `Enter`：打开大图。
  - `Esc`：清除选择或关闭浮层。
  - `Ctrl/Cmd+A`：在网格聚焦时全选当前结果。
  - `Delete`：移到回收站；回收站中仍需显式确认永久删除。
  - `F`：收藏/取消收藏，输入框聚焦时不触发。
  - `1–5`：评分，输入框聚焦时不触发。

所有快捷键都必须有可见按钮替代。

## 19. 性能与质量门槛

- 网格不得为每张素材加载完整原图。
- 10,000 条素材时 DOM 数量保持在视口项 + overscan 范围。
- 10,000 条轻量元数据的纯查询在常规桌面环境目标小于 150ms；CI 基准允许更宽阈值，主要防止数量级回退。
- 切换范围、项目和标签时不重新生成已有缩略图。
- 批量修改 1000 条素材使用单事务，UI 显示进度或禁用重复提交。
- Electron 清理和备份不把所有原图读入渲染进程。
- 所有新增迁移可重复执行，第二次运行不增加重复来源或项目。
- `npm test` 与 `npm run build` 必须通过。

## 20. 发布与回滚策略

### 20.1 发布阶段

1. 先发布数据层、迁移和生命周期测试，不切换默认 UI。
2. 接入图片视角和详情面板。
3. 接入回收站和备份。
4. 通过真实大库验证后，把顶栏文案改为“素材库”并默认新用户进入图片视角。

可以在同一开发分支完成，但每个阶段都必须保持应用可构建、可启动和旧批次可访问。

### 20.2 回滚能力

- 新 store 是加法结构，旧任务和图片 store 不变。
- V1 不删除旧收藏字段和收藏影子任务。
- 迁移失败可禁用图片视角，生成批次仍工作。
- 不物理重命名 `cache-images`，旧版本仍能读取原图。
- 永久删除属于用户明确动作，不能通过回滚恢复；因此上线前必须完成备份和引用冲突测试。

## 21. V1 验收标准

### 数据与生命周期

- 生成 3 张图后出现 3 个素材记录，重启仍存在。
- 相同图片内容由两个任务产生时，只有一份原图和一条素材，详情有两个来源。
- 删除来源任务后素材、提示词、参数、模型和原图仍存在。
- 删除素材到回收站后可以完整恢复。
- 永久删除无阻断引用素材会删除缩略图和原图。
- 有任务输入、SOP 或策略引用时永久删除被阻止并显示引用。
- 历史任务回填可中断、恢复、重复执行且不重复。
- 旧收藏和非默认收藏夹正确迁移为收藏与项目。

### UI 与工作流

- 顶级入口显示“素材库”，图片/生成批次切换清晰。
- 图片单选、多选、框选、全选和键盘操作都作用于素材而非任务。
- 左栏范围、项目、标签和回收站数量正确。
- 右侧详情可连续浏览，不需要反复关闭 Modal。
- 复用到生成器能恢复提示词和参数，缺失参考图有明确提示。
- 生成批次原有重试、SOP、失败清理和详情能力无回归。
- 移动端可以通过 Drawer 完成导航、详情和批量操作。

### 备份与跨端

- 来源任务已删除的素材仍能被完整备份和恢复。
- 旧版本备份导入后可以回填素材。
- Electron 定位文件、流式备份和安全删除通过路径边界测试。
- 浏览器版本隐藏文件系统专属操作，其余素材管理可用。

### 性能与安全

- 网格滚动不批量解码完整原图。
- 10,000 条素材查询和虚拟滚动达到性能门槛。
- 删除 IPC 不能删除 `cache-images` 外文件，不能跟随符号链接逃逸。
- 备份和来源快照不包含 API Key。

## 22. 后续版本候选

完成 V1 并积累真实素材库后再评估：

- V2：AI 自动标签、重复检测界面、相似图片和可保存智能筛选。
- V2：衍生版本堆叠、对比视图、批量改名、注释。
- V2：把物理目录从 `cache-images` 平滑迁移为正式素材库目录。
- V3：导入外部图片、目录监视、云同步和团队共享。

这些候选不进入 V1 数据迁移承诺，也不应提前增加无使用场景的抽象。
