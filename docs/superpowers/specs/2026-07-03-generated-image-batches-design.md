# Generated Image Batch Filenames Design

## Goal

Add a stable task-card batch number to generated image filenames. A task card is one batch; every image generated by that card keeps the same batch and uses its original one-based image position.

## Filename Policy

The ordered filename parts are:

1. The task's local generation date (`YYYYMMDD`) when date prefixes are enabled.
2. The owning workspace tab name.
3. The task card's stable daily batch number.
4. The task prompt when prompt filenames are enabled.
5. The task card's one-based image sequence.

Examples:

- `20260703-快手-1-1.png`
- `20260703-快手-1-红色海报-1.png`
- `20260703-快手-2-1.png`

Existing filename sanitization, prompt truncation, label fallbacks, and date/prompt settings remain unchanged.

## Batch Assignment

Add an optional persisted batch field to `TaskRecord`.

When a task card is created, assign one plus the largest batch already used by tasks that:

- have the same local generation date; and
- belong to the same workspace tab.

Each workspace tab has an independent daily sequence. The sequence restarts at `1` on the next local calendar date.

The assigned value never changes. Deleting an earlier task does not renumber later tasks, and regenerating or recovering the same task card keeps its batch.

## Existing Tasks

During persisted-state hydration, backfill tasks without a batch in ascending creation-time order within each local-date and workspace-tab group. Preserve every existing valid batch and assign missing values after the largest batch already present in the group.

The backfilled value is persisted with the task so later deletion, restart, download, or recovery cannot renumber it.

Tasks without an owning workspace tab use their existing scheduled-output label fallback as the batch scope.

## Integration

The pure generated-filename module receives the task batch and places it before the optional prompt and final image sequence.

All existing generated-image paths continue using the shared filename builder:

- Electron automatic saving;
- single and multi-image browser downloads;
- selected-task and favorite downloads;
- agent downloads; and
- image names inside ZIP archives.

The final image sequence is the image's original position in the task card. Directory collision protection remains unchanged and does not alter the task batch.

## Verification

Tests must prove:

- images from one task use one batch and consecutive image sequences;
- later task cards in the same tab and local date increment the batch;
- different tabs count independently;
- a new local date restarts at batch `1`;
- deleting an earlier task does not change a persisted later batch;
- prompt-enabled names use `date-label-batch-prompt-image`;
- existing tasks receive deterministic persisted batches; and
- automatic save, download, and ZIP paths use the same result.
