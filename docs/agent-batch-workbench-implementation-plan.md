# Agent 批量任务工作台实施方案

## 1. 目标与结论

将当前“导入文件后直接生成计划”的批量规划弹窗，升级为一个可持续编辑和追踪的批量任务工作台，形成以下闭环：

```text
导入文件 → 字段识别 → 表格审阅/过滤 → 参数编辑 → 应用策略预设
        → 校验与拆解预览 → 保存草稿/计划 → 立即运行或定时运行 → 持续反馈
```

核心判断：当前底层规划器无需推翻。`agentBatchImport.ts`、`agentBatchPlanner.ts`、`agentBatchExecution.ts` 和 `agentBatchQueue.ts` 已覆盖导入、拆解、提交和简单队列。主要缺口在产品交互、持久化和执行可观测性。

本方案建议将现有小弹窗替换为大尺寸工作台；首期仍以本地桌面应用为运行主体，不承诺应用完全退出后继续执行。

## 2. 当前能力与缺口

| 模块     | 已有能力                                          | 主要缺口                                               |
| -------- | ------------------------------------------------- | ------------------------------------------------------ |
| 文件导入 | CSV、JSON；中文表头别名；方向比例/固定数量解析    | 不支持 XLSX；没有字段映射确认；导入成功不明显          |
| 数据审阅 | 导入后只保存为内存中的 `rows`                     | 没有表格、过滤、排序、搜索、编辑、批量修改             |
| 校验     | 规划时检查 SKU、产品、渠道、规格、数量、方向      | 报错合并且只显示第一处；无法定位单元格；没有修复建议   |
| 参数拆解 | 方向分配、有/无文案拆分、冗余、每日限额、输出目录 | 拆解结果只显示按日汇总；无法查看每个方向和提示词       |
| 生成策略 | 行级/方向级 `strategy`，无值时使用默认文本        | 没有策略预设管理、版本、应用范围和覆盖规则             |
| 保存     | 启动队列时写 localStorage 和计划 JSON             | 未运行的编辑草稿无法恢复；一个新队列会覆盖旧队列       |
| 执行     | 首日立即提交；应用运行时按日期自动提交            | 没有明确执行时间；没有持久状态中心；应用关闭语义不清楚 |
| 反馈     | Toast、提交中数量、队列错误                       | 用户不知道何时执行、使用哪个 API、并发多少、保存到哪里 |

## 3. 产品范围

### 3.1 首期必须实现

- CSV、JSON 导入后在应用内形成可编辑表格。
- 自动识别字段并展示识别结果；未识别字段允许手动映射。
- 表格支持搜索、筛选、排序、行选择和批量编辑。
- 自动提取并允许编辑任务参数、方向拆解和生成策略。
- 生成策略可以保存、更新、复制、删除和应用为预设。
- 保存草稿、保存计划、立即执行、按日定时执行四种动作语义清晰。
- 执行前显示确认摘要；执行后提供持久化回执与状态中心。
- 错误精确到“第几行、哪个字段、什么原因”。
- 保持现有 `gpt-image-2`、API Profile、并发配置和图片任务体系不变。

### 3.2 建议第二期实现

- 原生 `.xlsx` 导入和工作表选择。
- 撤销/重做、复制粘贴多单元格、列宽拖动、冻结列。
- 计划导出为 CSV/JSON、重新导入已保存计划。
- 多队列并存、队列优先级、跨日期拖拽调整。
- 失败项一键补跑和仅运行筛选结果。

### 3.3 暂不承诺

- 应用完全退出后仍在后台定时运行。
- 云端调度、跨设备同步、多人协同编辑。
- 飞书双向同步。可在工作台稳定后单独接入。

## 4. 信息架构与页面布局

建议把当前 `AgentBatchPlannerModal` 改为 `AgentBatchWorkbenchModal`，尺寸约为 `96vw × 92vh`，内部采用固定头部、主内容和固定操作栏。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 批量任务工作台   [草稿名] [预设▼] [导入] [保存草稿]       [关闭] │
├─────────────────────────────────────────────────────────────────────┤
│ 数据表 | 拆解预览 | 执行计划 | 运行记录                              │
├─────────────────────────────────────────────────────────────────────┤
│ 搜索  筛选  排序  仅看错误  已选 12 行  [批量编辑] [应用预设]       │
│ ┌──────────────────────── 可编辑表格 ─────────────────────────────┐ │
│ │ 状态 | SKU | 产品 | 渠道 | 规格 | 数量 | 方向 | 策略 | ...     │ │
│ └─────────────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────────────┤
│ 128 行 · 2 行错误 · 目标 1,800 张 · 含冗余 1,980 张 · 预计 2 天    │
│                    [保存计划] [定时运行] [立即运行]                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.1 顶部区域

- 草稿名称：默认使用导入文件名，可编辑。
- 当前文件：显示文件名、路径、导入时间和数据行数。
- 策略预设选择器：显示当前应用的预设及“已修改”状态。
- 导入按钮：支持“替换当前数据”和“追加数据”，追加时先做重复 ID 检查。
- 保存草稿：保存当前表格、字段映射、过滤条件和工作台参数，不启动任务。

### 4.2 主标签页

1. **数据表**：原始任务的审阅、筛选和编辑。
2. **拆解预览**：展示方向、有/无文案、目标数、冗余数、提示词和输出目录。
3. **执行计划**：按日期显示计划批次、预计数量、执行时间和 API 配置。
4. **运行记录**：显示队列状态、提交结果、失败原因和任务入口。

## 5. 导入与字段提取

### 5.1 导入流程

1. 用户选择文件。
2. 解析表头和数据，不立即生成执行计划。
3. 展示“字段识别”步骤：左侧为目标字段，右侧为来源列。
4. 自动匹配高置信字段；有歧义或缺失时要求用户确认。
5. 用户确认映射后进入表格。
6. 对每行执行标准化与完整校验，并显示导入结果摘要。

### 5.2 字段分级

必填字段：

| 字段     | 当前别名                       | 校验             |
| -------- | ------------------------------ | ---------------- |
| SKU      | SKU                            | 非空             |
| 产品     | 产品、产品名称                 | 非空             |
| 渠道     | 渠道                           | 非空             |
| 素材规格 | 素材规格、需求类型、规格、尺寸 | 非空             |
| 数量     | 数量、需求数量、模板数量       | 正整数           |
| 方向     | 方向、创意方向、内容方向       | 至少一个有效方向 |

可选字段：任务 ID、日期、部门、负责人、对接人、生成策略、有文案占比、参考图目录、备注。

### 5.3 字段映射规则

- 自动匹配采用标准化后的精确别名匹配，不做模糊猜测后静默写入。
- 一个来源列默认只能映射到一个目标字段。
- 必填字段未映射时禁止进入可运行状态，但允许进入表格修复。
- 保存用户确认过的表头映射，下次遇到同一组表头时自动复用。
- 导入摘要必须明确显示：成功行、警告行、错误行、忽略行。

### 5.4 错误表达

禁止继续使用：

```text
Task 1 is missing SKU, product, channel, or specification
```

改为：

```text
第 1 行「渠道」为空
第 8 行「数量」必须是大于 0 的整数，当前值为“二十”
第 12 行「方向」格式无法识别，示例：旅游:50%; 美食:30%; 头像:20%
```

错误需要同时出现在：顶部错误计数、行状态、单元格红框和悬停说明中。

## 6. 可编辑表格能力

### 6.1 列设计

默认展示：状态、任务 ID、SKU、产品、渠道、素材规格、数量、方向、生成策略、有文案占比、参考图、备注。

部门、负责人、对接人、日期默认收进“更多列”。用户可控制列显隐。

### 6.2 编辑规则

- 文本字段：单击编辑，失焦或 Enter 提交，Escape 取消。
- 数量：整数输入，输入时显示即时校验。
- 有文案占比：接受 `0–100%`，界面显示百分数，内部保持 `0–1`。
- 方向：使用结构化编辑器，每个方向包含名称、固定数量或权重、策略覆盖、有文案占比覆盖、参考图目录。
- 参考图目录：支持目录选择和手动输入；不存在时显示警告，不立即删除值。
- 生成策略：支持直接编辑或选择预设。
- 修改后行状态变为“已修改”，并重新计算拆解预览。

### 6.3 过滤与批量操作

必须支持：

- 全局关键词搜索：SKU、产品、渠道、方向、负责人。
- 多选筛选：渠道、规格、负责人、部门、状态、是否有参考图。
- 数量范围筛选。
- 仅看错误、仅看已修改、仅看未应用预设。
- 点击列头排序；默认保持源文件顺序。
- 行复选框、全选当前筛选结果。
- 批量设置渠道、规格、生成策略、文案比例、参考图根目录。
- 批量启用/停用行；停用行不进入计划，但保留在草稿中。

首期不建议实现类似 Excel 的任意公式和跨单元格计算，避免扩大范围。

## 7. 参数提取与拆解预览

### 7.1 参数层级

参数优先级从高到低：

```text
方向级覆盖 > 任务行参数 > 当前策略预设 > 工作台默认值
```

每个最终值都要显示来源，例如“来自行数据”“来自预设：应用商店竖图”“默认值”。

### 7.2 自动提取结果

每行导入后应自动得到：

- 基础标识：任务 ID、SKU、产品、渠道、规格。
- 生产数量：目标数量、冗余后数量。
- 方向结构：方向名称、固定数或权重、分配结果。
- 文案结构：有文案数量、无文案数量。
- 生图策略：行级策略或预设策略。
- 参考图规则：明确目录或按根目录/SKU/方向自动拼接。
- 输出路径：输出根目录/SKU/产品/渠道/规格/方向/文案模式。
- 生图参数：API Profile、模型、尺寸、质量、格式、压缩、并发上限。

### 7.3 拆解预览表

拆解预览以 `PlannedBatchUnit` 为粒度，字段包括：

- 来源行和 SKU。
- 方向与文案模式。
- 目标数量、冗余数量、计划数量。
- 执行日期和时间。
- 最终策略和完整提示词。
- 参考图目录。
- 输出目录。
- API Profile、模型和并发配置。

点击拆解项可以回到来源行；修改来源数据后预览自动重新计算。

## 8. 生成策略预设

### 8.1 预设数据结构

```ts
interface AgentBatchStrategyPreset {
  id: string
  name: string
  description?: string
  version: 1
  createdAt: number
  updatedAt: number
  strategyText: string
  defaultCopyRatio: number
  redundancyRate: number
  executionMode: 'balanced' | 'task-first'
  dailyLimit: number
  runTime?: string
  outputPathPattern: string
  referencePathPattern?: string
  apiProfileId?: string
  imageParams: {
    size?: string
    quality?: 'auto' | 'low' | 'medium' | 'high'
    outputFormat?: 'png' | 'jpeg' | 'webp'
    outputCompression?: number
    moderation?: 'auto' | 'low'
  }
}
```

预设不得保存 API Key。预设保存 `apiProfileId`，配置不存在时显示“API 配置已丢失”，运行前要求重新选择。

### 8.2 预设操作

- 新建预设：从当前工作台参数创建。
- 保存为新预设：复制当前预设并命名。
- 更新当前预设：显示变更摘要后覆盖。
- 重命名、复制、删除。
- 导出/导入预设 JSON，方便迁移。
- 应用范围：全部任务、当前筛选结果、已选任务。
- 应用方式：覆盖全部参数、仅填充空值。默认推荐“仅填充空值”，避免覆盖表内明确配置。

### 8.3 路径变量

路径模板建议支持：

```text
{date} {sku} {product} {channel} {specification} {direction} {copyMode}
```

保存预设时默认只保存路径模式，不保存机器相关的绝对输出根目录；用户可以显式勾选“同时保存根目录”。

## 9. 保存、运行与反馈

### 9.1 四个动作

| 动作     | 是否提交 API | 是否持久化 | 行为                                 |
| -------- | ------------ | ---------- | ------------------------------------ |
| 保存草稿 | 否           | 是         | 保存表格、映射、筛选、预设选择和参数 |
| 保存计划 | 否           | 是         | 冻结一份可运行计划和 manifest        |
| 立即运行 | 是           | 是         | 确认后马上创建队列并提交到并发执行器 |
| 定时运行 | 到期后提交   | 是         | 按日期与时间提交；应用必须保持运行   |

### 9.2 执行前确认

点击立即运行或定时运行后，必须出现确认摘要：

```text
计划名称：7 月应用商店素材
有效任务：128 行（忽略 3 行）
目标数量：1,800 张；冗余后：1,980 张
执行方式：2026-07-17 09:30 起，按日执行
每日上限：1,000 张；预计 2 天
API：默认 OpenAI / gpt-image-2
最大并发：5
输出目录：D:\Outputs\...
应用关闭后：暂停，重新打开后等待用户确认补跑
```

存在错误行时禁止执行，并提供“查看 2 个错误”入口。仅有警告时允许执行，但需要在确认摘要中列出。

### 9.3 执行后的回执

执行成功后不能只显示 Toast。应生成持久回执：

- 计划 ID、队列 ID、创建时间。
- 执行模式、首次执行时间、预计结束日期。
- 总批次数、总图片数、已提交数、成功数、失败数、等待数。
- API Profile、模型、并发配置。
- manifest 文件路径和输出根目录。
- “查看运行记录”“暂停队列”“打开输出目录”按钮。

Toast 仅做即时提醒，例如“计划已保存”“队列已启动”；完整信息进入运行记录。

### 9.4 队列状态

建议状态机：

```text
draft → validated → saved → scheduled → submitting → running
                                      ↘ paused
running → completed | partially_failed | failed | cancelled
```

每个状态显示明确中文：草稿、待校验、已保存、等待执行、正在提交、生成中、已暂停、部分失败、完成、失败、已取消。

### 9.5 应用关闭和错过时间

首期采用本地运行语义：

- 应用关闭时不执行 API 请求。
- 重新打开后检测到错过的计划，显示恢复卡片。
- 提供“立即补跑”“跳过本次”“重新安排”三个动作。
- 不应在用户无感知的情况下补交几千张图片。
- 状态中心固定显示“定时任务依赖应用保持运行”。

持久化建议：

- manifest JSON 继续写入输出目录，作为外部可追溯副本。
- 需要定义数据版本和迁移逻辑，保留当前 `tangbao.agent-batch-queue.v1` 的读取兼容。

## 12. 实施阶段

### 阶段 A：导入工作台与可编辑表格

- 建立大尺寸工作台和标签页结构。
- 导入后进入字段映射与数据表。
- 实现单元格编辑、过滤、排序、选择、批量编辑。
- 新增逐字段校验与错误定位。
- 保留现有规划器作为实时预览来源。

验收：导入 500 行 CSV 后可在表格中定位错误、过滤并批量修正；修正后错误计数归零，页面无需重新导入。

### 阶段 B：预设、草稿和拆解预览

- 实现预设管理和应用范围。
- 实现工作台草稿持久化和自动恢复。
- 完善拆解预览、提示词预览、路径预览。
- 增加保存计划与 manifest。

验收：关闭应用再打开，草稿内容和修改状态完整恢复；同一预设可应用到筛选结果，并准确显示参数来源。

### 阶段 C：执行确认、运行记录和多队列

- 执行前确认摘要。
- 多队列状态机和运行回执。
- 明确日期、时间、错过执行和应用关闭语义。
- 支持暂停、恢复、取消、失败项补跑。

验收：用户能从运行记录回答“何时执行、执行多少、使用哪个 API/模型、并发多少、保存在哪里、当前完成多少、为什么失败”。

## 14. 关键产品决策

1. **导入不是运行。** 导入只创建可编辑数据，用户必须明确保存计划或执行。
2. **计划是冻结快照。** 运行后继续修改草稿不会改变正在执行的计划；修改后需创建新版本。
3. **预设不保存密钥。** 只引用 API Profile。
4. **错误行不能运行。** 用户可停用错误行后运行其余有效行，但确认摘要必须显示被忽略数量。
5. **定时执行依赖应用运行。** 首期明确提示，不伪装成系统后台服务。
6. **反馈必须持久化。** Toast 只做即时提醒，状态和回执必须可再次查看。
7. **先做数据正确性，再做 Excel 体验。** 首期聚焦可靠的导入、编辑、规划和执行闭环，不扩展任意公式能力。

## 15. 完成定义

该功能完成时，用户无需查看原始 CSV，也能在应用内完成以下任务：

- 看见导入了哪些行、识别了哪些字段、哪里有错误。
- 过滤、排序、编辑并批量修改参数。
- 查看每行如何被拆成方向、文案模式、数量和执行日期。
- 保存并复用生成策略预设。
- 保存草稿或冻结计划。
- 在运行前明确知道何时运行、如何运行、使用哪个模型和并发配置。
- 在运行后持续看到提交、生成、完成和失败状态，并能定位输出目录和失败原因。
