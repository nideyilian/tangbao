# SOP 管理中心 · 功能规格说明书（可复用）

> 本文档从 糖包 的「SOP 管理中心」模块中提取全部功能，并抽象为**与实现无关**的能力规格，
> 供其它程序（Web / 桌面 / 后端服务 / 移动端）按同一套产品能力进行复刻或对接。
> 文中所有「SOP」均指 _标准作业程序（Standard Operating Procedure）_：一套可直接交给 AI/模型执行的、
> 结构化的系统指令（正文为 Markdown）。

---

## 1. 定位与范围

SOP 管理中心是一个**模态工作台**，统一负责三类对象的全生命周期管理：

| 对象                             | 中文名                    | 作用                                        |
| -------------------------------- | ------------------------- | ------------------------------------------- |
| SOP 库（SopLibraryItem）         | SOP / 标准作业程序        | 用户可执行、可复用、可检查的指令正文        |
| SOP 分组（SopGroup）             | 分组                      | 对 SOP 进行归类                             |
| 生成元指令（SopMetaInstruction） | 元指令 / Meta Instruction | 控制「AI 如何把输入编译成一份 SOP」的提示词 |

它由三个并列页签组成，页面顶部为通用头部（标题 + 大屏模式开关 + 关闭按钮）：

1. **SOP 库（Library）** —— SOP 与分组的管理、编辑、应用、封面、历史生成结果查看。
2. **生成元指令（Meta）** —— 元指令的编辑与 AI 优化。
3. **智能生成（Generate）** —— 用「元指令 + 说明/样本 + 参考图」生成新 SOP 并入库，附完整生成记录。

### 1.1 范围边界

- **本规格覆盖**：SOP 库、分组、元指令、SOP 文本编辑器、AI 对话优化、封面选择、SOP 智能生成、生成记录。
- **不覆盖（关联但独立）**：画廊内的「SOP 批量生图」（`sopPromptBatch` / 素材库批次视图）、
  策略工作台（`StrategyEditor`）、SOP 预设选择器（`SopPresetPickerModal`）。它们消费本中心产出的 SOP，但不属于本中心。

## 2. 数据模型

> 字段以「逻辑契约」描述，不绑定任何数据库；`createdAt/updatedAt` 均为毫秒时间戳。

### 2.1 SopGroup —— SOP 分组

| 字段                      | 类型    | 必填 | 说明                                                                           |
| ------------------------- | ------- | ---- | ------------------------------------------------------------------------------ |
| `id`                      | string  | ✅   | 唯一标识                                                                       |
| `name`                    | string  | ✅   | 分组名称                                                                       |
| `parentId`                | string? | —    | 父分组 id；缺省 / `null` = 根级。分组树据此逐级展开与收起                      |
| `collectionId`            | string? | —    | 关联的项目文件夹 id；由项目树镜像而来才有，缺省 = 用户自建或历史遗留的独立分组 |
| `createdAt` / `updatedAt` | number  | ✅   | 创建 / 更新时间                                                                |

> 分组树是素材库「项目」文件夹树的**投影**，项目文件夹树是唯一主源；同步规则见 §4.1.4。

### 2.2 SopLibraryItem —— SOP 条目

| 字段                      | 类型     | 必填 | 说明                                                                      |
| ------------------------- | -------- | ---- | ------------------------------------------------------------------------- |
| `id`                      | string   | ✅   | 唯一标识                                                                  |
| `groupId`                 | string?  | —    | 所属分组；缺省 = 未分组                                                   |
| `coverImageId`            | string?  | —    | 封面图 id                                                                 |
| `name`                    | string   | ✅   | SOP 名称（标题）                                                          |
| `description`             | string   | ✅   | 一到两句话说明用途、输入、产出                                            |
| `content`                 | string   | ✅   | SOP 正文（Markdown，可直接作为系统指令）                                  |
| `source`                  | enum     | ✅   | `manual`（手工）/ `generated`（AI 生成）/ `legacy-preset`（历史预设迁移） |
| `metaInstructionId`       | string?  | —    | 生成时使用的元指令 id（来源追溯）                                         |
| `createdBy`               | string   | ✅   | 创建者 id                                                                 |
| `createdAt` / `updatedAt` | number   | ✅   | 创建 / 更新时间                                                           |
| `favorite`                | boolean? | —    | 是否收藏                                                                  |
| `lastUsedAt`              | number?  | —    | 最近使用时间，用于「最近使用」视图排序                                    |

### 2.3 SopMetaInstruction —— 生成元指令

| 字段                      | 类型   | 必填 | 说明                               |
| ------------------------- | ------ | ---- | ---------------------------------- |
| `id`                      | string | ✅   | 唯一标识                           |
| `name`                    | string | ✅   | 名称                               |
| `description`             | string | ✅   | 说明                               |
| `instruction`             | string | ✅   | 元指令正文（控制 AI 如何编译 SOP） |
| `kind`                    | enum   | ✅   | 见下表                             |
| `createdAt` / `updatedAt` | number | ✅   | 创建 / 更新时间                    |

`kind` 取值及含义：

| kind             | 中文           | 行为约束                                                |
| ---------------- | -------------- | ------------------------------------------------------- |
| `general`        | 通用 SOP       | 文字需求 + 参考图 → 通用执行 SOP                        |
| `image-prompt`   | 图片提示词 SOP | 至少需要 1 张画风参考图；产出多变体中文提示词直出型 SOP |
| `prompt-reverse` | 提示词反推 SOP | 需要粘贴成品提示词样本；从样本反推可复用 SOP            |
| `custom`         | 自定义         | 用户自定义元指令，生成行为由元指令决定                  |

### 2.4 SopGenerationRecord —— SOP 生成记录（不可变审计）

| 字段                      | 类型    | 说明                                                                   |
| ------------------------- | ------- | ---------------------------------------------------------------------- |
| `id`                      | string  | 唯一标识                                                               |
| `status`                  | enum    | `running` / `success` / `error`                                        |
| `createdAt` / `updatedAt` | number  | 创建 / 更新时间                                                        |
| `elapsedMs`               | number? | 生成耗时（毫秒）                                                       |
| `metaInstruction`         | object  | 生成时使用的元指令完整快照（`{id,name,description,instruction,kind}`） |
| `targetGroup`             | object? | 目标分组快照（`{id,name}`）                                            |
| `brief`                   | string  | 生成说明 / 样本提示词原文                                              |
| `referenceImages`         | array   | 参考图快照（`{id,name,dataUrl}`）                                      |
| `result`                  | object? | 成功结果（`{id,name,description,content}`）                            |
| `error`                   | string? | 失败原因                                                               |

### 2.5 SopReferenceImage —— 参考图（生成输入）

| 字段      | 类型   | 说明                        |
| --------- | ------ | --------------------------- |
| `id`      | string | 引用内唯一标识              |
| `name`    | string | 文件名 / 素材来源名         |
| `dataUrl` | string | 图片数据（base64 Data URL） |

### 2.6 SopBatchSnapshot —— 「生成提示词」视图数据（只读）

用于在编辑器里查看「某 SOP 历史上生成过哪些提示词集」，核心字段：

- `id` / `title?` / `tags?` / `createdAt`
- `sop`: `{id,name,description,content}`（生成时 SOP 快照）
- `brief`：生成提示词时的要求
- `prompts[]`：`{id, text, origin('ai'|'manual'), edited, deleted?}`（仅展示 `deleted !== true` 的条目）

## 3. 全局行为与通用交互

以下行为横跨三个页签，属于中心级约束。

### 3.1 模态与大屏模式

- 整个中心是一个**模态对话框**（`role=dialog` + `aria-modal`），点击遮罩背景关闭。
- 提供「大屏模式」开关：在普通尺寸与 `80vw × 80vh` 之间切换；**选择持久化**（本地存储键 `tangbao.sop-management-modal-mode`），下次打开自动恢复。

### 3.2 未保存修改保护（脏检测）

- 编辑器的「脏状态」由以下字段与已持久化值比对判定：`name`、`description`、`content`、`groupId`、`coverImageId`。
- 在以下**破坏性/切换性**动作前，若存在未保存修改：
  - 若修改合法 → **先立即保存**再继续；
  - 若修改非法（名称或正文为空）→ 弹出确认框「放弃未保存的修改？」（`tone: warning`），用户确认放弃后继续。
- 这些动作包括：切换页签（除切回「SOP 库」）、切换选中 SOP、切换分组、关闭中心、应用等。

### 3.3 自动保存

- 对 **SOP 正文/参数** 的合法修改采用 **防抖自动保存**：默认延迟 **800ms**。
- 自动保存状态机：`idle`（无修改）→ `pending`（等待防抖）→ `saved`（已保存）→ `blocked`（名称或正文为空，阻止保存）。
- 编辑提示文案随状态实时变化，并通过 `aria-live` 播报，例如：
  - `修改将在 1 秒内自动保存，并更新当前使用的 SOP。`（应用中的 SOP）
  - `名称和正文不能为空，当前修改尚未保存。`
  - `当前 SOP 已使用。` / `无需编辑即可直接应用。`
- 手动保存（`保存修改` 按钮或 `Ctrl/Cmd + S`）会**立即冲刷**未落地的防抖保存并落地。

### 3.4 键盘快捷键

| 快捷键                                        | 作用                  |
| --------------------------------------------- | --------------------- |
| `Ctrl/Cmd + S`                                | 立即保存当前 SOP 草稿 |
| `Enter`（分组创建框 / 分组重命名框）          | 提交                  |
| `Escape`（分组重命名 / 全屏编辑 / AI 对话框） | 取消 / 退出           |
| `Ctrl/Cmd + F`（正文编辑器内）                | 聚焦「查找正文」      |

### 3.5 删除保护

所有不可逆删除（分组 / SOP / 元指令 / AI 对话记录）均需二次确认：

- 删除分组：提示「组内 SOP 会转为未分组」（`tone: danger`）。
- 删除 SOP / 元指令：提示「将永久删除「X」」（`tone: danger`）。

### 3.6 应用（把 SOP 接入当前生图）

- 「应用」动作：将当前 SOP 标记为「使用中」，写入 `lastUsedAt`，回调外部 `onApply`，并选中该 SOP。
- 应用语义与编辑语义分离：**应用的是已持久化的 SOP**，编辑中的草稿不会自动应用；存在脏修改时「应用 SOP」按钮禁用。
- 已应用的 SOP 在列表中显示「使用中」徽标，按钮态变为「已使用」；提供「取消应用」入口（外部传入 `onClear` 且存在已应用 SOP 时显示）。

## 4. 页签一：SOP 库（Library）

布局为**三栏**：左「分组侧栏」+ 中「SOP 列表」+ 右「编辑器」。

### 4.1 分组侧栏

**4.1.1 创建分组**

- 输入框 + 「新增分组」按钮；`Enter` 快速创建。
- 名称为空时默认命名「新建分组」；创建后**自动选中并进入内联重命名态**。

**4.1.2 智能视图（内置筛选，带计数）**

| 视图     | 规则                                         |
| -------- | -------------------------------------------- |
| 全部 SOP | 所有条目                                     |
| 收藏     | `favorite === true`                          |
| 最近使用 | 有 `lastUsedAt` 的条目，按 `lastUsedAt` 降序 |
| 未分组   | `groupId` 为空                               |

**4.1.3 用户分组操作**

- **选中**：点击分组名切换筛选。
- **重命名**：点击铅笔进入内联编辑；`Enter`/失焦提交，`Escape` 取消；空名不提交。
- **复制分组**：复制一个分组（外部提供 `onDuplicateGroup`，返回新分组 id）。
- **删除分组**：二次确认后删除，组内 SOP 转为未分组。

**4.1.4 分组树与项目文件夹的同步**

分组以 `parentId` 组织成树：每行按层级缩进，有子分组时渲染展开/收起箭头；折叠状态存在
localStorage `tangbao.sop-group-collapsed`，与素材库侧栏的折叠偏好互不影响。

它与素材库「项目」文件夹树保持一一对应，规则如下：

| 操作              | 行为                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------ |
| 项目文件夹 → 分组 | 新建 / 改名 / 移动后自动镜像：按 `collectionId` 匹配既有分组，缺失则补建（幂等、只增不删） |
| 分组 → 项目文件夹 | 新建分组 = 在当前分组绑定的文件夹下建子文件夹；重命名、删除同步回主源（项目树才是主源）    |
| 删除              | 分组与其项目文件夹一并移入素材库回收站（可恢复），组内 SOP 转为未分组                      |

- **只增不删**：项目文件夹进回收站后，对应分组与组内 SOP 原样保留、不掉进「未分组」；文件夹从回收站恢复时会自动重新接上（靠 `collectionId`，不按名称匹配）。
- **独立分组**：无 `collectionId` 的用户自建分组不受镜像影响；仅**根级**出现同名时会被认领绑定，避免同一层级出现两份同名。
- **选中父分组**：SOP 列表会连同各级子分组里的条目一起显示，否则点开产品线会看到空列表。
- **内置结构**：首次启动会写入内置的「产品线 - 产品 - 方向」三级项目结构（3 条产品线 / 13 个产品 / 61 个方向，定义在 `src/lib/builtinProjectTree.ts`），并镜像成同名分组树。该结构**只在首次启动写入一次** —— 用户删除、改名、移动之后不会被自动重建（避免出现「删不干净、每次启动又冒出来」）；需要找回时到「设置 → 素材库维护 → 补齐内置项目结构」显式补回，该操作只补当前缺失项，不改写既有内容。

### 4.2 SOP 列表

- 标题显示当前筛选结果数量；「新建」按钮创建 SOP。
- **搜索**：按 `名称 + 正文` 做大小写不敏感匹配（实时过滤）。
- **行信息**：
  - 封面缩略图（无封面时显示名称首字）；
  - 名称；
  - 所属分组名 + 「使用中」徽标（当前应用的 SOP）。
- **行内操作**（悬停/常驻图标按钮）：
  1. **收藏/取消收藏**（星标，实心 = 已收藏）；
  2. **应用**（仅当外部传入 `onApply` 时显示）；
  3. **复制 SOP**（外部 `onDuplicateItem`，成功后选中新副本）；
  4. **删除 SOP**（二次确认）。
- 空态：`当前分组暂无 SOP`。

### 4.3 SOP 编辑器（右侧）

**4.3.1 顶部动作**

| 动作       | 触发条件                            | 说明                          |
| ---------- | ----------------------------------- | ----------------------------- |
| 应用 SOP   | 已持久化且无脏修改、未应用          | 应用当前 SOP                  |
| 保存修改   | 有脏修改且名称/正文非空             | 立即保存                      |
| 生成提示词 | 已持久化                            | 打开历史提示词查看（见 §4.5） |
| 取消应用   | 外部提供 `onClear` 且存在已应用 SOP | 取消当前应用                  |

**4.3.2 字段**

- `名称`（文本输入）
- `所属分组`（下拉：未分组 + 所有分组）

**4.3.3 SOP 正文编辑器（见 §6）**：完整的 Markdown 文本编辑器 + AI 工具。

### 4.4 封面选择器（Cover Picker）

- **入口**：双击 SOP 列表中的封面缩略图（辅助说明「双击选择封面」）。
- **候选来源**：该 SOP 通过批量生图产生的所有输出图
  （筛选规则：`task.sopBatch.sopId === 该SOP.id` 且任务有 `outputImages`，按任务时间降序去重）。
- **展示**：网格缩略图，标注「提示词 N · 图 M」；当前封面高亮打勾。
- **操作**：
  - 点击候选 → 设为封面（写入草稿，**保存后生效**）；
  - 「移除当前封面」→ 清空封面。
- **空态**：提示「先使用该 SOP 完成一次生图，再双击封面选择生成结果」。

### 4.5 「生成提示词」历史查看

- 点击「生成提示词」打开对话框，读取该 SOP 关联的全部 `SopBatchSnapshot`，按时间降序。
- 每条快照展示：标题、时间、所有未删除提示词（带序号）。
- 每条提示词提供「复制」按钮（剪贴板）。

## 5. 页签二：生成元指令（Meta）

布局为**两栏**：左「元指令列表」+ 右「编辑器」。

### 5.1 元指令列表

- 标题 + 数量说明「控制 AI 如何编译 SOP」；「新建」按钮。
- 每行：名称 + 说明（空则「暂无说明」）。
- 行操作：**复制元指令**、**删除元指令**（二次确认）。

### 5.2 元指令编辑器

- 提示文案：`重命名或修改后，新生成任务立即使用最新内容。`
- 字段：
  - `名称`
  - `类型`（下拉：通用 SOP / 图片提示词 SOP / 提示词反推 SOP / 自定义）
  - `说明`（文本域）
  - `元指令正文`（等宽字体文本域，占满剩余高度）
- 顶部动作：**AI 对话**（打开元指令优化对话）、**保存**（名称或正文为空时禁用）。

### 5.3 元指令 AI 优化

复用 AI 修订对话面板（§7），但目标为 `meta-instruction`：

- 起始建议语针对「输出漂移 / 输入分析 / 约束保留 / 失败处理」等元指令问题；
- 提案动作集为「复制」「应用到元指令」（无「测试生图」「另存为新版」）；
- 应用后仅回填编辑器，**仍需手动点「保存」** 才持久化。

### 5.4 内置元指令（种子数据）

系统预置并自动补齐以下元指令（缺失时合并注入，用户可复制/删除）：

| id 语义          | 名称                                        | kind             |
| ---------------- | ------------------------------------------- | ---------------- |
| 通用编译器       | SOP 智能编译器（文字 / 图片转标准作业程序） | `general`        |
| 反推编译器       | 提示词反推 SOP 编译器                       | `prompt-reverse` |
| 画风多变体编译器 | 图片画风多变体 SOP 编译器                   | `image-prompt`   |
| 生图策略提取 ×2  | extract-image-generation-strategies         | `image-prompt`   |

## 6. SOP 正文编辑器（SopTextEditor）

内嵌于 SOP 编辑器，是一个面向 Markdown 的增强文本编辑器。

### 6.1 顶部

- 标题「SOP 正文」+ 副说明「支持 Markdown 结构与快捷编辑」。
- **全屏编辑**开关（展开/收起；`Escape` 退出全屏）。

### 6.2 快速整理（本地规则，非 AI）

| 工具     | 作用                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 自动分段 | 把纯文本按句子合并、按目标长度（约 150 字符）拆分段落，保留标题/列表/代码块等结构行           |
| 统一格式 | 规范标题空格、列表符（`• → -`）、编号（`1. / 1、 → 1. `）、行尾空格、多余空行；代码块内不处理 |
| 清理粘贴 | 统一换行符、去除零宽字符/软连字符、NBSP 转空格、去行尾空格、压缩 3+ 空行为 2 个               |

> 三者均为**可撤销**的本地变换；结果不变时提示「无需调整」。

### 6.3 AI 工具（Agent，需 OpenAI 兼容配置）

| 操作                   | 说明                             |
| ---------------------- | -------------------------------- |
| AI 结构化（structure） | 重写为更稳定、可执行的结构化 SOP |
| AI 精简（concise）     | 压缩重复、精简表达，保留约束     |
| AI 检查（audit）       | 输出检查报告，**不改写正文**     |

- 执行前校验：正文非空 + Agent 配置完整 + Provider 为 OpenAI 兼容；否则提示并 toast。
- 结果以**预览面板**呈现（不直接替换），提供：
  - **测试生图**（可选，仅非 audit 且有 `onTestRevision`）；
  - **复制结果**；
  - **替换正文**（非 audit；应用后可撤销）。
- 请求支持取消（AbortController）；切换文档时中止进行中的请求。
- 工具条显示当前 Agent 模型名。

### 6.4 格式工具栏

- **撤销 / 重做**（历史栈上限 100 步）。
- **标题（#）/ 项目列表（-）/ 引用（>）/ 代码块（```）**：作用于当前选中行或选中文本。
- **查找**：输入关键词，实时显示「N 处 / x/N / 无匹配」；「下一个」从光标处循环定位并高亮。
- **自动换行**开关（默认开）。
- **复制正文**。

### 6.5 状态栏

- 左侧：`N 行 · M 字符`。
- 右侧：动态状态（复制成功 / 换行状态 / 查找定位 / 整理结果提示）。

## 7. AI 修订对话面板（SopAiRevisionPanel）

用于「SOP 正文」和「生成元指令」的多轮 AI 优化，是**持久会话**。

### 7.1 会话持久化

- 以 `documentId`（SOP id 或 `meta-instruction:{id}`）为键，**本地存储**（localStorage），保留最近 **30 条**消息。
- 关闭对话框/切换对象后重新打开，历史对话与提案**自动恢复**。

### 7.2 起始建议（空会话时展示 3 条可点击建议）

- SOP 目标：诊断执行稳定性 / 重组减重 / 优化生图一致性；
- 元指令目标：诊断输出漂移 / 强化输入分析与约束 / 检查歧义与失败处理。

### 7.3 消息与提案

- 每条助手消息携带一个**完整修订提案**：`{ content, changeSummary[] }`。
- 展示：变更摘要列表 + 可折叠的完整正文（`查看完整 SOP / 元指令 · N 字符`）。

### 7.4 提案动作

| 动作                      | 适用目标 | 说明                                                                  |
| ------------------------- | -------- | --------------------------------------------------------------------- |
| 测试生图                  | SOP      | 用提案内容发起一次实际生图验证（外部 `onTestRevision`）               |
| 复制                      | 两者     | 复制提案正文                                                          |
| 另存为新版                | SOP      | 把提案存为新 SOP（自动命名「原名称（新版）/（新版 N）」），不覆盖当前 |
| 应用到正文 / 应用到元指令 | 两者     | 把提案写入编辑器（SOP 可撤销；元指令需再点保存）                      |

- 已应用的提案标记「已应用于 HH:mm」，可「再次应用」。

### 7.5 后台执行与重试

- 请求以**后台任务**运行：关闭面板不中断，结果完成后回填。
- 失败时显示错误 + **重试**按钮；可**清空对话记录**（二次确认，正文不受影响）。

### 7.6 输入

- 文本域：`Enter` 发送、`Shift+Enter` 换行、上限 4000 字符。
- 加载中禁用输入与发送。

## 8. 页签三：智能生成（Generate）

布局为**两栏固定（无滚动）**：左「生成表单」+ 右「状态/记录」。

### 8.1 生成表单

**8.1.1 模式**

- 根据所选元指令的 `kind` 动态切换标题与表单：
  - `prompt-reverse` → 标题「从提示词反推 SOP」；
  - 其它 → 标题「生成新 SOP」。

**8.1.2 表单字段**

| 字段                            | 说明                                    |
| ------------------------------- | --------------------------------------- |
| 生成元指令（下拉）              | 必选；决定生成模式                      |
| 保存到分组（下拉）              | 可选（未分组）                          |
| 生成说明 / 样本提示词（文本域） | `prompt-reverse` 时标签为「样本提示词」 |
| 参考图片                        | `prompt-reverse` 模式**隐藏**；否则显示 |

**8.1.3 参考图片输入**

- 上限 **8 张**，单张 ≤ **10 MiB**，仅接受图片文件。
- 三种添加方式：
  1. **点击选择**（文件选择器，多选）；
  2. **拖拽**到投放区（隔离的 dropzone，阻止全局图片输入误触）；
  3. **从素材库选择**（打开素材选择弹窗，`selectionLimit = 剩余名额`，自动去重已存在图片）。
- 缩略图带序号标签「图 N」与「移除」按钮；提供「清空」。
- 计数实时显示 `已添加 N / 8`。

**8.1.4 提交**

- 按钮文案随状态变化：`开始生成并保存` / `开始反推并保存` / `正在生成 SOP` / `正在反推 SOP`（加载态）。

### 8.2 生成前校验（阻止提交并给出错误）

| 场景                      | 错误提示                              |
| ------------------------- | ------------------------------------- |
| 未选元指令                | 请选择一个 SOP 生成元指令             |
| `image-prompt` 且无参考图 | 图片生成 SOP 至少需要一张画风参考图片 |
| `prompt-reverse` 且无样本 | 请粘贴至少一条完整的提示词样本        |
| 无说明且无参考图          | 请填写生成说明或添加参考图片          |

### 8.3 生成流程（五步 + 修复）

固定步骤及含义（进度条与步骤列表均按此推进）：

| 步骤 | 阶段 id    | 说明                                         |
| ---- | ---------- | -------------------------------------------- |
| 1    | `validate` | 校验生成条件（元指令、说明、参考图）         |
| 2    | `prepare`  | 整理参考输入（按顺序标记并组织参考图）       |
| 3    | `request`  | 调用 AI 编译 SOP（分析共同规律、差异与约束） |
| 4    | `parse`    | 校验生成结构（名称、说明、完整正文）         |
| 5    | `save`     | 保存到 SOP 库                                |

- 额外的 `repair` 阶段映射到「校验生成结构」步骤（自动修复不完整返回）。
- 进度条按「当前步骤序号 + 0.5 / 总步数」估算百分比；成功固定 100%。
- 运行中实时显示已运行秒数。

### 8.4 生成结果处理

- 成功后：
  - 生成 `SopLibraryItem`（`source: 'generated'`、记录 `metaInstructionId`、`createdBy`），写入目标分组；
  - 自动**选中该分组并选中新 SOP**；
  - 状态面板显示 `SOP「X」生成并保存成功`，提供「查看生成结果」跳转到 SOP 库。
- 失败后：展示友好错误（AI 返回不完整时给出「已自动尝试修复，请重试或切换模型/简化元指令」），提供「重新生成」。

### 8.5 生成记录（历史）

- **写入时机**：生成开始时写入 `running` 记录；结束（成功/失败）更新为终态并记录 `elapsedMs`、`result` 或 `error`。
- **持久化**：独立存储（`getAllSopGenerationRecords / putSopGenerationRecord`），跨会话保留。
- **列表**：状态图标（运行中/成功/失败）+ 结果名（或元指令名）+ 说明摘要（或参考图数量）+ 时间；**分页，每页 4 条**（上一页/下一页）。
- **详情覆盖层**：完整展示「生成说明、参考图片（含缩略图）、完整元指令、完整 SOP 正文、失败原因」。

## 9. SOP 编译契约（供后端/AI 对接复用）

### 9.1 生成接口签名（逻辑层）

```
GenerateSop(
  description: string,                       // 生成说明或样本提示词
  context: { product?; materialType?; generationMode? },  // 业务上下文
  referenceImages?: SopReferenceImage[],     // 参考图
  kind?: 'general' | 'image-prompt' | 'prompt-reverse',
  metaInstruction?: string,                  // 自定义元指令（覆盖默认）
  options?: { onProgress?; signal? }         // 进度回调 / 取消
) => Promise<{ name: string; description: string; sop: string }>
```

### 9.2 默认输出契约

AI 必须只返回一个合法 JSON（无 Markdown 代码围栏、无解释）：

```json
{
  "name": "专业、清晰、可识别用途的 SOP 名称",
  "description": "一到两句话说明该 SOP 的用途、输入和产出",
  "sop": "完整 SOP 正文，使用 Markdown 标题和编号组织，可直接作为系统指令"
}
```

### 9.3 结果解析与容错

解析器按以下优先级容错：

1. 剥离代码围栏 → 定位首个 `{"` → 截取到最后一个 `}` → `JSON.parse`；
2. 兼容 `result` / `data` / `output` 包裹层；
3. 兼容 `sop` / `content` / `instruction` / `body` 等字段名；
4. JSON 缺失时回退到「结构化文本识别」（识别 Markdown 标题 / 编号列表 / 生图策略列表）提取名称；
5. 均失败 → 报错「AI 返回内容无法识别为 SOP，请重试或切换文本模型」。

## 10. 复用建议（对接其它程序的要点）

1. **对象三件套**：把「SOP / 分组 / 元指令」作为一等实体，SOP 通过 `groupId` 挂靠分组，通过 `metaInstructionId` 追溯来源。
2. **应用与编辑解耦**：`lastUsedAt` 表示「是否正在使用」，编辑草稿独立于已持久化内容，避免误改正在使用的 SOP。
3. **自动保存 + 脏检测**：正文类长文本务必做防抖自动保存（约 800ms）与「名称/正文非空」校验；切换/关闭前冲刷或确认。
4. **生成记录作为审计快照**：记录必须完整保存「输入（说明+参考图）+ 元指令 + 结果/失败」，不引用可变实体。
5. **AI 优化采用「提案-确认」模式**：任何 AI 改写先预览，经「测试 → 应用/另存」才落地，且会话可持久化、可后台运行、可清空。
6. **参考图约束**：上限 8 张、单张 10 MiB、仅图片、去重、支持拖拽与素材库两种来源。
7. **内置元指令需可合并补齐**：预置元指令在缺失时自动注入，避免升级后功能退化。
8. **无障碍与状态**：进度、错误、编辑提示均通过 `aria-live` / `role=alert` / `role=progressbar` 对外播报。
