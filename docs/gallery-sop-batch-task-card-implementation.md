# 画廊 SOP 批量生图：单任务卡片实现文档

## 1. 目标

当用户在画廊中选择 SOP 并生成多条提示词后，底层仍按每条提示词独立提交、独立执行生图任务；但任务列表将这些同一批次的任务聚合为一张 SOP 批量任务卡片。

用户可以在该卡片中查看批次进度、结果缩略图和失败状态。点击任一结果图片后，打开该图片对应的现有详情弹窗，并展示该图片实际使用的完整提示词、参数、输出和错误信息。

本方案的核心是“执行任务不合并，展示任务合并”。这样无需改变当前并发、重试、取消和图生图/文生图调用链。

## 2. 现状与问题定位

当前链路已经为每条 SOP 提示词写入同一批次元数据：

- `GallerySopBatchModal.tsx` 为每一次提交写入相同的 `sopBatch.batchId`，并记录 `sopName`、`promptIndex` 与 `promptCount`。
- `TaskRecord` 已定义 `sopBatch` 字段。
- `TaskGrid.tsx` 目前将 `TaskRecord` 平铺后逐条渲染 `TaskCard`，因此同一个 SOP 批次会显示为多张任务卡片。
- `DetailModal.tsx` 已按任务 ID 读取任务，并展示 `task.prompt`；这是显示“图片对应具体提示词”的可复用能力。

问题只在任务列表的展示层：已有的批次关联没有被用于分组渲染。

## 3. 设计原则

1. 不修改 `submitTaskWithData` 的单任务执行模型；每条提示词仍可独立排队、失败、重试和恢复。
2. 不新增持久化的“父任务”记录；批量卡片是由已有子任务实时计算出的视图模型，避免数据迁移和父子状态同步问题。
3. 只聚合同一工作区、同一 `sopBatch.batchId` 的任务；普通任务和未带 `sopBatch` 的历史任务保持原样。
4. 图片详情始终指向真实子任务 ID，确保展示的是该图片的准确提示词，而不是批次摘要或其他图片的提示词。
5. 收藏视图保留按单张图片管理的语义，不进行强制聚合，避免“只收藏批次中一张图片”时产生歧义。

## 4. 交互方案

### 4.1 任务列表

同一 SOP 批次仅显示一张卡片，卡片内容包括：

- SOP 名称与“批量任务”标识。
- 进度摘要，例如“已完成 6/10，失败 1，生成中 3”。
- 最多 4 张结果拼贴缩略图；有更多结果时显示“+N”。
- 统一的队列、生成中、部分失败、完成状态。
- “查看全部”入口。

卡片中的可见缩略图可直接点击；“查看全部”打开批次详情面板。

### 4.2 批次详情面板

批次详情面板按 `promptIndex` 排序展示全部子任务。每一项显示：

- 图片缩略图或生成中/失败占位状态。
- 提示词序号与任务状态。
- 一行提示词摘要。
- 成功图片可点击，点击后关闭批次详情面板并打开现有 `DetailModal`。

`DetailModal` 中的“提示词”字段即为该图片实际提交的 `task.prompt`，无需复制或重新维护提示词数据。

### 4.3 操作边界

- 批量卡片的删除操作会明确提示“删除该批次全部 N 个任务”，确认后逐个调用现有删除能力。
- “复用参数”“编辑输出”“收藏”等单图操作放在批次详情的具体图片项中，避免对多个不同提示词做不明确的批量操作。
- 批量卡片的主点击行为为打开批次详情，不直接打开某一张图片详情。
- 拖拽框选与多选按批次作为一个视觉单元；选中批次时映射为选中其全部子任务 ID，确保批量删除等既有能力仍正确作用于真实任务。

## 5. 视图模型与状态计算

新增纯函数，将任务列表转换为可渲染的展示项：

```ts
type TaskGridItem =
  | { kind: 'task'; task: TaskRecord }
  | {
      kind: 'sop-batch'
      id: string
      batchId: string
      sopName: string
      tasks: TaskRecord[]
      createdAt: number
      summary: {
        total: number
        queued: number
        running: number
        completed: number
        failed: number
      }
    }
```

分组键为：`workspaceTabId + ':' + sopBatch.batchId`。同批任务按 `sopBatch.promptIndex` 升序排列；缺少序号的历史数据按创建时间排序。

批次显示状态规则：

| 条件 | 批次状态 |
| --- | --- |
| 存在排队或运行中的子任务 | 生成中 |
| 全部成功 | 已完成 |
| 全部失败或取消 | 失败 |
| 同时存在成功与失败，且没有运行中任务 | 部分完成 |

搜索、状态筛选应基于子任务集合计算：只要一个子任务匹配搜索词或状态筛选，批次卡片就应保留；卡片内需展示匹配结果数，避免用户误以为筛选失效。

| 文件 | 改动 |

| `src/lib/sopBatchTaskGrouping.ts`（新增） | 任务分组、排序、状态汇总、筛选映射等纯函数。 |

| `src/components/TaskGrid.tsx` | 使用展示项而非平铺任务渲染；接入批量卡片、批次详情打开、选择映射与批量删除确认。 |
| `src/components/SopBatchTaskCard.tsx`（新增） | 渲染单张聚合卡片、拼贴缩略图、进度与失败状态。 |

## 7. 实施步骤

1. 编写任务分组工具与单元测试，先锁定同批聚合、排序和状态汇总规则。
2. 开发 `SopBatchTaskCard`，使用固定高度的缩略图拼贴，避免破坏当前 `TaskGrid` 的虚拟滚动行高。
3. 开发 `SopBatchDetailModal`，复用任务图片缓存与状态展示；所有图片点击都设置真实子任务 ID。
4. 将 `TaskGrid` 替换为“普通任务 / SOP 批次”混合渲染，并接入搜索、状态筛选、删除和多选映射。
5. 回归普通生图、收藏视图、失败重试、历史 SOP 批次、文生图 SOP 与参考图 SOP。

## 8. 验收标准

1. 一次 SOP 批量提交 10 条提示词后，常规任务列表只出现 1 张 SOP 批量任务卡片。
2. 卡片准确显示 10 个子任务的完成、运行和失败数量。
3. 卡片与批次详情中的任意成功图片均可打开对应详情，并显示该图片自己的完整提示词。
4. 批次中某条任务失败，不影响其他图片展示；卡片显示部分失败，失败项可继续使用现有重试能力。
5. 普通任务、旧任务、非 SOP 批次任务与收藏视图的行为不变。
6. 删除批次卡片会删除其全部子任务，且确认文案包含受影响数量。
7. `npm.cmd test -- --run` 与 `npm.cmd run build` 通过。

## 9. 风险与控制

- 批次卡片不能直接作为持久化任务 ID 使用；所有操作必须映射回子任务 ID。
- 当前网格使用固定行高虚拟滚动，因此卡片只展示有限缩略图；完整列表放入批次详情面板，避免滚动定位错位。
- 同一批次的图片可能在不同时间完成，聚合状态必须从子任务实时计算，不能缓存为一次性状态。
- 已收藏单图的批次不在收藏模式下聚合，以保持单图收藏、编辑和删除语义明确。
