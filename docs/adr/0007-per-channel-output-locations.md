# 0007 导出位置分「全局渠道表 + 节点覆盖」两层，单渠道最多两个位置（双写）

- **日期**：2026-09-19
- **状态**：生效中
- **决策者**：杰哥（产品负责人）

## 背景

杰哥的原话：「当前导出位置只能设置一个全局总路径，无法满足我的需求。请修改导出位置相关逻辑，
使其支持按渠道单独配置导出位置，并允许单个渠道设置一个甚至两个导出路径，同时保留或明确兼容
原有的全局默认位置。」

三个事实决定了这次不能只加一个输入框：

1. 「按渠道的目录」**早就存在**，但只藏在「项目树 → 节点 → 参数 → 按渠道分别设置」里
   （`ProjectNodeParamsDialog`）。全局面板上确实只有一个「输出目录」。
2. 已按《输出位置明细》导入了 **80 处** `byMedia[m].outputDir`（挂在项目节点上，见
   `docs/output-location-import-2026-09-18.md`）。删掉节点级这一层就等于让这批数据失效。
3. 杰哥确认了两件事：第二个位置是**双写**（两个位置各存一份），渠道级配置放在**全局**一层、
   节点仍可覆盖。

## 决策

### 一、逐渠道解析出「位置列表」，而不是一个字符串

- 归一化后的权威字段是 `Record<媒体 id, string[]>`，上限 `MAX_POSTPROCESS_OUTPUT_DIRS = 2`。
- 全局层：`PostprocessMediaConfig.mediaOutputDirs`（新增，后处理设置里的「按渠道设置导出位置」）。
- 节点层：`PostprocessMediaOverride.outputDirs`（新增），与旧的单值 `outputDir` 并存，
  **`outputDirs` 优先**（旧的单值读得到、折成 `[值]`，已导入的 80 处行为不变）。
- 写盘侧只认**一个**读口：`resolvePostprocessOutputDirs(config, mediaId)`。
  `applyPostprocessOverride` 负责把节点覆盖与全局渠道表折进 `mediaOutputDirs[mediaId]`，
  所以写盘处不需要知道继承链。

**生效顺序（逐渠道）**：节点渠道 → 节点通用 → 全局渠道 → 全局默认 → 本地保存目录 `postprocess`。

**为什么不把上限放开**（明确的取舍）：位置数是**写盘放大**（文件数 × 位置数），
放开后一次误配就能把磁盘写满；两个已经覆盖「本地留档 + 共享盘交付」这个真实场景。

**为什么「节点通用」优先于「全局渠道表」**：这是既有口径的延续（改前是
`byMedia > 节点通用 > 全局 outputDir`），插入全局渠道表时把它放在「全局默认」之前、
「节点通用」之后——保持**节点比全局更具体**这条线一致，而不是让同一层里两个维度互相越级。
代价写在 RISK R-34：填了节点通用值就会盖住渠道表，所以渠道行的占位提示必须显示**实际继承到的**位置。

### 二、双写：渲染一次，写多个位置

- `renderVariant` 只调用一次，多份写盘复用同一份 `dataUrl`。体积压缩是逐档试编码，
  按位置重渲染会让耗时整倍翻。
- 第二个位置沿用第一个位置定下的**文件名**（含撞名后缀），两处看起来才是同一个东西。
- 产出记录只登记**主位置**：清单回答的是「产出了哪些变体」，第二份是同一张图，
  登记进去只会让「产出 N 个文件」翻倍。
- 分发（按天排期）两个位置都要排，否则第二处会漏下没排的文件。

### 三、配了位置却不可用时**跳过**，不降级本地

`outputRoots.ts` 的三条口径：

- 一个位置都没配 → 用默认输出位置（老行为，兼容）；
- 配了但**全部**不可用 → 跳过这一桶 + 提示。**刻意不写本地**：用户以为交付进了共享盘、
  文件其实留在本机，是这套流程里最坏的一种错；
- 配了两个只有一个可用 → 写可用的那个并报「有 N 个位置不可用」（保产物优先）。

## 被否决的方案

- **把导出位置收成唯一一处（退役节点级）**：要一次性迁移 80 处已导入配置，且失去
  「某方向个别渠道不同」的表达能力。杰哥已确认保留节点覆盖。
- **每个渠道放开任意多个位置**：缺少真实用例，且是写盘放大。
- **第二个位置做「主备回退」而不是双写**：杰哥确认要双写（两个位置都要有文件）。
- **把命名模板的 `{token}` 本身改成中文**：模板是**落盘格式**，改了会让所有已配好的模板与
  已产出文件的命名口径失效。改为**按钮显示中文名、插入仍是 `{token}`**（占位符进 tooltip）。

## 影响与代价

- 命名模板插入从「追加到末尾」改为「插在光标处」。光标位置必须记在 ref 里：
  点按钮时输入框已失焦，现读 `selectionStart` 会被浏览器归零 → 症状是「不管点哪儿都插到开头」
  （RISK R-36）。
- 新增两个共用组件（`ChannelOutputDirs` / `NamePatternField`）：全局层与节点层的交互必须
  一模一样，否则「全局能配两个、节点只能配一个」会让节点一覆盖就把双写吃掉。
- 无 schema 变更、无落盘格式破坏：`mediaOutputDirs` 缺失即按空表处理，旧库升级后行为不变。
