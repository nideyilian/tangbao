# 架构决策记录（ADR）

> **本文件是唯一的决策记录载体。** 回答"为什么不那么做"。
> 一条决策一个文件，**只增不改**：决策变了就新开一条，并标注取代关系。
> 目的：把散落在工作日志「三问定案」表格里的决策沉淀下来 —— 日志会被压缩，决策不该被压缩掉。

## 为什么需要它

这个项目的决策密度极高（一个功能一天内可能有 3–5 个语义拍板），但决策依据原先只存在于日志里。
日志为了控制体量会被反复压缩（曾一天压缩 4 次），**过程与理由是最先被丢的部分**，
而"为什么这么定"恰恰是几个月后最需要的信息。

## 新增 ADR 的模板

```markdown
# NNNN <一句话决策>

- **日期**：YYYY-MM-DD
- **状态**：提议 | 生效中 | 已被 NNNN 取代
- **决策者**：杰哥（产品负责人）

## 背景

（要解决什么问题，附证据位置。不写过程叙事，只写约束与事实。）

## 决策

（一句话说清"定了什么"。）

## 理由

（为什么这么定，而不是另一个方案。至少给出被否决的方案与它被否决的原因。）

## 后果

- 正面：
- 代价 / 知情取舍：
- 对后续代码的约束：
```

## 什么时候必须写

- 两个以上合理方案之间做了取舍
- 定了一条**语义**（例如"空数组代表什么"）
- 决定了"不做"某件事（`DROPPED` 的需求必须指向一条 ADR）
- 引入了长期约束（数据模型、持久化、跨模块接口）

**不需要写**：纯实现细节、bug 修复、能靠代码自解释的改动。
