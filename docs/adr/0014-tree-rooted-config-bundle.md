# 0014 配置包以项目树为骨架（配置同步）

- **日期**：2026-09-22
- **状态**：**生效中**（包结构与导出/导入已实现；配置中心入口见 TB-086）
- **决策者**：杰哥（产品负责人）
- **相关**：[0001](0001-unified-project-tree.md)（统一项目树）、[0012](0012-watermark-library-per-product.md)
  （水印库按产品隔离）、[0013](0013-participation-follows-direction.md)、TB-086
- **字段级规范**：[`config-spec.md`](../config-spec.md)（**唯一真相源**，已重设计到 v9 / TB-100）。
  本文只记「为什么这么定」；包里每个字段的类型、默认值、必填选填与取值范围，一律查规范。

## 背景：杰哥提的（原话链）

> 「为什么没有将我的配置一起发布？」→「那个是固定资产啊」→「中控台」→
> 「所有数据都跟着树来走，树就是根」→「那你这样对应的文档结构就要改变了，按照刚才所说的重新整理」

起因是发布 v0.3.2 时发现：**中控台那套配置（树 / 每个方向的参数 / 水印库 / 渠道与尺寸）
一个都不随版本走**。查下去发现比"发布不带"更严重 —— **导出/导入本身就不全**：

- `ExportData`（v7）里，树结构（`assetCollections`）、水印库（`compositeState`）、
  渠道与尺寸（`postprocessMediaState`）是**三块并排**；
- 而**挂在节点上的 `projectTreeParams` 压根没进包**。

于是把包拿到另一台机器恢复，得到的是「树在、水印在、渠道在，但**谁挂谁全断了**」——
固定资产搬了一半，且丢得没声。

## 一、树是根：包的第一层就是树

```
配置包 v8
└ 全局默认（根节点）：渠道与尺寸字典、默认输出位置、命名模板、分发排期
   └ 产品线
       └ 产品：水印库（按 productId 归属，含 LOGO 图）
           └ 方向：渠道选择、输出位置、命名、是否参与产出
```

- **渠道与尺寸的字典放根节点**（全局一份），节点只写"我用哪几个渠道"。
  这与 [0010](0010-param-center-scope-correction.md) 的裁决一致：渠道**规格**是全局维度，
  「这个方向投哪几个」才是方向维度（[0013](0013-participation-follows-direction.md)）。
- **水印库挂在 `productId` 指向的那个节点下**，判据是"有没有水印挂在它下面"，
  **不看层级标记** —— 这样自建节点也能当库主（呼应 [0012](0012-watermark-library-per-product.md)）。

## 二、恢复顺序不可交换

**立树 → 灌每个节点的参数 → 放水印库 → 挂渠道与输出位置。**

顺序反了会出现「引用了不存在的水印 / 渠道」—— 引用关系是字符串，写的时候不校验，
出问题要到产出那一刻才炸，这类错误极难自查。

## 三、没归属的水印必须单列一区

`productId` 缺省（老数据）或指向一个已删除的产品时，按产品分组的循环会**漏掉它们**。
漏掉 = 静默丢配置，用户只会觉得"水印少了几套"却查不出为什么。
包里为此留 `unassignedWatermarks`；回收站里的节点同理 —— 不导出，但**报个数**（`trashedSkipped`），
否则"我明明 80 个方向，怎么只过去 74 个"会成为下一个报障。

## 四、树跟着「配置」走，不再挂在「素材」下

此前 `assetCollections` 只在勾了「包含素材库元数据」时才进包。按"树是根"，
**树属于配置**：勾「包含配置」就该带树，且**不该顺带把我的素材索引（`generatedAssets`）发出去**
—— 那只会让别人的素材库里多出一堆指不到的条目。

## 五、过渡期双写（老版本不静默归零）

v8 包里**同时**写 `treeConfig`（新）与 `compositeState` / `postprocessMediaState` /
`assetCollections`（旧）。原因很实际：还在用 ≤0.3.2 的同事，**不认识** `treeConfig`，
只写新字段会让老版本导入后**静默什么都不恢复**。全员升级后才可删那几行。

## 六、同步语义：单向覆盖 + 拉取前备份

- 发布出来的文件名带时间戳（`tangbao-config-YYYYMMDD-HHmmss.zip`），**字典序即时间序** ——
  拉取方不用猜哪份最新，也不靠机器时钟比大小。
- 拉取方以包为准（同 id 覆盖）；**拉取前先把本机配置备份一份，备份失败就直接中止** ——
  不做没有退路的覆盖。备份放**本机**的 `backups/`，不放共享盘（那是自己的历史配置）。
- 包内**不含 API Key**（默认排除）：放共享盘等于所有能看到那个盘的人都能拿到密钥。

## 七、未决

- **本地独有的节点（包里有、对方自建）保留还是删掉**？当前实现是**保留**：
  彻底替换会把对方自建的方向、连同挂在上面的素材一起变成孤儿，而换来的只是"树长得更一致"。
  要"完全一致"需再加一个显式开关（默认关）。
- 配置目录要**持久化放行**（主进程路径白名单，见 R-31 / R-62）：它多半是内网共享盘的 UNC 路径。

## 后果

- 配置第一次真正可以"整套搬走"：树、每个方向的参数、水印库（含 LOGO 图）、渠道与尺寸。
- 中控台那几块配置的**家是树**，因此任何新增的配置维度都要先回答"它挂在哪一层"，
  不能再平铺进包里。
- `ExportData.version` 7 → 8；v7 及更早的备份仍能导入（走老字段那条路）。
