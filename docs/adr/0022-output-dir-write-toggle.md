# 0022 导出位置开关：位置配置保留，临时不写

- **日期**：2026-09-24
- **状态**：**生效中（已实现）**
- **决策者**：杰哥（产品负责人）
- **相关**：TB-130；补充 [0007](0007-per-channel-output-locations.md)、[0013](0013-participation-follows-direction.md)；`src/lib/postprocessMedia.ts`、`src/features/postprocess/outputRoots.ts`

---

## 背景

杰哥 2026-09-24 的需求原话：

> 为后处理流程的每个导出位置添加一个启用开关，用于在保留导出位置配置的前提下，临时停用某个渠道
> 或该渠道下某个特定的导出位置而不删除它。要求：该开关仅在该导出位置已填写输出位置或存在可继承
> 位置时才可启用；关闭开关时跳过对应的导出操作，重新开启后恢复原有导出行为。默认都是开启的。

要解决的问题是**交付目录会临时不可用**（共享盘维护、某个盘要整理、这批不想往那边写），
而现在的唯一手段是**删掉那个位置**：删了以后路径配置就没了，恢复时要重新用「选择目录」找回
（共享盘路径手输不在主进程白名单里，选不出来就填不回去）。

## 决策

### 1. 开关**不做进位置元素**，另存一份「路径 → 开/关」的表

位置列表保持 `string[]` 不动，开关存为 `PostprocessOutputDirEnabledMap = Record<路径, boolean>`
（挂在 `mediaOutputDirs` 旁边：全局 `mediaOutputDirEnabled[mediaId]`、节点
`PostprocessMediaOverride.outputDirEnabled`）。

**为什么不做成 `{ path, enabled }[]`**：位置列表的继承口径是**整份覆盖**（某一层声明了就盖住下面
所有层）。开关塞进元素，就要求「本级只声明第 3 处的开关、不定第 1/2 处」这种**逐槽位继承** ——
那会改掉存量行为：「本级填一处」现在只写一处，改完会变成「本级那处 + 继承的所有处」，
一次升级就让所有多写一份文件。分家之后，位置列表一个字不改，开关另走一份表。

键用**路径**而不是下标：位置可以删（后面的往上顶），下标会串位；路径是这一处的天然主键，
且界面上那一格显示的就是它。代价是路径改名时记录要跟着搬（`renameOutputDirEnabledKey`）——
不搬的话用户改完路径，那处会「忘记自己关过」。

### 2. 逐层**逐键浅合并**，不是整份替换

`applyPostprocessOverride` 里：`{ ...浅一层, ...本层 }`。

整份替换的后果：全局停了「共享盘」，某个方向只想再停「本地留档」，一写就把全局那条抹掉 ——
共享盘又恢复写了，而用户以为全局的停用还在。

三个取值缺一不可：缺键 = 没表态（沿用浅一层，整条链都没有就是开）；`false` = 停用；
**`true` = 明确启用**，用来盖掉浅一层的 `false`（「全局把它关了，这个方向还是想用」）。
少了 `true` 这一档，用户在本级点开一个被上级停用的开关会**没反应** —— 静默失效。

### 3. 列名是「写入」，不是「启用」

这张表里已经有一个渠道级开关（「参与产出」）。再来一列叫「启用」会让人以为是同一个东西的
两种说法 —— ADR-0013 删掉渠道级 `enabled` 正是因为这个。两者语义必须能一句话分开：

| 开关 | 关掉之后 |
| --- | --- |
| 参与产出（渠道级） | 这个渠道**不产出变体**（连渲染都不做） |
| 写入（位置级） | 变体照产出，只是**不落到这一处** |

### 4. 「配了位置但全停」必须与「一处都没配」分开判

`resolveBucketOutputRoots` 里两条分支**看起来都是空数组，意思正相反**：

- 一处都没配 ⇒ 用默认输出位置（老行为）；
- 配了但全被停用 ⇒ **一处都不写**，报 `PP-DIR-005`（severity `skipped`，不是故障）。

合在一起的话，「把交付目录全关掉」会变成**悄悄写到本地默认位置** —— 用户以为停掉了、
其实写了，而且他会照着「已经关了」的判断去安排后面的动作。

配套：报 `PP-DIR-003`（部分位置不可用）时分母用**过滤后**的数量。

### 5. 继承来的位置也能**逐处**开关（杰哥 2026-09-24 选定的口径）

本级留空、跟着上一级时，表格**按能继承到的位置数铺行**（而不是只铺一行）。只铺一行的后果是
「停了继承来的第一处、第二处还在写」这种状态根本显示不出来 —— 开关会变成撒谎。

`planPostprocessOutputDirSlots` 是两个入口（中控台大表、后处理弹窗按渠道表）共用的唯一实现：
行数与「哪一格能开关」是同一条规则，两处各写一遍迟早分叉。

**不对称（刻意的）**：全局作用域留空那行**不给**开关。全局层停掉兜底位置等于「这个渠道不产出」，
而这件事归「参与产出」管，别造第二个入口说了算。节点作用域则给：那行的落点是「上级配置」，
停它是**方向级**的决策（「这个方向先别写出去」），没有等价的替代入口。

### 6. 哪些位置能开关

配置里**写明了路径**的那些（本级填的、或从上级继承来的具体路径）。两处**不给**：

- 还没填路径的空格（没有作用对象）；
- 程序兜底的「本地保存目录下的 `postprocess`」—— 它的路径是运行期解析出来的，
  开关表里不可能有它（用户想「这个渠道别产出」，该关「参与产出」）。

### 7. Excel 往返不加开关列

`console_workbook` 的 `output_dirs_global` / `output_dirs_node` **不导出开关**，导入时
**保留**既有记录（`setMediaOutputDirs` 按还在的位置过滤，而不是「清空 + 逐个写」——
后者会把记录一起清掉，等于把用户停用的交付目录重新打开，且一声不响）。

开关是「这一处这一轮写不写」的临时状态，不是位置配置；塞进格子会让「导出 → 改 → 导入」
把它固化或误清，而用户改 Excel 时多半没意识到自己在动交付开关。
**配置包**（`treeConfigBundle`）则相反，必须带上：它是整份配置的搬家，漏了就少一处状态。

## 为什么不那么做

- **不加渠道级启停**：ADR-0013 已裁过 —— 与「参与产出」对产出完全等价。渠道级停用 =
  把它每个位置的开关都关掉即可，不需要第二个概念。
- **不把 `enabled` 塞进 `mediaOutputDirs` 的元素**：见决策 1（逐槽位继承会改存量行为）。
- **不给「默认输出位置」本身加全局开关**：它是所有渠道共用的兜底，挂在某个渠道那行上会让人
  以为是「只停了这个渠道」；而它真正要表达的「这个渠道不投」是「参与产出」的事。
- **不给开关单独做一份「停用清单」**（而不是三态表）：纯并集无法表达「本级重新启用」，
  点开没反应属于最坏的一类静默失效。

## 影响面

- `lib/postprocessMedia.ts`：类型 + 归一化 + 合并 + `isOutputDirEnabled` + 改名的搬运 + `planPostprocessOutputDirSlots`；
- `storePostprocessMedia.ts`：归一化、`setMediaOutputDirEnabled`、`setMediaOutputDirs`（替换掉
  `clearMediaOutputDirs` + 逐个写那个会清掉记录的组合）、快照深拷贝、`partialize`；
- `postprocess/outputRoots.ts` + `postprocessIssue.ts`（新码 `PP-DIR-005`）；
- 两个表格入口（`ConsoleMediaTables` / `ChannelOutputDirs`）与两个调用方；
- `treeConfigBundle`（配置包带开关）；Excel 两张表刻意不带。

**落盘版本不动**（`tangbao-postprocess-media` 保持 v4）：纯新增字段，缺键 = 一处都没停用 =
旧行为，没有需要折算的旧语义。但 `partialize` 白名单必须加 —— 漏了就是「点完开关当场生效、
重启全变回开」，界面上不报任何错。
