# 0002 水印归属由参数层 `watermarkPresetIds` 单点决定，预设组概念退役

- **日期**：2026-09-18
- **状态**：生效中
- **决策者**：杰哥（产品负责人）

## 背景

杰哥原话：「我需要将水印归属设计成同时覆盖现有的预设和预设组，采用一套统一的树状结构，
将项目树状文件夹完全打通……**重点降低用户的理解成本**。」

诊断结论：这**不是"缺一棵水印树"，而是"缺一个把两条线合起来的模型"**。

- `PostprocessNodeOverride.watermarkPresetIds`（`lib/postprocessMedia.ts:207`）**一直是**
  「某方向用哪些水印」的唯一真相，但它只在项目树节点的"参数"弹窗里能配，水印工作区完全不知道这件事。
- `presetGroups`（预设组）全仓只有 **7 处引用**，只服务左栏水印库的筛选，与"哪个方向用哪些水印"
  **零关系**。
- 两条不相交的线 → "这版水印是给谁用的"只能靠脑子记。
- 另有第三处覆盖源：后处理弹窗自己有一份"勾选水印预设"（写全局 `watermarkPresetIds`），
  与项目树参数层那份**是两条能互相矛盾的线**。

## 决策

1. **归属值只认参数层的 `watermarkPresetIds`**（数组，不是水印 store）。
2. **取消"预设组"这个概念** —— 分组交给项目树本身。
3. **后处理弹窗不再自己存水印**，改为**只读**展示按归属算出的结果。
4. 树上的一切都是项目树的投影；左栏取消组列表，并进库里（三段 → 两段）。

杰哥三问定案：`| 预设组的定位 | 取消这个概念 | | 树的层级管理 | 统一由项目树管 | | 左栏结构 | 取消组列表，并进库里 |`

## 理由

- 归属值一直在参数层，水印侧看不见 —— **把两条线接起来比新造一个模型便宜得多**。
- "组"的唯一不可替代能力是"一次绑一组"，这个能力可以用**水印库多选 + 批量绑定**保住
  （`librarySelection` + `bindPresetsToNode`，逐个走 `bindPresetToNode` 以保住**顺序即产出顺序**）。
- 保留"组"就要回答"组归属与预设归属谁优先"，那是一层推理负担 —— 与"降低理解成本"直接冲突。

**被否决的方案**：① 「预设组 = 可归属集合」；② 「项目下挂容器」。
否决原因：都在原有两条线上再加一层，用户仍要理解三层关系。

## 后果

- **正面**：用户只需理解"树 + 绑定"；预览条数与实际产出**严格一致**
  （水印是"项目 × 媒体 × 尺寸 × 预设"四维之一，必须逐媒体算）。
- **代价 / 知情取舍**：
  1. **`undefined`（继承）与 `[]`（显式不加水印）在树上不再可区分**，只剩「恢复继承」出口的有无。
     要看逐方向生效明细走后处理面板的「水印归属」区块。
  2. **继承态下第一次改动必须"物化"**：直接写结果数组会把"少一个"表达成"一个都不要"，
     必须取**生效值**做增删再写回。
  3. `deletePreset` **刻意不清理引用**（预设 id 不存在时跳过整桶，不静默降级）。
- **对后续代码的约束**：
  - 判据一律 `=== undefined`，**不能用 `length`**（空数组是有效值）。
  - `overridden` 不能用 `sourcedFrom === collectionId` 判定 —— 两边都是 `null`（图片无归属）会误判。
  - 归属树（`PresetProjectTree`）**只做一件事**：不挂任何标注标签，不订阅 `selectedCollectionIds`
    （启用范围是后处理的配置，挂上去会让树看起来像归属失效）。
  - 「按渠道」是**动作**不是注释，用图标而非 chip；有渠道分叉时点亮 `ds-accent`。

**证据**：`PresetProjectTree.tsx`、`features/composite/lib/presetBinding.ts`、`params.ts` 的
`resolveNodeWatermarkBinding`、`storeV2` 落盘 v4 → v5（丢弃式）、commit `4aa04dc` / `31f1ad6`。
