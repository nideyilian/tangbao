# 0006 水印标识符全局单点渲染时叠加；预设导出用路径名带归属

- **日期**：2026-09-19
- **状态**：生效中
- **决策者**：杰哥（产品负责人）

## 背景

杰哥两个需求：

1. 「提供一个专门的标识符输入位置……所有带文字的水印按设置附加；没有文字水印的自动在左下角
   添加；位置可设置且对所有相关水印即时生效。」
2. 「支持将水印预设导出为文件、从文件导入恢复，**要带树状归属的信息**。」

难点不在功能本身，而在**这两件事各有一个"看起来更直接但会埋雷"的实现**：

- 标识符最直接的写法是「改预设的文字图层」——但那要改 N 个预设、每个都要能撤销，
  且导出预设时会把署名一起写死进别人的文件。
- 归属最直接的写法是「把绑定结果按 collection id 导出去」——但 id 在别人机器上不存在，
  传过去是一串没有意义的字符串。

## 决策

### 一、标识符 = 全局一份配置，渲染时叠加（`storeV2.identifier`）

- 字段：`{ text, placement: 'prefix' | 'suffix' | 'both' }`，**全局唯一**，无单预设例外。
- **不写回预设图层**：渲染时 `applyIdentifierToText` 叠加；无文字水印时 `buildIdentifierLayer`
  造一个 `bottom-left` 图层叠加在最上层。
- 多行文案只贴**整段**首尾，不逐行贴。
- 纯空格 = 不启用（`isIdentifierEnabled` 用 `trim()` 判，但原文前后空格保留）。
- 持久化 v5 → v6 补默认值（空文本），**升级后旧水印渲染结果不变**。

**为什么不做「每个预设可单独关闭」**（杰哥已确认选全局）：多一层例外就多一层推理，
且导出时要额外带一个开关字段。当前没有真实用例支撑这份灵活度。

**代价（知情取舍）**：叠加层意味着缓存与 UI 依赖都要跟着改——
`preset.updatedAt` 不会因为改标识符而变化，所以 **overlay 缓存键必须纳入标识符签名**，
画布预览的 effect 也必须订阅 `identifier`。漏掉任意一处，症状都是「改了但没反应」。

### 二、导出文件用**路径名**表达归属，导入不自动建节点

文件格式（`lib/compositePresetTransfer.ts`）：

```json
{
  "kind": "tangbao-watermark-presets",
  "version": 1,
  "presets": [ ... ],
  "bindings": [{ "presetId": "w1", "path": ["女鞋", "凉鞋", "抖音"], "media": "头条" }],
  "identifier": { "text": "@小王", "placement": "suffix" }
}
```

- **只收显式声明的绑定**（节点自己写了 `watermarkPresetIds` 或 `byMedia[渠道]` 才收）。
  继承来的不导：继承是目标机器那棵树自己算出来的结论，把结论塞进文件等于硬写一份可能过期的值。
- **归属用路径名而非 id**：id 跨机器无意义，路径名是两台机器唯一能对齐的东西。
- 导入按路径**逐层匹配**（`resolveCollectionIdByPath`），不是只比最后一级名字——
  两条产品线下的同名「抖音」必须能区分。
- 匹配不上 → 进 `unmatchedBindings` 报告，**绝不自动创建节点**（杰哥已确认）。
- 同 id 预设 → **覆盖且保留原位**（顺序即产出顺序）；`asCopy` 参数保留但未在 UI 暴露。
- 文件里的 `identifier` **只在本机没配过时才采用**，不静默覆盖用户已有署名。
- **图片资产内嵌为 dataUrl**（杰哥已确认）：`stored` / `project` / 本地 `path` 三类都读出来内嵌，
  导入时重新存回资产库（`storeCompositeBlobs` 按内容哈希，重复导入不产生副本）。

## 后果

- 用户心智：标识符「一处改、全部生效」；导出导入「预设 + 归属一起走，导入即可用」。
- 导出文件体积随图片资产增大（单图可达数 MB）——这是「内嵌」换「开箱可用」的代价。
- 保存目录受主进程路径白名单约束（桌面 / 文档 / 下载 / 图片 / userData），
  选到别处会写失败，UI 已给出明确提示。

**证据**：`src/features/composite/lib/compositeIdentifier.ts`、
`src/features/composite/lib/compositePresetTransfer.ts`、`storeV2.ts` v5→v6、
`compositeRendererV2.getCompositeOverlayCacheKey`（第 4 参 `identifierSignature`）。

## 后续补充：叠加是「逐层」的，可按层关闭（2026-09-22）

标题里的「**全局单点**」说的是**标识符配置只有一份**（`storeV2.identifier`，一处改全部生效），
**不是**「整个水印只贴一处」—— 实现上 `applyIdentifierToText` 在**每一个文字层的渲染里**都会跑
（`compositeRendererV2` 的文本分支），所以**多文案水印默认每段文案都带标识**。
单文案水印看不出区别，这就是它一直没暴露的原因。

杰哥 2026-09-22 报障：一个水印里两块文案（合规声明 + 卖点），**卖点也被贴了标识**。

补充决策：`CompositeV2TextLayer` 增加 **`withIdentifier?: boolean`**，**缺省 = 带**
（只有显式 `false` 才跳过），判据集中在 `layerWantsIdentifier` **一处** ——
图层面板那个「带标识」勾选框与渲染器读的是同一份判据，不各写一次。
**不做「预设级选一层」**（那种只能指定一层）：逐层开关更灵活，两层都该带就都勾上。

**本 ADR 的其余决策不变**：标识仍不写回预设、仍是渲染时叠加、overlay 缓存键仍含标识签名。
