## 背景

TB-107（同日早些时候）把分发改成「原地**恒定**在产出文件夹下面建一层日期子文件夹」，
并写进 `config-spec.md`：「目标目录留空时恒定在产出目录下面建一层日期文件夹，
**不再去替换目录名里的日期段**」，同时加了两条回归用例把这条口径钉死。

当天 17:00 杰哥报障三条：

1. 导出后出现**重复的两份**素材；
2. 导出位置**仍然只有一个**，只是在其中增加了子文件夹；
3. 子文件夹**仅以日期命名**，实际应采用完整的命名（至少应改变日期）。

## 真因（三条是同一套结构的后果，不是三个独立 bug）

- **① + ②**：`resolveBaseTargetDir` 在 `targetDir` 留空时返回**产出文件夹自身**，而搬运方式
  默认 `copy` ⇒ 在产出文件夹里**复制自己**。另外 `targetDir` 填成**输出根**时，「保留相对结构」
  会把目标算回产出文件夹自身（`pathJoin(输出根, 产出文件夹名)`）⇒ **填了等于没填**。
- **③**：子文件夹名硬编码 8 位日期，命名模板那套完整命名（`{date}-{product}-{direction}-{media}-{size}`）
  被整段丢掉。

一轮内部复盘（TB-107）曾把「重复两份」归因为「用户手填的起始日期填错了」。本次报障说明
**那不是用法问题而是机制问题**：只要「目标目录可能等于产出目录」+「默认复制」这两条同时成立，
重复就必然发生，与用户填什么无关。

## 决策

**分发不再套子文件夹，改成给产出文件夹本身「按排期日改名」**（杰哥原话：「沿用命名模板，
只改日期命名……整体先导出到当天日期的文件夹里，然后计算每天要多少个，再创建文件夹后剪切进去」）：

- 文件夹名 = 产出文件夹名，**只把日期段换成排期日**
  （`20260922-高颜值-头条-广点通-1140x640` → `20260924-高颜值-头条-广点通-1140x640`）；
  模板里没有 `{date}` 时把排期日前置（否则每天的文件夹会撞名，分配结果直接错乱）。
- 与产出文件夹**同级**：分发根 = `targetDir`（留空则 = 产出文件夹的父目录 = 输出根）。
- **搬运恒定 move**，字段 `mode` 删除（旧数据里的值不读）。
- 排期日与文件当前位置重合时（起算日 = 产出当天 ⇒ **第 1 天必然重合**）**不搬、不复制**。

## 为什么移除「复制 / 移动」开关（而不是把它保留成选项）

保留 copy 在这套结构下**给不出自洽的结果**：起算日 = 产出当天 ⇒ 第 1 天的目标就是产出文件夹
自己（原地），第 2、3 天若复制，产出文件夹里会同时留着属于第 2、3 天的副本 ——
「哪一天的文件在哪个文件夹里」这条基本性质当场失效。而「复制」在分发语境下的唯一好处是
保留产出母版，与本次的核心诉求（不要重复素材）直接冲突。

TB-107 第一轮反而**因为**这条口径而否掉了「替换目录名里的日期段」这个做法（担心算回原地）。
本条的判定是：真正会算回原地的是「把产出文件夹名又拼回路径」这一步，**不是**日期替换本身；
去掉那一步、再加一条「目标 == 源就跳过」的短路，替换日期段就是安全的。

## 代价 / 影响

- `PostprocessDistributionConfig` 少一个字段（`mode`）：中控台「搬运方式」分段控件、
  控制台导出表该行、导入表该字段一并删除。
- **分发结果的位置变了**：原来在产出文件夹**内**多一层，现在产出文件夹**同级**出现排期文件夹。
  旧产出里已经存在的 `20260923\` 子目录**不会被自动清理**（程序不动用户磁盘上已有的东西）。
- 旧配置里的 `mode` 值被忽略（与 `startDate` 同一处理方式：类型里删掉、归一化时不读）。
- 铺 1 天 = 什么都不做（原来是"多一层文件夹 + 一份副本"）。
