# 0015 「输出位置」并入「渠道与尺寸」，两个 tab 合成一个「渠道与输出」

- **日期**：2026-09-22
- **状态**：生效中（已实现，TB-093）
- **决策者**：杰哥（产品负责人）

## 背景

杰哥原话：「请将『输出位置』和『渠道尺寸』两个 tab 合并为一个统一的 tab，并把原来的渠道表格与
输出位置表格合并成一张表格，因为二者有很多参数和基本框架是相同的。」

三个事实决定了这次能合、而且该合：

1. **几张表的粒度已经一致**。渠道表与尺寸表 2026-09-21 起都是「一行一个渠道」
   （详细尺寸改成格内复选框组，见 `ConsoleMediaTables.tsx` 头注）；输出位置表按渠道分组
   （渠道名跨行合并，`ChannelOutputDirs.tsx`）。说的是同一个实体。
2. **当初分表的理由已经消失**。「渠道与尺寸是 1:N，压成一张表会让渠道名重复」这条 ——
   尺寸已经压进一格，而「一个渠道的多个位置」本来就是合并单元格最适合表达的形状。
3. 分两个 tab 的真实代价是**同一件事要看两处**：想知道「这个渠道出到哪」得在两个 tab 之间来回切。

## 决策

**中控台右区分区从 4 个收到 2 个（`watermark` / `channel`），三张表合成一张。**

### 一、行粒度是「位置槽」，前三列跨行合并

一张表 5 列：渠道名 / 详细尺寸 / 参与产出 / 导出位置 / 操作。
一个渠道占 **1 行**（单写）或 **2 行**（双写，`MAX_POSTPROCESS_OUTPUT_DIRS`）；
**渠道名 / 详细尺寸 / 参与产出 三列跨行合并**（`DataGridColumn.spanRows`，三列返回同一组行数），
只有「导出位置」与「操作」逐行 —— 于是第二行读作「它的第二个位置」，而不是「另一个渠道」。

### 二、导出位置上下排列，不用左右两列

杰哥先选「左右两列」（与 Excel `output_dirs_global` 的 `outputDir1` / `outputDir2` 同形），
看过预览图后改成**上下**，理由：「Excel 表格也是这种方式展现比较清楚，逻辑也清晰」——
即保留 `ChannelOutputDirs` 的合并单元格读法。

### 三、三个历史分区 id 全部收敛到 `channel`

`distribution`（2026-09-21 已并入 `output`）、`output`、`media` 都进 `RETIRED_SECTION_ALIASES`。
分区 id 是**持久化值**，认不出会把人弹回水印 —— 等于把「我上次停在哪」默默抹掉。

### 四、层级说明换承担者

合并后一张表里混着三种层级（全局规格 / 跟作用域 / 表下三节全局），一条**分区级**提示说不清
（这正是 2026-09-21 删 `ControlConsoleSection.globalOnly` 的理由）。改由两条承担：
① 分区顶上的**作用域条**（节点作用域下说明这是谁的覆盖值、留空往哪退）；
② 每列的 **`help`**，点名「所有方向共用」还是「跟着作用域走」。

## 理由

**为什么是上下而不是左右**（被否决的方案与原因）：

- 上下（**采纳**）：路径列**拿满剩余宽度**。这张表为「路径被挤窄、中文共享盘路径只剩半截」
  报过两次障（`ChannelOutputDirs` 头注记着两次）；左右两列时两条路径各占一半，等于把老毛病请回来。
  而且与 Excel 合并单元格的读法一致，用户不需要重新学。
- 左右两列（**否决**）：与导出 Excel 的列名一一对应确实是优点，但代价是路径宽度减半 ——
  而用户核对路径这件事**不能靠悬停提示兜住**（他看的就是长度本身）。

## 后果

- **正面**：「这个渠道出到哪」一屏看全；分区从 4 个收到 2 个；`spanRows` 从孤例变成有明确用途的特性。
- **代价 / 知情取舍**：
  - 表会变高（有双写的渠道占两行）→ 靠三列跨行合并把「这两行属于同一个渠道」表达清楚，
    组内不加分隔线。
  - 路径列宽度**取决于「详细尺寸」列是否固定宽**：它是 `flex-wrap` 复选框组，不给固定宽会被浏览器
    按「内容偏好宽度」抢走弹性空间（见 `data-grid.tsx` 的 `columnWidthStyle`）。实现给 300px 固定宽，
    路径列不给宽 → 拿剩余。
  - 中控台**不再消费 `ChannelOutputDirs`**（后处理弹窗仍在用，它是跨整行的窄容器）→
    同一个字段在两个界面形态不同，本轮刻意不动。该组件的 `collapsible` 分支已无调用方。
- **对后续代码的约束**：
  - 参数的「层级」不能再靠分区边界区分，新加的列**必须写 `help`** 说清它属于哪一层；
  - 别再拆回多个 tab（`controlConsoleSections.ts` 里记着两次合并的理由）；
  - 合并视图时**先清点行级动作再清点字段** —— 字段有列可对，动作没有（见 `docs/RISK.md` R-82）；
  - 「尺寸数 / 可用尺寸」两个派生列已删，别再按卡片看板的形状加回来。
