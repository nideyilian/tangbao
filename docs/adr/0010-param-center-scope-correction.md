## 一、产物结构的真实三维（这次先确认，再评价）

一个方向产出哪些图，由**三个互相独立的维度**决定，而**只有第一个在树里**：

| 维度            | 取值                                | 在树里吗  | 说明                                                   |
| --------------- | ----------------------------------- | --------- | ------------------------------------------------------ |
| **① 归属**      | 产品线 → 产品 → 方向                | ✅ **在** | 树。业务归属，决定「这张图属于哪个方向」               |
| **② 尺寸/横竖** | `landscape` / `portrait` / `square` | ❌ 不在   | 按源图尺寸**自动判定**，或手选；决定每个渠道出哪些尺寸 |
| **③ 渠道**      | 广点通 / 百度 / 厂商 / 头条         | ❌ 不在   | `media` 表（全局共享规格），决定「投到哪几个平台」     |

**产出量 = 方向 × 渠道 × 该渠道同向尺寸 × 水印预设**（`buildPostprocessOutputs`，
`lib/postprocessMedia.ts:472`）。

⇒ **树只负责 ①。** ②③ 从来就不是树的层级，也不是「冗余层级」，
**它们是笛卡尔积的另外两维**。ADR-0009 的整个论证前提因此不成立。

### 实测佐证

- 内置项目树：**3 条产品线 / 13 个产品 / 61 个方向**（`lib/builtinProjectTree.ts`），
  方向名是业务名（`网赚` / `萌宠` / `大字报` / `签到有礼-10元话费+2G流量` …），**不是**横竖。
- 媒体表：**4 个渠道 / 15 个尺寸**（`lib/postprocessMedia.ts:71-115`），
  每个渠道自带尺寸规格（如厂商 8 个尺寸、百度 3 个）。
- `matchMediaSizes(media, direction)`（`:149`）：**同一个渠道在不同横竖下出不同尺寸** ——
  这正说明「横竖」是**筛选尺寸的条件**，而非树的层级。

## 二、那么「参数设置」到底该怎么改？（回到杰哥的真实诉求）

杰哥的原始诉求是两件事，都**与树结构无关**：

### 诉求 A：把「各项目、各方向的参数」统一管理

**这是对的，且现状确实散。** 参数目前落在：

| 存哪                                | 内容                                  | 编辑入口                                     |
| ----------------------------------- | ------------------------------------- | -------------------------------------------- |
| `storePostprocessMedia`（persist）  | 全局基线：媒体表 / 尺寸 / 命名模板 等 | 输入栏「后处理」弹窗（右栏，选「全局默认」） |
| `storeProjectTreeParams`（persist） | 按 `collectionId` 的节点覆盖          | 同一个弹窗（右栏，选具体节点）               |
| `localSettings`                     | 本地保存目录 / API / 主题             | 「设置」弹窗                                 |

⇒ **问题在「入口散」与「不知道某参数在哪」，不在「树层级深」。**

### 诉求 B：后处理只留与「对应项目」「对应方向」直接相关的项

**这才是「移除冗余」的准确落点**：把**与方向无关**的字段从节点覆盖里拿掉。

按这个口径重看那 10 个可覆盖字段（`PostprocessNodeOverride`）：

| 处置                          | 字段                                                                                                                               | 依据                                                                                                      |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| ✅ **与方向直接相关，必留**   | `outputDir` / `byMedia[].outputDirs`（目录）、`byMedia[].watermarkPresetIds` / `watermarkPresetIds`（水印）、`enabled`（是否参与） | ADR-0003 的业务表格：25 个方向目录按渠道分叉、56 个方向水印按渠道分叉。**这两项确实是「每个方向不一样」** |
| ⚠️ **与方向无关，上收全局**   | `autoCompanionClean`（纯净版伴随）、`distribution`（分发排期）                                                                     | **没有任何业务证据表明逐方向不同**。它们是「全局怎么跑」而不是「这个方向怎么跑」                          |
| ⚠️ **需你定**                 | `namePattern`（命名模板）、`creator`（创作者）                                                                                     | 取决于你的实际用法：命名模板是「全库统一一套」还是「不同方向不同」？                                      |
| ❓ **渠道维度，不是方向维度** | `selectedMediaIds`（节点级渠道勾选）                                                                                               | 勾选哪些渠道属于③渠道维度；若已是全局决定，节点级就多余                                                   |
| ❓ **横竖维度，不是方向维度** | `direction`（画面方向）                                                                                                            | 这是②尺寸维度。若它也该逐方向可配，那就**保留**；我上轮的「改名上收」是错的                               |

## 三、ADR-0009 里唯一还没被证伪的东西：R-63

那条风险**与结构理解无关，独立成立**：

> 无论按什么口径收窄 `PostprocessNodeOverride` 的字段集，
> **旧数据里被删字段的值会静默消失**，且升级瞬间不可逆。
> 修法：归一化阶段把旧值提升到全局 + 一次性迁移 + 跑前备份。

## 四、这次要请杰哥回答的（换成正确的问法）

> **✅ 已收口（2026-09-20）**：杰哥已逐条裁决 —— 命名模板/创作者取**全局**、
> 横竖**按源图自动判**、节点级渠道勾选**不需要**、纯净版伴随/分发**全局一套**。
> 结论与实现见 [0011](0011-node-override-narrowing.md)。

上轮我问的是「要不要保留树」——**问错了**，树当然保留。正确的问题是：

1. **命名模板 / 创作者**：你希望是「全局一套」，还是「不同方向可以不同」？
2. **画面方向（横竖）**：每个方向需要单独指定吗？还是按源图自动判就行？
3. **节点级渠道勾选**：需要「这个方向只投百度、那个方向只投头条」吗？
   （渠道本身的**规格表**肯定是全局的，问的是**勾选范围**要不要逐方向）
4. **纯净版伴随 / 分发排期**：确定按全局一套处理吗？（ADR-0003 无逐方向证据）

回答后，我把「确实与方向相关」的留下、「无关」的上收全局 —— **字段集收窄，树结构不动**。
