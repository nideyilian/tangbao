## 背景：杰哥提的两项（原话）

> 「1）参数为全局通用，但启用状态跟随对应方向；2）评估「参与产品」与「启用」两个选项是否重复，
> 是否可合并为一个」

ADR-0011 的裁决 #3 当时是「节点级渠道勾选 —— **不需要，我自己勾选**」。实际用下来这个判断只对了
一半，本轮明确改口：**渠道规格全局一套，「这个方向投哪几个渠道」跟着方向走**。

## 一、`selectedMediaIds` 回到节点层（推翻 ADR-0011 裁决 #3）

### 为什么当时判断偏了

ADR-0011 的理由是「勾哪些渠道是**运行时操作**」。但实际用法里它是**方向维度**的东西：

- 渠道**规格**（渠道名 / 尺寸 / 体积上限）确实是全局共享的一份 —— 这部分原判断正确；
- 「**这个方向**投哪几个渠道」却是每批图都要确认的事，与 `enabled`（这个方向跑不跑）同一层级。
  实测业务里不同方向投的渠道本来就不一样。
- 放全局之后，中控台里选一个方向、改的却是所有方向共用的那份勾选，顶上还挂着一句
  「全局设置，所有方向共用」的提示条 —— 用户**没法表达**「A 方向投头条、B 方向不投」。

### 落点与语义（与 `watermarkPresetIds` 完全同构）

```ts
export interface PostprocessNodeOverride {
  outputDir?: string
  watermarkPresetIds?: string[]
  selectedMediaIds?: string[] // 本条新增；[] = 这个方向一个渠道都不投
  enabled?: boolean
  byMedia?: Record<string, PostprocessMediaOverride>
}
```

- `undefined` = 没表态，沿「方向 → 产品 → 产品线 → 全局」向上继承（ADR-0004 同一套规则）；
- **`[]` 是有效值**：显式「这个方向一个渠道都不投」。判「有没有配」**不能看 `length`**；
- 数组顺序即产出顺序（与全局字段一个口径）。

**实现上几乎没有额外代码**：继承链是通用的（`resolveProjectPostprocessSlice` 逐级
`applyPostprocessOverride`），产出链读的本来就是 `slice.config.selectedMediaIds`
（`taskPostprocess.ts:270`）—— 只要 `applyPostprocessOverride` 认这个字段，界面与产出**同时**生效。

### 不采用的写法：放进 `byMedia`（渠道再细分一层）

`byMedia[mediaId].selected` 这种布尔会让「到底哪个值生效」需要递归推理，而这件事本来就是
「它有没有出现在那份列表里」。`byMedia` 保持只开放「目录 + 水印」（ADR-0003 不变）。

## 二、删掉渠道的「启用」字段（与「参与产出」合并）

两者对产出的影响**完全等价**：`matchMediaSizes` 先看渠道启用、`buildPostprocessOutputs` 先按参与列表
迭代，任一为关这个渠道都不产出。两个开关说同一件事，只会让人怀疑它们的区别。

保留的是「参与产出」（`selectedMediaIds`），因为：它带**产出顺序**（Excel 的「产出顺序」列）、
输入栏计数用它、名字就是用户核对结果时想的那个词。`PostprocessMedia.enabled` 字段**删除**。

> ⚠️ **不能只把它从界面上藏起来**：留着字段却不在界面露，就会出现「勾了参与产出却不产出」——
> 一个看不见的杀手开关，正是本仓最怕的那类静默失效。所以是**删字段 + 一次性迁移**。

## 三、⚠️ 两条迁移与一条往返（都不做就会静默出错）

### 1. 旧数据 `enabled: false` → 折成「不参与产出」

`storePostprocessMedia` **`version: 2 → 3`**（不 bump 则 zustand 不调 `migrate`，折算根本不发生）。
`normalizePostprocessMediaConfig` 先把旧值读出来（`isLegacyDisabledMedia`），再把这些 id 从
`selectedMediaIds` 里剔除。**忽略旧值等于把用户停用过的渠道悄悄放回产出**（行为反转）；
**保留字段等于留下杀手开关** —— 两条路都会让人对着结果发懵，只有折成「它当时真正表达的意思」是对的。

### 2. Excel 老包里的「启用」列

新导出**不再包含**该列。导入侧仍认它：`启用 = 否` → 不进 `applied`（= 不参与产出），
并在导入报告里汇总说一句（`formatImportPlan`）—— 用户看到的会是「这个渠道没被勾上」，
不解释就像导入漏了东西。

### 3. Excel `node_params` 表补 `selectedMediaIds` 列

不补的话「导出 → 导入」会把**已配好的方向级渠道静默丢掉**。口径与同表其它列一致：
**导出生效值**（含继承来的，`sourcedFrom` 说明来源），代价是往返会把继承**摊平**成每个节点
自己的值。老包（没有该列）导入时**不进 patch** —— `undefined` 在合并里表示「恢复继承」，
会把用户新版配好的值清掉；「包里没写这一列」不等于「包里说要继承」。

## 四、配套的界面整理

- 「渠道与尺寸」分区**不再是 `globalOnly`**：全局作用域改基线，节点作用域改这个方向自己那份，
  并显示「本级自定义 / 跟随「X」」与「改为跟随上级」（置 `undefined`，**不是**置 `[]`）；
- **`ControlConsoleSection.globalOnly` 字段与那条分区级提示条一并删除**（2026-09-21）：
  两个分区现在都是混合的（渠道与尺寸 = 规格全局 + 参与方向级；输出位置 = 目录跟作用域 +
  命名/分发/预览全局），一条分区级的话说不清，只会连不该覆盖的那一半一起误导。
  改成每个小节在自己的标题里说清属于哪一层。**别再按分区级提示加回来**；
- 「画面方向」仍是**全局一套**（ADR-0011 未开放到节点层），所以在节点作用域里显式标了
  「全局一套」—— 否则会被上面那条来源提示连带误导；
- 文件名预览的示例渠道改按**当前作用域生效值**取样（否则选中某方向时预览会拿一个它不产出的渠道算）。

## 五、知情取舍（都别当成 bug 再改回去）

| 取舍                                 | 说明                                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------------------- |
| **输入栏计数仍是全局基线**           | `InputBar` 的「已勾 N 个渠道」读全局 `selectedMediaIds`。方向级覆盖后它与该方向的真实产出可能不同 —— 输入栏没有方向上下文，改成「按当前方向」既做不到也会更费解。核对真实产出用中控台的「产出预览」（它按作用域展开） |
| **方向的渠道勾选不进 `channels` 表** | 那张表是渠道**规格**表；方向级的值在 `node_params` 表里（见 §三·3）                            |
| **不提供「按方向批量复制渠道勾选」** | 未提出需求；真要批量走 Excel 导入导出                                                          |
