# 参考「灵境 · 资产中心」的全局参数管理设计（评估）

- **日期**：2026-09-20
- **来源**：杰哥给的线上参考 `https://junbo-cy.jetmobo.com/aiimg/assets/center?tab=products`
- **性质**：**评估报告**（只调研与提方案，未改代码）
- **相关**：ADR-0010 / ADR-0011（节点覆盖收窄）、TB-050（已完成）、TB-052（本报告新增）

## 〇、结论先行

**这个站点与糖包是同一套业务数据的两个前端** —— 产品线 / 产品 / 方向名**逐字一致**：

|        | 灵境 · 资产中心（线上）                              | 糖包（本地）                    |
| ------ | ---------------------------------------------------- | ------------------------------- |
| 产品线 | 保险 / APP-拉新 / 卡券（**3**）                      | 保险 / APP-拉新 / 卡券（**3**） |
| 产品   | 百万医疗险 / 快手 / 小红书 / 百度 …（**14**）        | 同（**13**）                    |
| 方向   | 月亮 / 图标 / 插画 / 大字报 / 网赚 / 萌宠 / 一分购 … | **逐字相同**                    |

⇒ 灵境是**服务端权威源**，糖包是**本地客户端**。所以它的参数组织方式**不是"别人的做法"，
而是"同一份业务在另一端的既有解法"** —— 参考价值极高，且**可直接对照**。

**最重要的一个发现**：它的右侧配置面板里，「渠道与尺寸」这一栏**不是树**，
而是**「渠道分组 + 渠道内尺寸多选」**。这与我们刚做完的 ADR-0011（节点覆盖收窄到
目录/水印/enabled）**方向一致**，但它比糖包多走了两步：**① 有配置模板概念；② 有审核规则维度。**

## 一、它的真实结构（实测）

### 布局：三栏 + 顶部 tab

```
┌─ 顶级 tab：素材库 5 | BGM 库 0 | 视频水印库 0 | 产品库 14 ─────────────┐
├────────────┬──────────────────┬──────────────────────────────────────┤
│ 产品线 3 条 │ 产品与方向 14 个 │ 产品资料：百万医疗险                 │
│            │                  │ 保险                                 │
│ 全部产品   │ [产品配置][+新建] │ ┌ 产品名称 / 产品线 / 方向数量 / 排序┐│
│ 保险   1产 │ 百万医疗险 5方向 │ └────────────────────────────────────┘│
│ APP-拉新12 │   月亮/图标/插画  │ 调用配置                             │
│ 卡券   1产 │ 快手  10方向     │  产品可继承上级配置，也可以覆盖       │
│            │   网赚/萌宠/老歌  │  ┌[渠道与尺寸][审核规则][输出位置][水印]┐│
│            │ 小红书 8方向     │  │ ▸ 广点通   2/2 已应用             ││
│            │ ...              │  │   1080x1920 竖版 ≤399KB 当前产品使用│
│            │                  │  │ ▸ 头条     2/2 已应用             ││
│            │                  │  │ ▸ 百度     0/3 已应用             ││
│            │                  │  └──────────────────────────────────┘│
└────────────┴──────────────────┴──────────────────────────────────────┘
```

### 关键文案（原文）

> **调用配置**
> 「产品可继承上级配置，也可以在当前层级覆盖。」 ← **与糖包的继承语义完全一致**
>
> 「还没有可配置模板 / 请先点击**产品配置**创建模板。」 ← 空态提示

### 顶部三个按钮的可操作项

- **产品配置**（`配置<产品线名>`，如「配置保险」）—— 挂在**产品线**行上
- **+ 新建方向** / **+ 新建产品** / **+ 新建产品线**

### 「渠道与尺寸」的数据形态（这是最有价值的部分）

每个渠道是一个 **`<h4>` 分组 + 「N / M 已应用」计数**，组内是**尺寸卡片**：

```
▸ 广点通                    2 / 2 已应用
   [广点通 1080 x 1920]  竖版   1080 x 1920 · ≤ 399 KB   当前产品使用 ✓
   [广点通 1280 x 720 ]  横版   1280 x 720  · ≤ 399 KB   当前产品使用 ✓
▸ 头条                      2 / 2 已应用
   [头条   1080 x 1920]  竖版   ...                       当前产品使用 ✓
▸ 百度                      0 / 3 已应用
   [百度   1140 x 640 ]  横版   ...                       未应用
```

**注意三个细节**：

1. **尺寸卡片自带三要素**：`渠道 + 宽高` / `横竖标签` / `体积上限（≤ 399 KB）`。
   ⇒ **体积上限（KB）是尺寸的一个属性**，与糖包的 `PostprocessMediaSize` 高度类似。
2. **状态是二元的**：「当前产品使用 ✓」/「未应用」——**按产品勾选启用哪些尺寸**。
3. **粗粒度计数**在分组头（`2 / 2 已应用`）—— 一眼看出这个渠道有没有配。

| 维度                | 灵境 · 资产中心                          | 糖包（当前）                                           | 差距判断                      |
| ------------------- | ---------------------------------------- | ------------------------------------------------------ | ----------------------------- |
| **导航布局**        | 顶级 tab（素材/BGM/视频水印/产品）+ 三栏 | 项目树工作台**单栏表格**                               | ⚠️ **差距明显**               |

## 三、值得吸收的 4 件事（按价值排序）

### ⭐ 1. 三栏同屏：左树 / 中列表 / 右详情

**这是糖包最大的结构差距。** 糖包现在：

- `ProjectTreeWorkbench` = 展平表格（`tableRows.ts`）
- `PostprocessSettingsModal` = 弹窗（左树 + 右参数）

⇒ **两块是割裂的**：看结构要开一个界面，改参数要开另一个界面，而且后者是弹窗（遮挡上下文）。

**灵境的做法**：树、列表、详情**同屏三栏**，选中即读即改，无弹窗。
⇒ 这也是 TB-049「入口分散」那个报障的**根因解法** —— 不是"把两个入口做个跳转"，
而是**本来就不该是两个入口**。

### ⭐ 2. 「配置模板」：把一组参数存成命名模板，可套用

灵境的 `配置模板` 按钮 + 空态提示「请先点击产品配置创建模板」，说明它支持：
**先定义几套配置模板 → 再套到产品线上**。

糖包当前是**逐节点直接配**，没有「先存一套、再批量套用」的能力。
⇒ 对「61 个方向要配同样的水印组合」这类场景，模板能省掉大量重复劳动。
**但要注意**：这会引入"模板 → 节点"的第二层间接，与 ADR-0011 的收窄方向**有张力**
（收窄是减少层级，模板是增加间接层）。建议**只做「从现有节点反向存成模板」+「套用」**，
不做"所有节点都必须走模板"。

### 3. 渠道分组头的计数徽章（`2 / 2 已应用`）

**低成本的可见性提升**。糖包现在要展开折叠区才知道哪个渠道配了几个位置。
⇒ 加一个 `已配 / 总数` 徽章即可，改动面很小（`ChannelOutputDirs` 内部）。

### 4. 「审核规则」作为独立参数维度

灵境把它和「渠道与尺寸/输出位置/水印」并列成 4 个 tab。
糖包目前只有配方卡的 `adNegativeRules`（21 词合规红线），**没有把它当成"产品级参数"**。
⇒ 如果业务上确实存在「这个产品禁用哪些词」的需求，它应该是一个**产品级参数**。
**这条需要先确认业务需求，不要照着建。**

---

## 四、⚠️ 不建议照搬的两件事

1. **顶级 tab「素材库 / BGM 库 / 视频水印库 / 产品库」** —— 这是**平台级多模块**的划分
   （对应它还有「策略中心」「下单中心」）。糖包是**单一应用的桌面工具**，
   加顶级 tab 只是为了对齐形态，**没有业务收益**。
2. **在桌面端做服务端形态的「保存到云端」** —— 灵境是 Web 端（有服务端），
   糖包是本地 SQLite（`asset-kernel.sqlite`）。**数据主权在本地是糖包的优势**，
   不要因为这个参考而引入云端依赖。

## 五、建议的落地顺序（若采纳）

| 优先级 | 项                                     | 改动面                                                             | 前置                             |
| ------ | -------------------------------------- | ------------------------------------------------------------------ | -------------------------------- |
| **P1** | 三栏同屏（树/列表/详情合并，去掉弹窗） | **大** —— 重组 `ProjectTreeWorkbench` + `PostprocessSettingsModal` | **TB-049 必须先修**              |
| **P2** | 渠道分组计数徽章                       | 小 —— `ChannelOutputDirs`                                          | 无                               |
| **P3** | 配置模板（从节点反向存 + 套用）        | 中 —— 新增 store + 存储结构                                        | 需先定「模板与节点覆盖的优先级」 |
| **P4** | 审核规则参数化                         | 待定                                                               | **需先确认业务需求**             |

### 与 ADR-0011 的关系

**互补，不冲突**：

- ADR-0011 解决「**每个字段该挂在哪一层**」（水平方向：收窄节点覆盖）
- 三栏同屏解决「**这些参数以什么形态呈现**」（垂直方向：呈现方式）

⇒ 两者都做完，才是「参数管理」这件事的完整解法。
